# Changelog

## Unreleased

- Directional shadow cascades divide their range 80% logarithmically instead of 95%, so a camera about five meters from a character keeps its shadow in a finer cascade: with a 75° field of view, texels between 5.5 and 12.5 meters shrink from about 2.3 to 1.4 centimeters. `CascadeSplits` sets how far directional shadows reach, 100 meters by default, and the split blend; pass it with `VisibilityPipelineSettings::with_cascade_splits`, or set the `render.directional-shadows.distance` and `render.directional-shadows.split-blend` parameters. Surfaces past the shadow distance receive no sun shadow. `csm::make_csm_views` takes the splits as a new argument.
- Contact shadows are soft and filtered. The trace fades an occluder's shadow out over the second half of the ray's reach and near its thickness limit, instead of stopping at a hard line, and a new depth-aware 5×5 filter pass smooths the trace's dithered result into the `Contact Shadows` target material evaluation reads, without crossing onto other surfaces. The unfiltered result is the `Contact Shadow Trace` target.
- Directional shadows are percentage-closer soft shadows: penumbrae widen with the distance between an occluder and the surface it shades, and stay sharp where they touch. `DirectionalLight::angular_radius` sets how fast they widen; it defaults to the sun's `DirectionalLight::SUN_ANGULAR_RADIUS`, about 0.27°, and `DirectionalLight::with_angular_radius` sets a larger disk for softer shadows. Each receiver searches a cascade's max-depth pyramid for nearby occluders, then filters with the same noise-free tent as before, with its taps spaced one, two, or four texels apart and blended between spacings. A larger light searches a coarser cascade, so the search covers occluders up to two meters above the receiver, and a penumbra wider than eight texels of the receiver's cascade is filtered in a coarser cascade that holds it, fading between the two so no seam shows. `AtmosphereSkyRenderPassSettings::sun_angular_radius` is removed: the sky draws its sun disk at the light's angular radius. Rebake materials, because the generated material-evaluation shaders changed.
- Directional and cone shadows have smooth, noise-free soft edges that stay still from frame to frame. They filter the shadow map with a tent that is two texels wide on each side of the receiver, over the 4×4 texels it covers, instead of 8 point samples with a random rotation per pixel. That rotation changed every frame the camera moved, which made penumbrae boil. Point shadows keep their 8-sample kernel, but its rotation now depends on the shadow-map texel the surface falls in, so it no longer changes as the camera moves. Rebake materials, because the generated material-evaluation shaders changed.
- The PBR visibility pipeline buckets lights on the GPU. A compute pass splits each sink's view into 16 × 8 × 24 clusters, with depth slices that grow exponentially, and marks which lights reach each one; material evaluation then shades a pixel with only its cluster's lights. A point or cone light reaches as far as its exposed illuminance stays above 1/1024 lux, so lights keep their inverse-square falloff without a visible edge. The light table grows from 16 to 1,024 lights and is now a storage buffer. The cone and point shadow pools keep their limit of 16 maps each, and shadow selection ranks each light once per sink instead of once per pool slot. Rebake materials, because the generated material-evaluation shaders changed.
- BESL gains `find_lsb(u32) -> u32`, which returns the index of the lowest set bit, or `0xFFFFFFFF` for zero, on every backend and in the VM, and a scalar `log2(f32) -> f32` overload.
- The HTTP inspector captures render targets at full precision and several at a time. `GET /screenshots` takes `format=exr` for a lossless OpenEXR image that keeps HDR values, such as half-float lighting buffers, or `format=raw` for the texture bytes as the GPU stores them; PNG stays the default. Every image response reports the texture's format and size in `X-Byte-Engine-Format`, `X-Byte-Engine-Width`, and `X-Byte-Engine-Height`, and raw responses add `X-Byte-Engine-Bytes-Per-Row`. `previous=true` reads the copy of a history target, such as `Diffuse Radiance History`, that the previous frame wrote, which is what the current frame's passes read as history. `POST /screenshots` takes a JSON list of up to 16 captures from any sinks and capture points, reads them all from the same frame, and returns one `multipart/form-data` part per image. `Inspector::request_screenshot` is replaced by `Inspector::request_screenshots`, which takes a list of `ScreenshotSelection` values and answers with unencoded `Screenshots`; transports encode each readback with `ScreenshotFormat::encode`, so encoding no longer runs on the graphics thread. GHI gains `CommandBufferRecording::transfer_texture_with_frame`, which reads another frame's copy of a per-frame image.
- The bloom pass is a real HDR bloom: a 13-tap prefilter and downsample after Jimenez, with a luma-weighted first level so a single bright texel cannot flicker the glow, a tent-filtered upsample as wide as `BloomPassSettings::radius`, and a composite that adds the glow onto the scene. `BloomPassSettings::max_brightness` holds each texel to a ceiling before it glows, six stops above display white by default, so a sun reflection at the half-float limit stays a highlight instead of flooding the frame. Overflowed scene texels can no longer smear into black: the prefilter reads texels unfiltered and clamps them, the composite stays within the half-float range, and the ACES tone mapper maps an infinite input to white. Install it with `setup_bloom_render_pass` after the passes that write scene light and before tone mapping.
- The atmosphere sky includes multiple scattering, following Hillaire's 2020 approximation: a 32×32 LUT, built once with the transmittance LUT, holds the light from every scattering order after the first, including sunlight the ground reflects back up. The sky is up to about twice as bright near the horizon and bluer overhead. `AtmosphereSkyRenderPassSettings::ground_albedo` sets the ground's reflectance and defaults to 0.3.
- The atmosphere sky takes its brightness and color from the newest `DirectionalLight` instead of a fixed intensity, so the sky and sunlit surfaces share units and one camera exposure fits both. The sun disk's radiance is the light's illuminance over the disk's solid angle, capped to stay finite in half-float targets. `AtmosphereSkyRenderPassSettings::sun_intensity` is removed, and without a directional light the sky is black.
- Cameras have an exposure, set in stops with `Camera::with_exposure` or `Camera::set_exposure`. Each stop halves or doubles the light the camera shows, and `0.0` keeps today's output; a photographic EV100 converts to `-(EV100 + log2(1.2))` stops. The PBR visibility pipeline and the atmosphere sky multiply scene light by it as they write it (pre-exposure), so real-world intensities, such as a 100,000 lux sun on a glossy surface, stay within the half-float scene image, and bloom and tone mapping receive exposed light. `Sink::exposure_scale` carries the linear factor to render passes.
- `Environment::with_illuminance` calibrates an environment map to the lux it delivers to an upward-facing surface, so it lights the scene in the same units as analytic lights. The loader measures each map's upward illuminance from its baked diffuse irradiance; without a calibration, the map's own values are used.
- Loading a mesh no longer solves its materials. A `Mesh` stores each distinct material variant once in `Mesh::materials`, and `Primitive::material` is an index into it (`Mesh::material` returns a primitive's variant). Request a variant by its ID when you need it; the visibility renderer already does, so a mesh load drops from a storage read per primitive for its variant, material, shader, and every image to reads of the mesh and its skeleton only. `PrimitiveModel`, `SubMesh`, and `SubMeshModel` are removed; `Primitive` is both stored and loaded.
- `ResourceManager::request` and `ResourceManager::query` read each requested resource once. Implement the new `StoredModel` trait to make a model requestable; it builds the reference from the record storage already returned, and `Reference::from_stored` takes the resource's ID, hash, size, and streams from that record. `ReferenceModel` solves through `StoredModel`, and the request bounds are now `T::Model: StoredModel<Resource = T>`.
- Material, variant, and flipbook solves read their shaders, parameters, variables, and images concurrently. Packed resource stores map only the pages that hold a payload instead of the whole packed file for every read, and resources without a payload, such as materials and variants, no longer open a file.
- Baking commits each resource without waiting for the disk and makes a whole root bake durable with one flush when it finishes, instead of one full flush per stored resource. `WriteStorageBackend::persist` is the new hook that makes committed resources durable; a crash before it runs rolls the resource database back to the last persisted bake.
- glTF and FBX textures bake as their own image fragments through the dependency pool, once per container, instead of inline and once per material. They decode, generate mips, and compress in parallel, and an image fragment requested directly now bakes exactly like one requested by a material: same semantic, and mips when a material mip generator is installed. FBX gains `images/<index>` fragments, and a glTF image fragment reads only its own buffer view.
- Generated glTF and FBX materials that lower to the same BRDF graph share one compiled shader, stored as `<container>#shaders/<hash>`. Material texture variables are named by slot (`material_texture_0`, …) instead of by source image index, and unique shaders compile concurrently. On macOS, each shader compiles and links in one `metal` invocation instead of separate `metal` and `metallib` runs.
- `AssetManager::rebuild_resources_baked_before` makes every resource stored before a given time stale, so the next bakes rebuild each root and each shared dependency exactly once. `beld bake --force` uses it with the time the command starts, so forced glTF and FBX bakes also recompress their embedded textures. Stored resources record when they were baked.
- `beld bake` skips assets whose stored resource is current with its source files, so repeated bakes only process what changed. `beld bake --force` rebakes everything selected, which is needed after an asset processor or `--texture-compression` changes. `AssetManager::bake_if_stale` exposes the same check to library callers, and `beld::bake` takes a `force` argument.
- UI components no longer share the engine's state. Every write a component makes, such as declaring an element, an `update_*` call, `remove`, `reparent`, `adopt`, focus requests, and starting a `component` or `mount`, is a future that writes straight into the engine when awaited, in the order it was awaited; the next layout and the components polled after it see the change. An edit of a removed element or a reparent cycle is logged and changes nothing. Reads are futures that complete at once: `Context::geometry`, `Context::pointer`, and `Context::drag` are awaited, and `Context::ctx` is replaced by `ctx.with(|app| ...).await`. The host reads and changes the application context with `Engine::ctx` and `Engine::ctx_mut`. UI wait futures such as `RenderFuture` and `WaitFuture` take the engine's context type, and the free `ui::wait` and `ui::seconds` functions are replaced by `Context::wait` and `Context::seconds`.
- UI elements are declared and edited with setup functions that set their properties in place, such as `ctx.element("panel").container(|c| c.width(240.into()).clip(false)).await` and `panel.update_container(|c| c.opacity(0.5)).await`. Each setter writes into the element where the engine stores it. The element builders, such as `Container::default().width(..)` and `Text::new(..)`, and the `set_*` methods are removed; a plain function over `Properties` holds a reusable look for declarations and edits alike. Text is formatted straight into the element from any `Display` value, such as a number or `format_args!`, image pixels are copied from any byte slice, and `style` takes any layers, such as an array. The engine keeps the storage of removed elements, dropped render entries, and ended components and reuses it, so a screen that closes and opens again allocates only its component tasks.
- UI components are async closures or async functions: `Engine::mount`, `ElementContext::component`, and `ElementContext::mount` take an `AsyncFnOnce(&mut EvaluationContext<C>)` instead of a closure returning a boxed future, and `UiFuture` and `MountedUiFuture` are removed. `animate` takes an `AsyncFnMut`, so one frame can edit several elements.
- UI element keys are explicit. `Context::element` takes an `ElementKey`, made from a name or a `(name, index)` pair, and an element's id is a 64-bit hash of its parent's path and its key, so the same key under the same parent always has the same id. Siblings declared from one list need distinct keys, such as `("row", index)`; declaring one key twice under the same parent in one frame is logged and ignored. The implicit per-frame numbering of repeated names is removed, and `ui::Id` is now a `NonZeroU64`.
- Reworked input around two classes: every source event is recorded into an `InputCollector`, and each consumer owns an `InputSink` that declares its actions, pulls them once per tick, and answers `Capture::Captured` to keep the source event from later sinks. `InputEvents`, `ActionProcessor`, and `InputManager` are replaced; `GraphicsApplication::input_system` is replaced by `GraphicsApplication::input`, and manual action queuing is removed in favor of publishing `ActionEvent` values directly.
- A value driven by a record is no longer repeated a second time in the same tick by `TickPolicy::WhileActive` or `TickPolicy::Always`.
- Retained control values live in a dense per-seat, device, and trigger table instead of a hash map, each sink keeps a sorted control-to-action index so a record only visits the actions bound to it, and binding gates are classified when resolved. `InputCollector::has_trigger` is replaced by `InputCollector::trigger`, which returns the handle for recording without a name lookup, and the public `TriggerMapping` alias is removed.
- `InputCollector::end_tick` is removed. Each sink reads from its own position in the queue, and a record is retained and dropped once every sink has pulled past it.
- `process_default_window_input` records into the collector itself and discards the seat on focus loss, minimize, close, and resize, returning whether it did.
- The UI `Engine` owns the pointer drag: `Engine::press`, `Engine::drag_to`, `Engine::release`, and `Engine::drag` replace the standalone `Drag` type, components read the held source through `Context::drag`, and `Engine::cancel` ends the interaction in progress. A changed viewport size cancels from `Engine::evaluate`.
- The UI engine hit-tests pointer gestures itself: `Engine::press`, `Engine::drag_to`, and `Engine::release` take normalized window coordinates, `press` grabs the surface under the pointer from the last evaluated frame, and `Engine::hit` answers what is under a point. `HitTest` is no longer needed to drive a drag.
- The UI engine delivers drag gestures to components as events: the grabbed surface gets `Events::Grabbed` on press, `Events::Dragged` once per evaluation with the offset from the press point in `UiEvent::delta`, and `Events::DragEnded` when the grab ends with the surface it was dropped on in `UiEvent::source`. `Events::Dropped` reaches the surface under the release point and its ancestors with the released source in `UiEvent::source`, before the source's `DragEnded`. `UiEvent` gains that `source` field.
- `EvaluationContext::reparent` moves a retained UI element under another parent as its last child, keeping its id and properties, and `EvaluationContext::adopt` moves another element under this one.
- UI depth is local to each container. `Depth::relative` orders a child among its siblings only, and a container paints and hit-tests as one block with everything inside it, so no depth set inside one component can put its elements over another's. `Depth::absolute` layers leave their parent and sit above all ordinary content wherever they are declared, from the lowest value to the highest, in tree order among equals, and above the layer they were declared in. Depth used to be one number added up along the tree, so a deep or raised element could show through a modal mounted earlier in the tree, and its backdrop blur skipped it. A layout element's depth is now its rank in that paint order.
- `Container::absolute_position` is now an offset from the parent's top-left corner rather than the viewport's, so nested widgets keep their internal placement wherever their parent's flow puts them. Containers with `Depth::absolute` still start from the viewport.
- Components spawned inside a mounted UI scope end when that scope is removed, and finished components release their runtime slot. Previously both stayed in the runtime, and components waiting on frames kept running after their elements were gone.
- `Context::element` accepts an owned `String` or `format_args!`, so elements created from runtime data can be named from that data; the slot is keyed by the text's content, and `format_args!` is hashed without allocating.
- `EvaluationContext::remove` removes one UI element with everything declared under it, including the components started there. Declaring the same key again reuses its id.
- `EvaluationContext::update_curve` edits a retained curve in place. `Properties::clear_segments` and the segment setters, such as `line` and `cubic`, re-route it while reusing its segment storage, and changing only the segments repaints without replaying layout.
- A container's `Transform` scale now reaches the curves and text under it: segment points, stroke widths, and font sizes scale with the inherited transform the way rectangles, hit bounds, and clipping already did.
- The UI engine reports the pointer passing over surfaces: `Events::PointerEntered` and `Events::PointerExited` reach the surface under the pointer and the ancestors that started or stopped containing it, a held drag source is skipped, `DragCapture::over` names the surface beneath a dragged item, and `Engine::hovered` answers at the application level.
- `hit_width(width)` in a curve's setup makes it a pointer target within `width` layout units of its stroke, so wires can be hovered, clicked, and dropped on. `HitTest` retains the same polylines.
- Absolutely positioned containers keep negative layout coordinates instead of being snapped to the viewport's edge; visual transforms preserve them as well.
- `Context::remove` is available to components, so a component can remove its own elements and end itself.
- GHI windows are pumped by one `ghi::window::App` per process instead of per window, matching how Win32, AppKit, and Wayland deliver events. Create windows with `App::create_window` and drain `App::poll`, which yields `ghi::window::Event`: either an application event such as `AppEvents::Quit`, or a window `Events` value tagged with the `WindowId` it targets. Input targets the window with focus. `Window::new`, `Window::poll`, and `Renderer::update_windows` are removed; `Renderer::poll_windows` replaces the latter, and the graphics application publishes `ghi::window::Event` instead of `ghi::window::Events`.
- Multiple GHI windows no longer steal each other's events on macOS, Win32 reports `WM_QUIT` and keeps handling messages sent between polls, and every Wayland window shares one compositor connection. The macOS dock's Quit item now asks the application to close instead of ending the process.
- The `render-on-demand` application parameter renders a frame only when something changed. Window changes, new UI renders, and screenshot requests ask for frames; call `Renderer::request_redraw` after changing the scene. Idle ticks keep handling events at the `max-frame-rate` pace. Render passes report pending output through the new `RenderPass::needs_frame`, which defaults to `false`.
- A UI `update_*` call that writes the values an element already has no longer advances the render revision, so unchanged frames reuse the retained render and on-demand rendering stays idle.
- Ticks that present nothing, such as idle on-demand ticks, now run at the refresh rate of the fastest display showing a window instead of a fixed 60 per second, or at the `max-frame-rate` pace when that is slower. GHI windows report their display's refresh rate through `Window::refresh_interval` and the new `Events::DisplayChanged` event on macOS, Win32, and Wayland, and `Renderer::refresh_interval` returns the fastest one.
- An idle `render-on-demand` application now waits in the window system instead of ticking. It keeps ticking while a frame is being shown, and wakes for window events, inspector requests, and anything that wakes its `LoopWaker`. After a wait, `Time::delta` is capped at one frame while `Time::elapsed` includes the wait.
- Systems the application loop drives report when they next need a tick, wired explicitly: `GraphicsApplication::waker` hands out a `LoopWaker` (which converts into a `std::task::Waker`), and `GraphicsApplication::schedule_tick` takes the instant of the next tick they need. A UI engine answers both with `Engine::set_waker` and `Engine::next_tick`, so animations keep running at the display rate and UI timers fire on time.
- `ghi::window::App::poll` and `Renderer::poll_windows` take a `Wait` that lets them wait for the first event, and `App::waker` returns an `AppWaker` that ends such a wait from any thread.
- Simulation can step at its own rate: `GraphicsApplication::tick_stepped_with` takes a `simulate` callback, run zero or more times per tick with a fixed step from the new `simulation-rate` parameter (default 60), and a `frame` callback run once with the display-derived time. The world and physics advance with the steps. A frame that falls more than eight steps behind drops the outstanding time. `tick_with` keeps simulating once per frame and panics when `simulation-rate` disagrees with the rate frames are presented at.
- Frames show the world interpolated between the two most recent simulation steps, one step behind. `PipelineManager::step` marks the end of a step, transforms read in it are that step's sample, and `PipelineManager::prepare` receives `alpha`, how far the frame lies between the two latest steps. The visibility pipeline moves each renderable between its samples and holds transforms written outside a step where they are; `Transform::interpolate` blends two transforms.
- `.flipbook` assets declare `frames_per_second` and the ordered `images` of a sequence. The standard setup bakes them together with their images into a `Flipbook` resource that owns its solved image references.
- `PipelineManager::prepare` receives `time`, the frame clock's elapsed time, after `alpha`, so managers can drive playback such as flipbooks at the display rate instead of the simulation rate.
- UI text is drawn from glyph outlines on the GPU with the Slug algorithm, following Eric Lengyel's reference shaders. Glyph curves and bands are packed once per glyph into two storage buffers and the fragment shader computes each pixel's coverage, so text stays sharp at any size and a zoom, a resize, or an animated font size rasterizes and uploads nothing. Horizontal glyph positions are fractional and baselines snap to whole pixels. The CPU glyph atlas renderer is kept; set `UI_TEXT_MODE` in `ui/render_pass.rs` to `UiTextMode::Atlas` to use it.
- The UI is drawn by one ubershader without vertex or index buffers. Every rectangle layer, glyph, image, backdrop blur, and curve piece is one 80-byte record in a storage buffer that the vertex shader pulls quads from, so a frame is one draw per damaged region plus one per backdrop blur, instead of one per depth level, curve, and image with a pipeline and buffer rebind each. The eleven per-type raster shaders and six pipelines are replaced by `ui-vertex.besl`, `ui-fragment.besl`, and two pipelines. Clips and feather masks are shared through a table instead of being repeated in every vertex, a square fill skips the corner, stroke, and mask math, circular corners skip the superellipse math, and images and the glyph atlas share one texture array that holds 31 images at once. The damage clear runs in the first draw's pass, and damage covering the viewport uses the attachment's clear.
- UI elements of different types now paint in exact depth and element order. Previously each type was batched per depth level, so a rectangle could paint under an earlier text or curve of the same depth. A backdrop blur paints under its own element's layers.
- UI curves are evaluated analytically on the GPU instead of being flattened, clipped, and cached on the CPU. Each segment is drawn in a few pieces, each the exact distance to a quadratic, so lines and quadratics are exact and cubics stay within 0.05 pixels. Strokes have no seams between pieces, and path ends and corners are round instead of butt ended.
- A backdrop blur now respects the rounded corners of a feather mask, as every other UI primitive already did.
- UI text measurement reads size-independent advances from glyph outlines instead of rasterizing every measured glyph, and line metrics scale from one entry instead of being cached per size.
- BESL descriptor arrays (`count:`) are indexable everywhere, not only inside `sample`: `texture_lod`, `texture_size`, `fetch`, and the downsample intrinsics accept `textures[i]` with any index expression, and MSL and HLSL pair the element with the sampler at the same index. They used to lower to a member access that no backend compiler accepts. GLSL marks every descriptor-array index `nonuniformEXT`.
- BESL has a `break` statement that leaves the innermost `for` loop. It lowers to GLSL, HLSL, and MSL, runs in the BESL VM, and ends its block for the optimizer like `continue` does.
- `ghi::BufferDescriptor` converts from a `BaseBufferHandle`, for binding a buffer whose element type was chosen at runtime.
- Fixed release and bench builds of `byte-engine-resource-management`: a stray `#[cfg(debug_assertions)]` removed `LoadMessages` from builds without debug assertions.

## 0.2.0 - 2026-08-20

- Added skeletal animation sampling, blending, inertialization, root motion, animation graphs, and reusable runtime players.
- Added block-based audio graph processing with custom processors, pitch shifting, random and round-robin selection, and sample-accurate playback time.
- Added navigation-mesh pathfinding and funnel-based corridor simplification.
- Expanded GHI allocation and I/O APIs while advancing the Direct3D 12, Metal, and Vulkan backends.
- Made resource loading asynchronous and improved baking with dependency tracking, request coalescing, streaming writes, and queryable storage.
- Added and optimized rendering paths for GTAO, shadows, environment maps, tone mapping, SMAA, visibility, and material evaluation.
- Reorganized public modules and resource APIs. This release contains breaking API changes from `0.1.x`.

## 0.1.1 - 2026-07-23

- Configured docs.rs builds to enable the AES and SSE2 target features required by `gxhash`.

## 0.1.0 - 2026-07-23

- Published `byte-engine`, `beld`, and the engine's internal support crates.
- Scoped internal package names under `byte-engine-*` while preserving existing Rust crate import names.
- Tightened the documented `byte-engine` API surface by hiding renderer and layout implementation modules.
- Fixed public rustdoc links and added a crate-level usage example.
- Added public facade re-exports across UI, rendering, gameplay, physics, audio, and networking modules.
- Verified `byte-engine` with strict missing-docs rustdoc linting.
- Stabilized BEMA material asset tests that previously shared shader compiler state under parallel test execution.
