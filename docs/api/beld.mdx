BELD bakes source assets into a resource store and inspects the result. This
page specifies its command line. To use it, follow
[Use BELD](/docs/use/resources/beld); the store it writes is specified in the
[resource store](/docs/reference/resource-store) reference.

## Global options

| Option | Default | Effect |
| --- | --- | --- |
| `-s`, `--source <path>` | `assets` | The source asset directory. |
| `-d`, `--destination <path>` | `resources` | The resource store directory. |
| `--color auto`, `always`, or `never` | `auto` | Terminal color; see [Color](#color). |
| `--storage-mode files` or `packed` | A new store uses files; an existing store keeps its mode | The persistence mode. A value that differs from an existing store's mode is an error. |
| `--config <path>` | `config.json` in the working directory | The project's [configuration file](/docs/reference/parameters#sources), which the application also reads. `bake` reads the render feature flags from it, and `query` and `browse` read the [roots](#roots). A missing file sets nothing. |
| `-V`, `--version`; `-h`, `--help` | | |

BELD reads the `RUST_LOG` environment variable for its log filter.

## Commands

| Command | Arguments and flags | Effect |
| --- | --- | --- |
| `bake [ids...]` | `--force`; `--memory-budget-mib <n>`, default half the available memory and never below a quarter of the installed memory; `--texture-compression none` or `metal-io-lz4`; `--dry-run`; `--format human` or `json`; `--payload none`, `typed`, or `base64`, default `none` | Bakes the given IDs, or every discovered asset. `--force` rebakes the selection and its dependencies. Only the render feature flags are read from the configuration. `--dry-run` bakes into memory and prints the result instead; see [Dry runs](#dry-runs). |
| `list` | | Prints one resource ID per line, read-only. |
| `inspect <id or uid>` | `--format human` or `json`; `--payload none`, `typed`, or `base64`, default `none` | Prints one resource's metadata and model, read-only. A 32-character hexadecimal argument is tried as a UID first. |
| `query [terms...]` | `--group <field>`, `--sort <field>`, `--reverse`, `--limit <n>`, `--format human` or `json` | Prints the resources that match a filter, grouped and sorted, read-only; see [Query](#query). |
| `browse` | | Opens an interactive view of every resource in the store, read-only; see [Browse](#browse). |
| `delete <ids...>` | | Removes each resource. |
| `clear`, `wipe` | | Removes every resource and payload, keeping the store's mode. |

A bake discovers every supported file below the source directory, follows
symbolic links with cycle detection, skips sidecars and unknown files, and
leaves out the pipelines and shaders of render features the configuration
turns off. Explicit IDs always bake. Up to 16 assets bake at once, and each
is skipped when its stored resource is current with every source file it was
baked from.

## Dry runs

`bake --dry-run` bakes the given IDs and every resource they depend on into
an empty in-memory store, prints that store, and discards it. It reads the
source directory and the configuration, and it doesn't read, create, or write
anything under the destination directory.

| Rule | Effect |
| --- | --- |
| IDs | At least one ID is required; a dry run doesn't discover assets. |
| `--force`, `--texture-compression` | Rejected with exit code 2. Every dry run bakes from scratch, and payloads stay uncompressed. |
| `--destination`, `--storage-mode` | No effect. |
| `--memory-budget-mib`, `--config` | Apply as in a normal bake. |
| `--format`, `--payload` | Accepted on `bake` only with `--dry-run`. |
| Exit code | The same as a normal bake of the same IDs. |

## Query

`query` prints the resources that match a [filter](#filter), grouped and
sorted, and exits. It reads the store as described in
[Filter, group, and sort](#filter-group-and-sort).

| Argument or flag | Effect |
| --- | --- |
| `terms...` | The terms of one [filter](#filter). An argument can hold several terms separated by spaces. Without terms, every resource matches. A term that starts with `-` must follow a `--` argument. |
| `--group <field>` | Groups the resources by a [field](#fields). Without it, the output has no groups. |
| `--sort <field>` | Orders the groups and the resources by a [field](#fields), in that field's [direction](#grouping-and-sorting). Defaults to `stored`, largest first. |
| `--reverse` | Reverses the order of the groups and of the resources in each group. |
| `--limit <n>` | Lists at most `n` resources in each group, or in all when ungrouped. Counts and sums still cover every matching resource, so `--limit 0` prints only those. |
| `--format human` or `json` | The [output format](#output-formats). Defaults to `human`. |

A term, `--group` field, or `--sort` field that doesn't parse exits with code 2
and prints nothing.

## Browse

`browse` shows the store in an interactive terminal view that you filter,
group, and sort as described in
[Filter, group, and sort](#filter-group-and-sort).

| Rule | Effect |
| --- | --- |
| Terminal | Standard input and standard output must be an interactive terminal, or `browse` exits with code 1. |
| Snapshot | The view shows the store as read at startup or at the last `R`. |
| Initial view | No filter, no group, sorted by `stored`, largest first. |

### Panes

| Pane | Shows |
| --- | --- |
| Table | One row per resource: its ID, class, stored size, encoding, and ratio, and the sort field when it isn't one of those. When grouped, one row per group, collapsed at first, with its resource count, summed stored and decoded sizes, and share of the stored bytes of every resource in the store. |
| Detail | The selected resource: the `inspect` output, its streams largest first, its source files and whether each is current, whether it's a root or unreachable, the resources it references and the resources that reference it, its `total`, and its bake trace. A failed bake shows its trace only. A selected group shows its resource count, summed decoded and stored sizes, ratio, and share of the store. |
| Usage | The whole store, regardless of the filter; see [Usage](#usage). |

### Key bindings

| Key | Effect |
| --- | --- |
| `/` | Edits the filter. The view follows each keystroke while the filter is valid. `Enter` keeps the filter, and `Esc` restores the filter from before the edit. |
| `g` | Opens the group picker: `none`, every field, every declared property in the store, and `model.` followed by a typed path. |
| `s` | Opens the sort picker, with the entries of the group picker except `none`. |
| `r` | Reverses the sort order. |
| `↑`, `↓`, `Page Up`, `Page Down`, `Home`, `End` | Move the selection in the focused pane. |
| `Enter` | On a group, expands or collapses it. On a resource, focuses the detail pane. On a reference in the detail pane, shows that resource in the detail pane, and selects it in the table when the filter shows it. |
| `Tab` | Moves the focus between the table and the detail pane. |
| `Backspace` | Shows the resource from before the last jump through a reference. |
| `u` | Shows or hides the usage pane. |
| `R` | Reads the store and the source directory again, keeping the filter, group, and sort. |
| `Esc` | Closes a picker, or returns the focus to the table. |
| `q`, `Ctrl+C` | Quits with code 0. |

### Usage

| Entry | Value |
| --- | --- |
| Classes | For each class, the resource count and the summed decoded and stored sizes. |
| Database | The size of `resources.db`, and the summed `metadata` of every resource. |
| Duplicates | Each group of two or more resources with the same hash and a non-empty payload. The wasted bytes are the stored sizes of all but one resource in each group. |
| Orphaned payloads | In files mode, the count and size of payload files whose name doesn't match the UID, hash, and encoding of a stored resource. See the store's [files](/docs/reference/resource-store#files). |
| Staging files | The count and size of `.resource-write-*` files. |
| Pack | In packed mode, the pack file's size, the bytes resources occupy, the free bytes, the number of free ranges, the largest free range, and whether the pack meets the [fragmentation rule](/docs/reference/resource-store#storage-modes). |
| Bakes | The number of stale resources and, in debug builds, of failed bakes. |

## Filter, group, and sort

`browse` and `query` read the metadata of every resource in the destination
directory, without payloads, and read the source directory to check whether
each resource is current. They write to neither directory.

| Rule | Effect |
| --- | --- |
| Source directory | Read for source file versions. If it can't be read, every resource's status is `unknown`. |
| Release builds | Read no traces or references. Failed bakes don't appear, and fields and flags marked debug are rejected. A store baked by a release build has no references. |
| Configuration | Read from `--config` for the [roots](#roots). A file that exists but can't be read or parsed exits with code 1. |

### Roots

The roots are the resources an application loads by ID. Every other resource
is needed only when a root references it, directly or through other
resources.

| Rule | Effect |
| --- | --- |
| `resources.roots` | An array of glob patterns in the configuration. Each pattern matches the whole ID the way a filter glob does: `*` matches any run of characters, including `/` and `#`, `?` matches one character, and case is ignored. |
| Root | A resource whose ID matches at least one pattern. |
| Reachable | A root, or a resource that a reachable resource references. |
| No roots | Without `resources.roots`, or with an empty array, `is:unreachable` is an error. |
| Patterns | A pattern that matches no resource has no effect. |

### Filter

```
filter   = [ term { " " term } ]
term     = [ "-" ] ( word | field operator value | "is:" flag | "has:" level )
operator = "=" | "!=" | "~" | ">" | ">=" | "<" | "<="
level    = "warnings" | "errors"
```

A resource matches when it matches every term. A leading `-` negates a term.
An empty filter matches every resource. Values can't contain spaces.

| Term | Matches when |
| --- | --- |
| `word` | The ID contains `word`, ignoring case. A word with `*` or `?` is a glob that must match the whole ID, also ignoring case: `*` matches any run of characters, and `?` matches one character. |
| `field=value` | The field's value equals `value`, exactly for text and numerically for the other types. |
| `field!=value` | The field's value differs from `value`, or the resource doesn't have the field. |
| `field~text` | The field's value, as text, contains `text`, ignoring case. |
| `field>value`, `field>=value`, `field<value`, `field<=value` | The field's value compares that way with `value`. The field can't be text. |
| `is:flag` | The [flag](#flags) holds. |
| `has:warnings`, `has:errors` | The bake trace has at least one warning, or at least one error. Debug. |

A resource without a field matches no term on that field except `!=`. A term
that names an unknown field, compares text with a number operator, or has a
value that doesn't parse for its field type is an error.

| Field type | Value |
| --- | --- |
| Text | Any characters. |
| Number | A decimal number. |
| Size | A decimal number followed by `B`, `KiB`, `MiB`, or `GiB` in any case, or by nothing for bytes. |
| Age | A decimal number followed by `s`, `m`, `h`, or `d`. `baked<1h` matches resources stored less than an hour ago. |

### Fields

| Field | Type | Value |
| --- | --- | --- |
| `id` | Text | The resource ID. |
| `class` | Text | The resource class. |
| `source` | Text | The ID without its fragment. |
| `encoding` | Text | `raw`, `cpu-lz4`, or `metal-io-lz4`. |
| `hash` | Text | The payload hash as 16 lowercase hexadecimal characters. |
| `status` | Text | One of the [statuses](#statuses). |
| `size` | Size | The decoded payload size. |
| `stored` | Size | The stored payload size. |
| `ratio` | Number | `stored` divided by `size`, or 1 for an empty payload. |
| `metadata` | Size | The size of the serialized model. |
| `baked` | Age | The time since the resource was stored. |
| `refs` | Number | The number of resources the resource references. Debug. |
| `used-by` | Number | The number of resources that reference the resource. Debug. |
| `total` | Size | The `stored` size of the resource and of every resource it references, directly or through other resources, each counted once. Debug. |
| A declared property, such as `render-pass` | Text | The property's value. A field in this table with the same name takes precedence. |
| `model.<path>` | Number or text | The value at `path` in the `resource` object of the `inspect` JSON output. `path` is object keys and array indexes separated by dots, such as `model.extent.width` or `model.shaders.0.id`. A number is a number; any other value is text, with objects and arrays as compact JSON. |

A failed bake has only `id`, `source`, and `status`.

### Flags

| Flag | Holds when |
| --- | --- |
| `is:failed` | The status is `failed`. Debug. |
| `is:stale` | The status is `stale`. |
| `is:compressed` | The encoding isn't `raw`. |
| `is:duplicate` | Another resource has the same hash, and neither payload is empty. |
| `is:root` | The ID matches a [root](#roots) pattern. |
| `is:unreachable` | The resource isn't [reachable](#roots) from a root. A failed bake isn't unreachable. Debug. |
| `is:dangling` | The resource references an ID that has neither a resource nor a failed bake in the store. Debug. |

### Statuses

| Status | Meaning |
| --- | --- |
| `current` | Every source file version the resource records matches the source directory. |
| `stale` | At least one source file the resource records changed or no longer exists, so the next `bake` processes it again. |
| `unknown` | The source directory couldn't be read. |
| `failed` | The latest bake of the ID stored no resource and left a trace. Debug. |

### Grouping and sorting

| Rule | Effect |
| --- | --- |
| Groups | Each distinct value of the group field is a group. Resources without the field form a group named `(none)`. |
| Resource order | By the sort field, text in code point order, with ties ordered by ID. Resources without the field come last. |
| Group order | By the summed value of the group's resources for `size`, `stored`, `metadata`, and `total`; by the group's summed `stored` divided by its summed `size` for `ratio`; and by the group's value, in the direction of the group field, for every other field. |
| Direction | A sort field orders sizes and numbers largest first, ages newest first, and text and model fields in ascending order. `r` in `browse` and `--reverse` in `query` reverse resources and groups; missing values stay last. |

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success. |
| 1 | The configuration couldn't be read, the store couldn't be opened or its mode didn't match, a command failed, at least one baked asset failed, at least one delete failed, or `browse` ran without an interactive terminal. |
| 2 | Invalid arguments, including a `query` filter term or field that doesn't parse, and `is:unreachable` without roots. |

## Output formats

| Output | Shape |
| --- | --- |
| `inspect`, JSON | An object with `id`, `uid`, `class`, `hash`, `size`, `stored_size`, `encoding`, `serialized_resource_size`, `baked_at`, in nanoseconds since the Unix epoch, `properties`, `streams`, and `resource`, the model as JSON. Each stream has `name`, `size`, and `offset`. Debug builds add `trace`, the bake messages. A failed asset with only a trace prints `resource` as null. |
| `inspect`, human | `key: value` lines, nested objects indented by two spaces, arrays as dashed items. |
| `bake --dry-run`, JSON | An object with `resources`, every stored resource in the `inspect` JSON shape ordered by ID, and `failed`, one object per requested ID that failed, with `id` and `error`. Debug builds add `trace` to both. |
| `bake --dry-run`, human | The same object in the `inspect` human layout. |
| `query`, JSON | An object with `count`, the number of matching resources and failed bakes; `size` and `stored`, their summed decoded and stored sizes; and `share`, `stored` divided by the summed stored size of every resource in the store, or 0 for an empty store. Without `--group`, it adds `resources`, the listed resources in order. With `--group`, it adds `groups` in order, each with `name`, the group's value as text, and the group's own `count`, `size`, `stored`, `share`, and `resources`. |
| `query`, JSON resource | An object with `uid`, `properties`, and every [field](#fields) with a fixed name that the resource has, under that name. Sizes are in bytes, and `baked` is in seconds. It adds each `model.<path>` field that the filter, `--group`, or `--sort` names, when the resource has it. Debug builds add `trace`, the bake messages. A failed bake has `id`, `source`, `status`, and `trace`. |
| `query`, human | A line of field names, then one line per resource with its `id`, `class`, `stored`, `encoding`, and `ratio`, followed by every other field that the filter, `--group`, or `--sort` names. A failed bake shows `failed` as its class. With `--group`, each group starts with a line of its name and totals, and its resources follow, indented. A line says how many resources `--limit` left out of a group. The last line gives the totals of every matching resource. |

Models with a JSON
form are animation, audio, image, LUT, material, mesh, primitive, shader,
skeleton, and variant; flipbooks, pipelines, and particle systems print an
unsupported marker.

Logs go to standard error, so standard output carries only the command's
output. Whether either stream is a terminal changes only how the output looks;
see [Terminals](#terminals).

## Payloads

`--payload` adds each stream's bytes to the `inspect` and `bake --dry-run`
output. Any value other than `none` requires `--format json`; other
combinations exit with code 2.

| Value | Each stream adds |
| --- | --- |
| `none` | Nothing. |
| `typed` | `encoding` `json`, `element`, and `data`, an array of decoded elements, when the stream's layout appears in the next table. Otherwise the stream falls back to `base64`. |
| `base64` | `encoding` `base64` and `data`, the stream's decoded bytes as one padded base64 string in the standard alphabet. |

A resource whose payload has no named streams but isn't empty, like audio or a
LUT, prints one stream named `payload` that covers all of it. Bytes are always
the decoded payload, never the stored compressed form. A payload stored with
`metal-io-lz4` compression can't be read on the CPU, so `inspect` exits with
code 1.

| Class | Stream | `element` | Each element in `data` |
| --- | --- | --- | --- |
| Mesh | `Vertex.Position`, `Vertex.Normal`, `Vertex.Tangent`, `Vertex.BiTangent`, `Vertex.UV`, `Vertex.Color`, `Vertex.Joints`, `Vertex.Weights` | The vertex component format, such as `vec3f` | An array of the format's component count. |
| Mesh | `VertexIndices`, `TriangleIndices` | `u16` | An integer. |
| Mesh | `MeshletIndices` | `u8` | An integer. |
| Mesh | `Meshlets` | `meshlet` | An object with `vertex_count`, `triangle_count`, `center`, `radius`, `cone_apex`, `cone_cutoff`, and `cone_axis`. |
| Image | Every stream | The stream's texel format, such as `RGBA8` | An array of channel values. |
| Audio | `payload` | `frame` | An array with one sample per channel. |
| LUT | `payload` | `rgb` | An array of three numbers. |

Elements appear in stream order, and image texels appear row by row from the
top-left texel. An image stream uses the format of the image-based lighting
level it belongs to, or the image's own format.

| Element type | Values |
| --- | --- |
| `f` and `f16` vertex components; `R16F` and `RGBA16F` texels; LUT entries | The shortest decimal that reads back as the same 32-bit float. Half-precision values widen to 32 bits first. NaN and infinities print as null. |
| `u16` and `i16` vertex components; `u` and `i` vertex components | Integers. |
| `RG8`, `RGB8`, `RGBA8`, and `RGBA8SRGB` texels | Integers from 0 to 255, sRGB-encoded where the format is. |
| `RG16`, `RGB16`, and `RGBA16` texels | Integers from 0 to 65535. |
| `BC5`, `BC5SNORM`, `BC7`, and `BC7SRGB` texels | No element; the stream falls back to `base64`. |
| 8-bit audio samples | Unsigned integers from 0 to 255, centered on 128. |
| 16-, 24-, and 32-bit audio samples | Signed integers of that width. |

## Terminals

BELD checks standard output and standard error separately. Whether a stream is
a terminal changes only how its text looks. The output format, the content,
and the exit code stay the same.

| Stream | When it's a terminal |
| --- | --- |
| Standard output | `--color auto` colors the human output, and `query` fits its human output to the terminal width; see [Width](#width). |
| Standard error | `--color auto` colors log messages, and `bake` shows a progress line; see [Progress](#progress). |

### Color

`--color` sets color for each stream separately.

| Value | A stream has color |
| --- | --- |
| `auto` | When the stream is a terminal and `TERM` is set and isn't `dumb`, unless an environment variable in the next table decides. |
| `always` | Always. |
| `never` | Never. |

| Environment variable | Effect on `auto`, in order of precedence |
| --- | --- |
| `NO_COLOR` set to any value but the empty string | No color. |
| `CLICOLOR_FORCE` set to any value but `0` or the empty string | Color, even when the stream isn't a terminal. |
| `CLICOLOR=0` | No color. |
| `CLICOLOR` set to any other value, or `CI` set | Color on a terminal even when `TERM` is unset or `dumb`. |

| Output | Colored parts |
| --- | --- |
| Help and argument errors | Headings, usage, literals, placeholders, and errors. |
| Log messages | The level name. |
| `query`, human | The header line in cyan, group lines in bold, a `stale` resource's line in yellow, and a `failed` bake's line in red. |
| `inspect` and `bake --dry-run`, human | Keys in cyan. |

JSON output and `list` output never have color.

### Width

When standard output is a terminal, `query`'s human output narrows the `id`
column so each resource line fits the terminal width.

| Rule | Effect |
| --- | --- |
| Shortened ID | Keeps its first and last characters, with `…` in place of the middle. |
| Narrowest column | 16 characters. A line that still doesn't fit wraps. |
| Other lines | The header, group lines, `--limit` lines, and the totals line keep their full text. |

When standard output isn't a terminal, no line is shortened.

### Progress

When standard error is a terminal, `bake`, including `--dry-run`, shows one
progress line at the bottom of standard error while assets bake.

| Rule | Effect |
| --- | --- |
| Line | `[done/total]`, the number of assets processed and requested; then `N failed` once an asset fails; then the IDs baking now. The line is cut to the terminal width. |
| Log messages | Print above the line. The messages that each asset started baking or is up to date aren't written; failures are. |
| End | The line is removed before the summary message. |

When standard error isn't a terminal, `bake` logs a message when each asset
starts baking and when it's up to date, and shows no progress line.
