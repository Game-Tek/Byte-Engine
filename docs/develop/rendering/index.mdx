Use these notes to learn how the renderer is put together, and which rules keep
it fast, before you change the renderer, a rendering pipeline, or the graphics
hardware interface (GHI).

Choose a topic:

- [Loading timeline](/docs/develop/rendering/loading): how loaded resources
  reach the GPU without ever blocking rendering.
- [Lighting pipeline](/docs/develop/rendering/lighting): how authored light
  units reach the GPU and how lights are culled.
- [Visibility pipeline](/docs/develop/rendering/visibility): how the visibility
  pipeline is built, starting with how it sizes and updates shadow maps.
- [Ray tracing](/docs/develop/rendering/ray-tracing): how the GHI builds
  acceleration structures, ray tracing pipelines, and shader binding tables on
  Metal and Vulkan, and why hits are sorted before they're shaded.
- [Shader variants](/docs/develop/rendering/shader-variants): when to leave a
  shader feature out at bake time, and when to select it with a specialization
  constant.
- [Debug views](/docs/develop/rendering/debug-views): how a pass shows what it
  computes through the renderer's pool of debug targets, and how release bakes
  leave that code out.
