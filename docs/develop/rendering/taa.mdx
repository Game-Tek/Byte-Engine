Read this page before you change the `taa` pass, `render_passes/taa.rs`, the `taa/` shaders, the velocity stage in
`pipelines/visibility/render_pass/velocity.rs`, jitter in `sink.rs` and `renderer/core.rs`, or the engine's blue
noise. What these produce is specified under [Jitter](/docs/reference/rendering#jitter),
[Temporal antialiasing](/docs/reference/rendering#temporal-antialiasing),
[Blue noise](/docs/reference/rendering#blue-noise), and the `Velocity` and `Reactive` rows of
[Stages and targets](/docs/reference/rendering#stages-and-targets).

## How the pieces connect

Temporal antialiasing is an ordinary post-scene pass. Nothing selects an antialiasing technique: an application
installs SMAA, temporal antialiasing, or neither with its own setup call, and `render.pass.taa` bypasses the pass at
runtime. What a temporal
pass needs from the rest of the renderer comes through the sink:

- **Jitter.** `PassHints::jitters_view` asks for it, like `samples_lens` asks for lens samples. While an enabled pass
  of a sink answers `true`, the renderer sets `Sink::with_jitter` from 8 Halton (2, 3) points. `Sink::view` stays the
  view without jitter, which every pass that culls, places, or reprojects reads. Scene pipelines rasterize through
  `Sink::jittered_view`: the visibility pipeline uploads it as the camera's `view_projection`, and particles and the
  simple pipeline take it from `Sink::view_projection`. Debug meshes draw after the pass, so they take `Sink::view`.
- **Velocity and the reactive mask.** The visibility pipeline writes `Velocity` and clears `Reactive` while an enabled
  pass of its sink reads `Velocity`: the pass reads it through `RenderPassBuilder::read_from`, the renderer gathers
  what each sink's enabled passes read into `Sink::with_read_targets`, and the velocity stage asks `Sink::reads` with
  the id `RenderPassBuilder::target_id` gave it. Jitter doesn't turn velocity on, so motion blur reads it without
  temporal antialiasing. Transparent material evaluation then writes `min(α, 0.9)` into `Reactive`.
- **Exposure and resets.** The pass keeps the extent and exposure of the last frame it resolved. A frame at another
  extent, or after a bypass, resets the history.

These are the inputs AMD FidelityFX Super Resolution (FSR), NVIDIA Deep Learning Super Sampling (DLSS), Intel XeSS, and the MetalFX temporal scaler
take, so a vendor upscaler is one more technique of the same pass, not another pass.

## Techniques and render scale

`TaaPassSettings::technique` picks the blend each frame: `engine`, the resolve below, or `metalfx`. A technique the
device lacks resolves with `engine`, and the pass warns once. Both render the scene at `TaaPassSettings::scale`,
which `engine` holds to 0.5 through 1 and a vendor upscaler to the device's range.

- **Render and output extents.** `PassHints::render_scale` asks for a scale, like `jitters_view` asks for jitter, and
  a bypassed pass asks for 1. The renderer sets `Sink::with_render_scale`, so `Sink::extent` is the render extent for
  scene pipelines and the passes before `taa`, and the output extent for `taa` and the passes after it, which see
  `Sink::at_output`. The pass creates `main` with `create_output_main_render_target`, which makes every later target
  follow the output extent. `RenderTargets` keeps one flag per target, and debug view slots always follow the output
  extent, since they're presented over it.
- **Jitter and texture detail.** At render scale s, jitter walks ⌈8 / s²⌉ Halton points, in render pixels, and material
  texture reads scale their footprint by s, so textures stay as sharp as the output's pixels.
- **The GHI upscaler.** `ghi::upscaler` is backend neutral: `Context::temporal_upscaler_scale_range`,
  `ContextCreate::build_temporal_upscaler`, and `CommandBufferRecording::upscale`. Backends without an upscaler keep the
  trait defaults, which report none. The pass rebuilds the upscaler when the render or output extent changes.
- **MetalFX synchronization.** The Metal backend builds an `MTL4FXTemporalScaler`, since it records into Metal 4 command
  buffers. Textures live in untracked heaps and MetalFX encodes its own encoders, so GHI's barriers can't reach it.
  `upscale` plans the inputs' barriers on a compute encoder of its own, updates the scaler's fence after that encoder,
  and gives MetalFX the fence to wait for. It then records MetalFX's reads and writes as one more encoder, so later
  commands, including writes to targets that share the inputs' memory, wait for it with a queue barrier.
- **The storage stand-in.** MetalFX's output needs shader-write usage, and an Apple GPU can't keep such an image
  losslessly compressed for the passes that read it afterward. So the pass keeps `TAA Output` without storage use and
  creates `TAA Upscaled` with it, through `RenderPassBuilder::create_main_stand_in`. `PassHints::writes_main_stand_in`
  answers `true` in a frame MetalFX ran, and `RenderTargets::plan` then places `TAA Output` as `TAA Upscaled`'s image,
  the way it places an idle pass's replacement as the `main` before it. A technique change places the sink's targets
  again. On the quarry at 3840 × 2036 the storage use read about 0.2 ms on `pass.taa` under `engine`.
- **MetalFX conventions.** Motion is `Velocity` times −1, since MetalFX wants where a pixel came from. The jitter goes as
  the sink holds it, in pixels with y down: negating either axis doubled every edge into a grid of seams once the scale
  dropped below 1, while at scale 1 the error stays under a pixel and hides. Depth is reversed. The pre-exposure is the exposure relative to the frame MetalFX last reset on: MetalFX divides the color by it and keeps half-float history, so the full exposure of a sunlit scene, about 2⁻¹⁵, overflowed it and posterized the image. MetalFX keeps its own history,
  so it resets whenever the frame before didn't run MetalFX at the same extents. MetalFX takes the engine's
  `RGBu11u11u10` color and the `RGBA16F` velocity as they are.

## Velocity

The velocity stage runs after the depth pyramid, while the visibility buffer still holds the opaque layer; the
transparent layer overwrites it later. For each pixel it rebuilds the surface point from depth under the jittered view,
takes its barycentrics on the triangle the visibility buffer names, and places the same barycentrics on the triangle as
this frame and the previous frame posed and placed it. Rigid and skinned motion share that path. Both points come from
the same barycentrics, never the current one from depth, so rounding in them moves both alike: on a thin triangle, or a
pixel whose depth misses its triangle, a still surface measured from depth showed motion of tens of pixels.

The previous frame's state stays on the GPU:

- **Model matrices.** A second dispatch copies each instance's model matrix into a GPU-only buffer after the velocity
  is written, by the instance's slot, which stays the same across frames. A zero matrix means the instance has no
  previous frame. When the previous frame skipped the stage, the buffer holds an older frame's matrices, so
  `previous_models_valid` is 0 and every instance counts as still for one frame. `SinkHistory::read_targets` tells
  the stage whether the previous frame read `Velocity`. The instance table's previous-frame copy can't serve instead: the CPU writes it for the next frame
  while the GPU may still read it.
- **Skinned positions.** Skinning copies each posed vertex's old position to `previous_vertex_positions` before writing
  the new one.

The background moves by the camera's turn alone, and takes the far plane as its previous depth, so the disocclusion
test catches background pixels that geometry covered in the previous frame.

## The resolve

`taa/resolve.besl` is one tile pass that writes `main` and the history. It runs at the output extent and reads the
scene, both velocities, and `Reactive` at the render extent, so the same pass antialiases at scale 1 and upscales
below it. Its steps follow published methods, ordered by how much ghosting each prevents:

1. **Nearest-depth velocity dilation** (FSR 2; Pedersen, *Temporal Reprojection Anti-Aliasing in INSIDE*, 2016). The
   edge of a moving object reprojects with the object's motion, not the background's, which is the largest single
   source of trails.
2. **Depth disocclusion** (FSR 2). The farthest of the 4 previous depth texels around the reprojected point must reach
   99 % of the surface's previous depth. Otherwise something stood in front of it, and its history is dropped. Both
   depths come from `Velocity`, which keeps a copy per frame, because the transparent layer overwrites `Depth` without
   moving the velocity: comparing against `Depth` dropped the history under every blended surface.
3. **Variance clipping toward the box center in YCoCg** (Salvi, *An Excursion in Temporal Supersampling*, Game Developers Conference 2016;
   Pedersen). The box is μ ± γσ of the 3 × 3 neighborhood, inside its minimum and maximum, with γ = 1.
4. **Feedback.** INSIDE's luma weight between feedback 0.88 and 0.97, phased in as a pixel's motion grows to 2 pixels
   per frame, lowered toward the minimum between 2 and 15 pixels of motion, held at `n / (n + 1)` for a history `n`
   frames old, and scaled by `1 − Reactive`. A still pixel keeps the maximum: the jittered samples of detail finer than
   a pixel, such as grass and its shadows, differ from the history every frame, and the luma weight then let up to 12 %
   of each frame through, so the 8-frame jitter cycle showed as flicker. Applying the weight only with motion is the
   engine's own choice; history that can be stale while still is rejected by the depth test, clipping, and `Reactive`.
5. **Sharp resampling.** A 5-tap Catmull-Rom history read (Jimenez, *Filmic SMAA*, SIGGRAPH 2016), so repeated
   resampling doesn't blur still images.
6. **Weighted blending** (Lottes): colors blend as `c / (1 + Y)`, so one bright sample can't dominate the history.

Below scale 1 the resolve upsamples as Karis (*High Quality Temporal Supersampling*, SIGGRAPH 2014) and Yang, Liu,
and Salvi (*A Survey of Temporal Antialiasing Techniques*, 2020, section 5) describe: each output pixel filters the
frame's samples around its center by how near they lie, and scales that color's share of the blend by a confidence
that falls with the nearest sample's distance, so a pixel far from every sample of a frame keeps its history, and over
the jitter's ⌈8 / s²⌉ phases each pixel gets samples of its own. Both weights are exp(−2.29 d²), Karis's Gaussian fit
to a Blackman-Harris window, with d in output pixels. The filter matters in motion, where the history weighs least:
with only the nearest sample, output pixels that share a sample repeat it, and foliage turns blocky. Two parts are the
engine's own: keeping the weight at 1 and the color unfiltered at scale 1, so the image there is the same as before
the resolve could upscale; and the 0.5 lower bound on the scale. Every step reads the 3 × 3 render pixels around the
nearest sample, so the neighborhood box covers a wider area of the output than at scale 1 and clips less.

On the quarry at 3840 × 2036 and scale 0.67, an M4 drew a frame in 36.7 to 37.1 ms with `engine` and 39.7 to 40.1 ms
with `metalfx`, as GPU `frame` p50 over interleaved runs.

The history's frame count, kept in its alpha, is the one combination of the engine's own: FSR keeps a comparable
count in a separate image. The 1 % disocclusion margin is also the engine's own choice.

## Masked cutoff

Alpha-tested foliage aliases under any spatial filter, because leaves thinner than a pixel drop in and out of pixels
from frame to frame. In a jittered frame, the masked visibility pass dithers its cutoff instead, so the resolve
averages the frames into partial coverage. `masked_coverage` in `scene_records.besl` combines two published methods:

- **Anti-aliased alpha test** (Golus, *Anti-aliased Alpha Test*, 2017). Opacity is rescaled by its change across one
  pixel, `fwidth`, so it ramps from 0 to 1 over one pixel around the cutoff.
- **Hashed alpha test** (Wyman and McGuire, *Hashed Alpha Testing*, 2017). The ramp is compared against the
  engine's blue noise instead of a hash. A threshold of 0.5 keeps exactly the fragments whose opacity reaches the
  cutoff, so frames without jitter look as before, and the coverage-preserving mips still match.

The scene set carries the noise slice in its `frame` record and the blue noise beside it. The slice follows the scene's
first sink, as the texture footprint does, and is `FIXED_CUTOFF` in a frame without jitter. Fragments read their pixel
through `input.thread_id`. The shadow passes keep the fixed cutoff, because shadow maps have no temporal blend.

## Blue noise

Effects that take one random sample per pixel read the engine's spatiotemporal blue noise (Wolfe et al.,
*Spatiotemporal Blue Noise Masks*, Eurographics Symposium on Rendering 2022): 32 slices of 64 × 64, two channels, stacked in one 64 × 2048 texture.
Each slice is blue noise across the image, and each texel's values through the slices are blue noise in time, so the pass's
blend averages them faster than values that change at random. The tests in `lookup_textures.rs` generate it with the
paper's void-and-cluster energy: a Gaussian across a slice within one slice, a Gaussian through time within one texel,
σ = 1.9 on every axis, and a 10 % initial pattern. The camera jitter isn't blue noise: it moves the whole image by one
offset per frame, which a low-discrepancy sequence covers most evenly.

## Rules a change must keep

- **Reproject without jitter.** `Sink::view` never includes the jitter. Velocity uses the views without jitter on both
  frames, so a still scene has zero velocity whatever the jitter.
- **Rebuild positions with jitter.** A pass that turns a pixel and its depth back into a position uses the jittered
  view, because the depth was rasterized through it. `screen_view_data` builds the screen-space passes' constants from
  `Sink::jittered_view` and keeps the projection's off-center terms. Built without jitter, each frame's positions were
  off by that frame's jitter, and the shadows the sun visibility pass looked up from them shook.
- **Keep the velocity convention.** `Velocity` holds this frame's position less the previous frame's, in pixels, x
  right and y down, and the opaque surface's previous and current linear depth in blue and alpha.
- **Read the visibility buffer before the transparent layer.** The velocity stage records before the transparent draw.
- **Clear `Reactive` wherever velocity runs.** Only blended surfaces raise it.
- **Reset on frames whose history isn't this sink's.** A resize or a bypass resets the history.
- **Keep the noise still without jitter.** Passes without history read blue noise slice 0 unless the sink is jittered.
- **Keep the masked cutoff fixed without jitter.** A frame without jitter writes `FIXED_CUTOFF`, and the threshold
  stays 0.5. Masked shadow passes never dither.
- **Don't share one sample across pixels.** A screen-space effect whose result changes with the jitter must change
  per pixel, not per block. The variance clip reads a block whose pixels all change together as the image changing,
  and drops its history. Contact shadows traced at half resolution from the nearest of each 2 × 2 pixels' depths:
  on grass, which blade was nearest changed with the jitter, and whole blocks flickered. They now trace every pixel
  and filter 3 × 3 pixels.
- **Size by the node's extent.** A pass reads `Sink::extent`, never the window's size, so it works on either side of
  the upscaler. Only the upscaling pass reads both `Sink::render_extent` and `Sink::output_extent`.
- **Upscale once per sink.** At most one pass calls `create_output_main_render_target`.
- **Keep storage off `TAA Output`.** Only the stand-in has it. Give MetalFX `TAA Upscaled`, never `TAA Output`.

## Tests

- `renderer::core` tests the jitter sequence, and `view` tests the pixel offset.
- `tests/velocity.rs` runs `velocity.besl` in the BESL VM: a still scene under jitter, a moving wall, a moving camera,
  and an instance's first frame.
- The skinning VM test checks that skinning keeps the replaced position.
- `lookup_textures.rs` checks the blue noise's value counts, its spatial and temporal spectra, and, among the ignored
  tests, that the committed texture matches its generator. Regenerate it with
  `cargo nextest run -p byte-engine --cargo-profile release --run-ignored only write_blue_noise`.
- `render_passes/taa.rs` tests the resolve's stages in the BESL VM at full and half scale, the technique fallback, the
  scale ranges, and the MetalFX conventions.
- `masked_coverage_ramps_over_one_pixel_around_the_cutoff_in_the_besl_vm` checks the masked cutoff's ramp and its
  fixed threshold.
- `sink.rs` and `renderer/targets.rs` test which extent each node and target follows, and which image a target with
  a stand-in is.
- The GHI `rendering` test `a_still_frame_upscales_to_its_own_color` runs MetalFX on the engine's formats. Run it with
  `cargo nextest run -p byte-engine-ghi --test rendering --ignore-default-filter upscale`.

## Measure a change

The visibility pipeline times the velocity stage as `stage.velocity`, and the pass reports `pass.taa`. Read them as
[Measure performance](/docs/develop#measure-performance) describes, with `--render.ghi.features.counters=true`.
