Use these notes to learn how the visibility pipeline works, and which rules a
change to it must keep. Its limits and contracts are specified under
[the visibility pipeline](/docs/reference/rendering#the-visibility-pipeline) in
the rendering reference.

Choose a topic:

- [Material parameters](/docs/develop/rendering/visibility/material-parameters):
  where dynamic material parameter values live, how instances find them, and
  why uploads carry only changes.
- [Shadow maps](/docs/develop/rendering/visibility/shadow-maps): how lights get
  shadow maps within the memory budget, how large each map is, and how map
  updates spread over frames within the update budget.
- [Skinning](/docs/develop/rendering/visibility/skinning): where posed vertices
  live, how an animated instance gets and gives back its vertices, and why one
  copy serves every frame in flight.
- [Surfel GI](/docs/develop/rendering/visibility/surfel-gi): how surfels gather
  ray-traced bounce light, why hits sort by material before they're shaded, and
  the rules the frame-wide surfel stages keep.
