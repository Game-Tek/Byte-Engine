Animation turns clips baked from glTF, GLB, and FBX files into poses that the
renderer skins with. This page specifies the data model, how a clip is sampled
and blended, what the animation graph guarantees, how animators play graphs
and post their updates, and the limits of the clip pool. To author the source
files, follow
[Author assets](/docs/use/resources/author); the importer rules are in the
[asset formats reference](/docs/reference/assets#skeletal-models).

## Skeletons and clips

A skeleton is a list of nodes in parent-before-child order. Each node has an
optional name, an optional parent index, and a rest local transform. A local
transform is a translation in the parent's space, a rotation, and a scale; the
identity transform has zero translation, identity rotation, and unit scale.

A clip holds:

| Field | Value |
| --- | --- |
| `name` | Optional. |
| `skeleton` | The skeleton the clip was authored for. |
| `duration` | Seconds. Finite and zero or more. |
| `frame_rate` | Optional. Frames per second when the source format records one; glTF records none. Finite and positive when present. |
| `tracks` | One track per animated node, in strictly ascending node order. A track has at least one of a translation curve, a rotation curve, and a scale curve. |

A curve is one of three kinds: step, linear, or cubic spline with in and out
tangents. A rotation curve's tangents are quaternion derivatives. Every curve
has the same number of times and values, at least one key, times in `[0,
duration]` that strictly increase, and finite values; a cubic curve has one
tangent pair per key.

## Sampling

Sampling a clip at a time in seconds produces a local pose for every node of
the skeleton:

| Rule | Behavior |
| --- | --- |
| Missing curve | The node keeps its rest local value for that channel. |
| Before the first key | The first key's value. |
| After the last key | The last key's value. |
| Step curve | The value of the last key at or before the time. |
| Linear curve | Translation and scale interpolate linearly. Rotation uses normalized linear interpolation along the shorter arc. |
| Cubic curve | Hermite interpolation with tangents scaled by the span between the two keys. A span of zero length yields the lower key. |
| Looping | Not part of sampling. The animation graph loops by phase. |

A global pose is the list of matrices for every node, where a node's global
matrix is its parent's global matrix times its local matrix, and a local matrix
applies scale, then rotation, then translation.

A pose map remaps a clip onto another skeleton by node name. Target nodes with
no source keep the target's rest pose. Mapped target nodes start from the source
rest pose. When several source nodes map to one target, the last one wins.

## Blending

| Operation | Rule |
| --- | --- |
| Two poses | The factor clamps to `[0, 1]`. Translation and scale interpolate linearly; rotation uses normalized linear interpolation. |
| Several poses | Weights must be finite and zero or more, and at least one must be positive. They normalize by their sum. Rotations flip to the hemisphere of the first positively weighted pose before mixing. |
| 1D blend space | At least one position, finite and strictly ascending. A value interpolates linearly between its two neighbors and clamps to the end samples outside the range. |
| 2D blend space | At least three positions and one non-degenerate triangle. A value takes the barycentric weights of the first triangle that contains it; outside every triangle, the closest point on any triangle edge or vertex. Weights clamp to `[0, 1]` and renormalize. |

## Inertialization

An inertializer carries the pose that was on screen into a new destination
without a visible discontinuity. It starts from a source pose and its previous
frame, a destination pose and its previous frame, the sample delta between those
frames, and a duration.

| Rule | Behavior |
| --- | --- |
| Sample delta | Finite and positive. |
| Duration | Finite and zero or more. A zero duration applies the destination at once. |
| At the start | The output equals the source pose. |
| At the end | The output equals the destination exactly, with zero velocity and acceleration. |
| Offset | Settles along a quintic curve that leaves the source without acceleration. |
| Velocity difference | Decays so that one thousandth remains at the end of the duration. |
| Rotation | Offsets are rotation vectors composed onto the destination rotation. |

## Root motion

Root motion is the movement of one named node, taken out of the visual pose so
that the owning object moves instead. A root motion delta is a translation and
a rotation; deltas compose by adding translations and composing rotations, and
blend by linear and normalized linear interpolation. Scale is never part of
root motion.

| Setting | Value |
| --- | --- |
| Node | By name. The name must exist exactly once in the skeleton. |
| Translation | Any subset of the X, Y, and Z axes, or none. |
| Rotation | None or full. |

The delta is measured between the node's previous and current sampled poses,
with the unselected channels replaced by the node's rest values, in object
space. When a looping clip wraps, the delta covers the remainder to the clip's
end, any whole loops, and the start to the current time. In a blend, each
positively weighted clip contributes its own delta, mixed as a weighted mean. In
a transition, the source and destination deltas blend by the transition factor.
The visual pose keeps the rest values on the extracted channels.

## Animation graph

A graph is a state machine built in code. Any number of
[animators](#animators) can play one graph, and each keeps its own playback.

### States

| State | Holds | Playback |
| --- | --- | --- |
| Clip | One clip, looping or played once. | |
| Linear blend | Clips at scalar positions, as a 1D blend space. | A request picks the position. |
| Planar blend | Clips at 2D positions, as a 2D blend space with explicit or fan triangulation. | A request picks the position. |

Every clip in a blend shares one playback mode. A blend's duration is the
weighted sum of its clips' durations, so all its clips share one phase. The
last requested linear position and the last requested planar position are
remembered per animator across all blends of that kind; a blend entered without a position
starts there, and at the origin before any request.

### Routes

A route leads from a source state to a target state.

| Route | Behavior |
| --- | --- |
| Direct, taken when the source settles | Waits until the source has reached its wait point, or its end for a clip played once, then inertializes into the target over the route's duration. A zero duration switches at once. |
| Direct, taken anytime | Also cuts short a blend into the source or a one-shot leading to it. |
| Through a one-shot clip | Plays a clip once between source and target, then inertializes into the target over the exit duration. The one-shot either must complete or may be interrupted. |
| From any state | A route every state can take, considered after the state's own routes. |

A wait point is a frame on the source clip, several frames on one clip of a
blend, or a time. Frames count at the clip's authored frame rate; a clip
without a frame rate never reaches a frame point. A route can also enter the
target at a given frame instead of its start.

Routes resolve in this order. A persistent state ignores a request for itself,
then takes the first of its own routes to the requested state, then any-state
routes. A one-shot takes its own routes first; while it plays, a request other
than its completion may take the completion state's anytime routes or any-state
routes; once it finishes, it takes its completion route. A blend in progress
can only be redirected along anytime and any-state routes, and never toward a
one-shot.

### Building a graph

Building validates the graph and reports the first problem:

| Error | Cause |
| --- | --- |
| `InitialStateOutOfRange`, `TransitionSourceOutOfRange`, `TransitionTargetOutOfRange`, `TransitionStateCompletionOutOfRange` | A state index names no state. |
| `EmptyStateName`, `DuplicateStateName` | A state has no name, or two share one. |
| `EmptyResourceId` | A clip has no resource ID. |
| `TransitionStateMustPlayOnce` | A one-shot transition clip loops. |
| `NegativeTransitionDuration` | A route or exit duration is negative. |
| `InvalidBlend`, `MixedBlendPlayback` | A blend space is invalid, or its clips mix looping and once. |
| `RoutePointClipMissing`, `RoutePointNeedsClip` | A wait point names a clip the source lacks, or a blend's wait point names no clip. |

## Animators

An animator plays one graph for one entity. The animation system steps every
animator of the world scope it's created on, and posts each animator's pose and
root motion to the world.

### Creating and removing

An animator is created through the world's animator factory under the handle of
the entity it poses, usually a skinned renderable.

| Field | Value |
| --- | --- |
| Graph | The graph to play. Any number of animators can play one graph. |
| Root motion | Optional. The settings in [Root motion](#root-motion). |
| Look chain | Optional. The settings in [Look chain](#look-chain). |

| Rule | Behavior |
| --- | --- |
| Adoption | The system adopts animators created after the system, at the start of its next step. It never adopts one created before it. |
| Replacement | An animator created again under the same handle replaces the previous one and starts over at its graph's initial state. |
| Removal | A deletion of the handle removes the animator at the start of the next step. Nothing more is posted for that handle. |
| Canonical skeleton | The skeleton of the first clip of the graph's initial state. Every animator of a graph shares it. Every clip an animator samples maps onto it, and the root motion and look chain node names resolve against it once it's resident. |
| Rejection | An animator whose settings don't resolve against the canonical skeleton is rejected. The system reports the error and posts nothing for the handle. |

### Requests

A request is a targeted message on an animator's handle. It names a state, or a
blend state with its position, and whether a position change is inertialized.

| Rule | Behavior |
| --- | --- |
| Latest wins | A step applies the last request posted for each handle since the previous step. |
| Persistence | A request holds until another replaces it. Before its first request, an animator plays its graph's initial state. |
| Other graph | A request for a state of another graph is discarded and reported as `StateFromDifferentGraph`. The previous request holds. |
| No animator | A request for a handle without an animator is discarded. |

### Playback

Each step advances every animator by the step's delta toward its latest
request, through the routes of its graph.

| Rule | Behavior |
| --- | --- |
| Phase | Advances by the delta divided by the clip's duration. A looping clip wraps; a clip played once stops at its end. A clip of zero duration stays at its start. |
| Clips sampled per step | At most three per motion: the triangle of a planar blend, the pair of a linear blend, or one clip. Only positive weights are sampled. |
| Transition | The destination is sampled at its start phase, both motions advance, and the inertializer carries the pose until the route's duration elapses. |
| Hand-over at a wait point or a one-shot's end | The time left in the step plays on the next state in the same step. |
| Redirect | A blend in progress can be redirected along an anytime route once the animator has posted a pose, from the pose and velocity it posted last. |
| Position change on a blend | An inertialized request blends the state from its current weights to the new ones, from the pose posted last. |
| Prefetch | Entering a state requests the clips of every state its routes can reach. |
| Initial clip not resident | The animator posts nothing. |
| Other clip not resident | The animator holds and posts its previous pose, with an identity root motion delta. |

### Stepping

The system steps once per frame, with the frame's delta. A step adopts new
animators and removes deleted ones; applies the latest requests and look
targets; admits the clips that finished loading; decides every animator's
routes, phases, and hand-overs for the delta and pins the clips they sample;
samples, blends, and inertializes every pose, extracts its root motion, applies
its look chain, and builds its global pose; posts the updates; and finally
unpins the clips.

| Rule | Behavior |
| --- | --- |
| Lanes | A step spreads its animators over the alley's lanes. |
| Independence | An animator's pose, root motion, and state don't depend on the lane count or on the other animators, whatever graphs they play. |
| Completion | Every update of a step is posted before the step returns. |
| Order | Animators post in no particular order. |

### Updates

Every step posts two updates for every animator whose initial clip is resident.

| Update | Route | Carries |
| --- | --- | --- |
| Pose update | The world's pose route, in headed builds only. | The global matrix of every canonical skeleton node, in node order, after the look chain. |
| Root motion update | The world's root motion route. | The step's root motion delta, in the entity's object space, and the state playing after the step. An animator without root motion settings carries the identity delta. |

The system never moves an entity: applying root motion to a transform is up to
the code that owns the entity.

### Queries

Between steps, the system answers these for each animator, as of the last step:

| Query | Answer |
| --- | --- |
| Playing state | The state playing, or none before the initial clip is resident. |
| Waiting for | The requested state whose route waits for the playing state to reach one of its wait points, or none. A new request cancels the wait. |
| Time until a route | How long the playing state plays on before its route to a given state starts: zero for a route that doesn't wait, and the time to the nearest wait point for one that does. None when the playing state has no route to that state, a one-shot has played past every wait point, the animator is blending, or the initial clip isn't resident. |

### Look chain

A look chain turns a chain of nodes toward a direction on top of the graph's
pose, before the global pose is built.

| Setting | Value |
| --- | --- |
| Nodes | One or more node names with a share each, from the chain's base to its end. Each name must exist exactly once in the canonical skeleton, and each node must descend from the node before it. |
| Shares | Finite and positive. They normalize by their sum. |
| Body node | A node name that must exist exactly once. Its animated yaw centers the yaw limit. |
| Yaw limit | Radians, from 0 to π. |
| Up and down limits | Radians, from 0 to π/2 each. |
| Response | Per second, finite and positive, or none for no easing. |

A look target is a targeted message on an animator's handle with a yaw and a
pitch in the entity's object space, or none to release the chain. The latest
target holds until another replaces it; before the first one, the chain is
released.

| Rule | Behavior |
| --- | --- |
| Angles | Yaw turns about +Y and pitch about +X, by the right-hand rule, in object space. The object faces -Z, so a positive pitch looks up. A turn pitches first, then yaws. |
| Animated yaw | For a node, the angle about +Y from -Z to -Z turned by the node's object-space rotation times the inverse of its rest object-space rotation, projected onto the XZ plane. |
| Clamping | The target yaw clamps to within the yaw limit of the body node's animated yaw, and the target pitch to the up and down limits. |
| Easing | The eased yaw and pitch start at the clamped target. Each step, they move the fraction 1 − e^(−response × delta) of the way to it, yaw along the shorter way around. Without a response, they equal the clamped target. |
| Turn | The chain turns by the eased yaw minus the end node's animated yaw, and by the eased pitch. |
| Distribution | Each node, from base to end, turns by its share of both angles about the object-space axes after its animated object-space rotation. Its descendants turn with it. |
| Release | The chain stops turning at once. The next target starts the easing over. |
| Root motion | The look chain never changes the root motion delta. |

### Errors

| Error | Cause | Result |
| --- | --- | --- |
| `RootMotionNodeNotFound`, `DuplicateRootMotionNodeName` | The root motion node name is absent or ambiguous. | The animator is rejected. |
| `LookNodeNotFound`, `DuplicateLookNodeName` | A look chain or body node name is absent or ambiguous. | The animator is rejected. |
| `LookChainOutOfOrder` | A look chain node doesn't descend from the node before it. | The animator is rejected. |
| `InvalidLookChain` | The chain is empty, or a share, limit, or response is out of range. | The animator is rejected. |
| `StateFromDifferentGraph` | A request names a state of another graph. | The request is discarded. |

## Clip pool

The animation system owns one pool, and every animator samples clips from it.
The pool keeps packed clips in one arena sized by a byte budget that the
application chooses, and loads clips on a worker.

| Request result | Meaning |
| --- | --- |
| `Ready` | The clip is resident. |
| `Loading` | The load is queued or in flight. |
| `WaitingForCapacity` | The load queue holds 64 requests, or no room could be made. Request again later. |
| `Failed` | The load failed or the clip is larger than the whole budget. |

When a clip doesn't fit, the pool evicts the least recently used clips that the
current step hasn't pinned. A clip any animator samples is pinned for the rest
of the step and never evicted during it. Up to 64 loaded clips can wait for
room; further ones are dropped. The pool reports `LoadFailed`, `Oversized`, and
`Evicted` events, keeping the latest 64.

## Flipbooks

A flipbook selects one image of a sequence by elapsed time. It needs at least
one image and a positive frame rate. The frame index is the floor of the
elapsed time times the frame rate, wrapped to the image count, so playback
loops and a negative time wraps backward. Selection is stateless: the caller
owns the clock, and skipped updates don't slow playback. The file format is in
the [asset formats reference](/docs/reference/assets#flipbooks).

## Limits

| Limit | Value |
| --- | --- |
| Clip loads in flight, pool events kept, clips waiting for room | 64 each |
| Clips sampled per step per motion | 3 |
| Remembered blend positions | One linear and one planar per animator |
| Requests and look targets applied per step | The last of each per animator |
| Animators | No fixed limit |
| Blend space samples | At least 1 for 1D, at least 3 for 2D |
| Skeleton nodes, clips, states | No fixed limit; node indices are 32-bit |
| Engine time resolution | 28,224,000 ticks per second |
