An asset is a source file that Byte Engine bakes into one or more resources.
This page lists the formats the standard setup accepts, how their IDs and
fragments are written, and the fields of the formats you write by hand. To
write those files, follow [Author assets](/docs/use/resources/author). To add a
format or change a handler, read
[Asset processing](/docs/develop/resource-management/assets).

## Asset IDs

Asset IDs are written as resource-style paths.
Asset IDs are case-sensitive on every platform: each directory and file name in an ID must match the file's spelling
exactly. On a case-insensitive file system, such as the default ones on macOS and Windows, an ID that differs from a
file only in case still names no file, so it fails to read and counts as missing.
The file extension is part of the ID when selecting an asset handler, and a fragment can identify a sub-asset when a container format exposes many resources.
For example, a glTF asset can produce mesh, skeleton, animation, material, image, and generated shader resources.

## Excluded assets

The `assets.exclude` [parameter](/docs/reference/parameters#application)
is an array of glob patterns. An asset whose ID matches a pattern is never
baked, by BELD or by a development build of the application.

| Rule | Effect |
| --- | --- |
| Match | A pattern matches the whole ID requested for a bake, ignoring case: `*` matches any run of characters, including `/` and `#`, and `?` matches one character. A source file's ID is its path below the source directory, so `textures/wip/*` matches every file under `textures/wip`. |
| Discovery | A full bake skips every discovered asset that matches. An asset that also matches a [root](/docs/api/beld#roots) pattern stops the bake before anything bakes. |
| Requested ID | A bake request for a matching ID fails with an error that names the asset as excluded, whether BELD, an application, or another asset made it, and even when the store already has a resource for the ID. |
| Dependency | An asset that needs an excluded asset fails to bake, with the same error for the excluded asset. |
| Stored resources | Excluding an asset doesn't remove a resource baked before. A release build, which never bakes, still loads it. |
| No patterns | Without `assets.exclude`, or with an empty array, nothing is excluded. |

## Source formats

The standard graphics setup bakes these formats:

- PNG, JPEG, and EXR images
- `.environment.bead` environment maps
- `.motion.bead` motion databases of skeletal animation clips
- glTF and GLB meshes, embedded images, skeletons, and skeletal animation clips
- FBX meshes, skeletons, and skeletal animation clips
- `.bema` materials and variants
- `.bemx` material graphs, which `.bema` materials name
- `.pipeline` GPU pipeline descriptions
- `.fusion` lists of pixel step pipelines that bake into one fused pipeline
- `.flipbook` image sequences with a playback rate
- `.particles` [GPU particle systems](/docs/reference/particles), which bake into generated shaders and pipelines
- LUT assets
- TrueType and OpenType fonts
- WAV and OGG audio
- standalone `.besl` shaders with `.besl.bead` stage metadata

## JSON5

Byte Engine expects JSON5 wherever an asset format or sidecar uses JSON. Write
comments and trailing commas in `.bead`, `.bema`, `.bemx`, and JSON glTF asset files.
JSON5 also supports unquoted object keys, single-quoted strings, and other
authoring conveniences.

Use ordinary JSON when you need compatibility with a tool that doesn't support
JSON5. Otherwise, use comments to explain non-obvious asset settings and keep
trailing commas so later edits produce smaller diffs. Read the
[JSON5 specification](https://spec.json5.org/) for the complete syntax.

## Flipbooks

A `.flipbook` file is a JSON5 object with these fields:

| Field | Value |
| --- | --- |
| `frames_per_second` | The playback rate. |
| `images` | The image asset IDs, in playback order. |

Baking a flipbook bakes its images and produces a `Flipbook` resource whose
images are in playback order.

## Detail levels

Mesh processing simplifies every rigid primitive into coarser detail levels,
each with about half the triangles of the one before, until a level stops
getting smaller, fits in about two meshlets, or reaches the level limit. Every
level uses the primitive's own vertices. Each level records an error: the
estimated largest distance, in model units, between it and full detail. The
renderer draws the coarsest level whose error covers at most a pixel, and
keeps only the levels that some instance needs; the
[detail level rules](/docs/reference/rendering#the-visibility-pipeline) define
which. Skinned primitives keep full detail only.

A level holds at most 4,096 meshlets of 64 vertices and 124 triangles. A primitive that needs more for any level fails to bake. That happens when its triangles share few vertices, so each meshlet runs out of vertices first.

A model's BEAD file tunes its levels with a `lods` object:

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | `false` keeps full detail only. |
| `max_levels` | `8` | Levels per primitive, counting full detail, from 1 to 8. |
| `max_error` | `0.25` | The largest error of a level, as a fraction of the primitive's largest extent. |
| `lock_borders` | `false` | `true` keeps open borders in place. |
| `authored` | None | A pattern that names the files holding an FBX model's own coarser levels; see [Authored detail levels](#authored-detail-levels). glTF and GLB models that set it fail to bake. |

Every key is optional. Set `lock_borders` to `true` when a model's primitives meet along a border, as when one surface is split by material, and gaps show between them at a distance. Each primitive is simplified on its own, so neighbors at different levels can otherwise pull apart by up to the sum of their errors. Locked borders simplify less.

### Authored detail levels

An FBX model can use coarser levels modeled by hand, stored in files next to it, such as `fern_LOD1.fbx` and
`fern_LOD2.fbx` for `fern_LOD0.fbx`. Its `lods.authored` pattern names them, so one directory `.bead` file covers
every model below it.

| Rule | Value |
| --- | --- |
| Pattern | Text with placeholders, such as `{name}_LOD{level}`. `{level}` is a decimal number and appears exactly once. Every other placeholder, `{` and a name of letters, digits, and underscores, then `}`, matches any text that isn't empty. Two placeholders can't touch. |
| Match | The pattern must match the model's file name without its extension. A model whose name doesn't match has no authored levels. |
| Level files | The model's directory and extension, with the pattern's placeholders as the model's name filled them and each level number above the model's in turn. A number keeps the model's zero padding, so `LOD01` is followed by `LOD02`. |
| Chain end | The first level file that doesn't exist, or that holds other than one mesh instance or other vertex streams than the model. A model that holds other than one mesh instance uses none. Adding a missing file later rebakes the model. |
| Other materials | A level file whose material names differ from those of the level before it, as a billboard's do, starts primitives of its own: one for each of its materials, bound like the model's materials by name. Later level files with those names are their coarser levels. These primitives take over from every primitive of the levels before them. |
| Takeover | The primitives that take over are drawn only where their error is within what the renderer allows, and the primitives they replace only where it isn't, so one set shows at a time. Their error is the level file's, measured against the model at full detail and at least the error of the last level before it. Every level of the new primitives adds it to its own. All the primitives on both sides share one bounding sphere, around all of them. |
| Count | At most `max_levels` level files, counting the model. Each primitive holds at most `max_levels` levels: authored levels take their places first, and gap levels and coarser levels take what's left. |
| Primitive | Each material's triangles in a level file become that level of the primitive with the same material, and its vertices are added to the primitive's. A level whose vertices don't fit in the 65,536 a primitive holds, a material that doesn't fit in one primitive at full detail, a skinned model, and a bake with lightmap UVs fall back to simplified levels, with a warning in the model's trace. |
| Error | Measured against full detail: the farthest a vertex of either lies from the other's triangles. A level's error is at least the error of the level before it. |
| Gap levels | Before each authored level, while `max_levels` leaves a level for it and every authored level after it, levels simplified from the level before it as [Detail levels](#detail-levels) specifies, each with that level's error added to its own. A gap level is kept while its error is less than the authored level's and the authored level has at most 75% of its triangles; the first that isn't ends the gap. |
| Coarser levels | Simplified from the last authored level as [Detail levels](#detail-levels) specifies, each with that level's error added to its own. |
| Baking | The level files are read as sources of the model and don't need to be baked themselves, so [excluded assets](#excluded-assets) can hold them. |

## Lightmap UVs

When the bake builds lightmaps in, with `render.baked-gi.enabled` set to `true`,
mesh processing gives every unskinned primitive of a glTF, GLB, or FBX model a
second set of texture coordinates, the `Vertex.LightmapUV` stream, in which no
two triangles overlap. A [lightmap](#lightmaps) stores light at these
coordinates. A bake without lightmaps leaves the stream out.

| Term | Definition |
| --- | --- |
| Chart | A largest set of triangles connected through shared edges, where an edge is shared when its two end positions are equal, whose normals have the same dominant axis: the axis of the normal's largest component, with its sign. A triangle without area joins the chart of its first neighbor, or forms a chart of its own. |
| Projection | Each chart projects along its dominant axis onto the plane of the other two, in model units, so every chart of a primitive keeps the same scale. |
| Square | The charts are placed in rows inside one square, tallest chart first, then scaled so the square spans 0 through 1 on both axes. |
| Gap | Charts lie at least two texels apart, and at least one texel from the square's edges, at the BEAD file's `resolution` texels per side. A primitive with more charts than that leaves room for keeps smaller gaps, and the bake warns. |
| Overlap | Triangles of different charts never overlap. Triangles of one chart can, where the surface folds back over itself along the chart's axis, as a spiral does. |

| Rule | Value |
| --- | --- |
| Vertices | A vertex shared by two charts splits into one vertex per chart. Every other stream of a split vertex keeps its value. |
| Detail levels | Every level indexes the same vertices, so each level's triangles keep the coordinates they had at full detail. |
| Vertex limit | A primitive holds at most 65,536 vertices after the splits, or its bake fails. |
| Skinned primitives | Have no `Vertex.LightmapUV` stream. |

A model's BEAD file tunes the stream with a `lightmap_uvs` object:

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | `false` leaves the stream out, so lightmaps skip the model. |
| `resolution` | `64` | The texels per side the gap between charts is measured at, from 16 through 4,096. Set it near the texels a lightmap gives the primitive. |

## Standalone images

A standalone image file bakes into one image resource. The file's extension
selects its decoder:

| Extension | Accepted samples | Gamma |
| --- | --- | --- |
| `.png` | Grayscale, grayscale with alpha, RGB, or RGBA at 8 or 16 bits; palette and lower bit depths expand to 8 bits | The texture's role, unless the role is sRGB and the file's color metadata names linear or sRGB |
| `.jpg`, `.jpeg` | 8-bit grayscale or color; color is stored as RGB | The texture's role |

The texture's role follows the [texture conventions](/docs/reference/conventions#color):
albedo is sRGB, and data textures, such as normal and roughness maps, are
linear. A file that a decoder can't read fails the bake. The
[image settings](#image-settings) apply the same way to every format.

## Image settings

An image's semantic says what its texels mean. It sets the image's color space
and its default settings. A glTF or GLB model assigns each image the semantic
of the material input that samples it, and falls back to the image's file name
when no input does. A standalone image, and an image a model only names, gets
its semantic from its file name.

### Semantics from file names

The file name without its extension splits into words at every character that
isn't a letter or a digit, and the last words are compared with each row below
in order, ignoring case. The first row whose words end the name gives the
semantic, so `rock_4K_BaseColor.jpg`, `rock_4K_Basecolor.jpg`, and
`rock_Base_Color.png` are all albedo maps. Words in the middle of a name, and
words joined to other letters, as in `NormalityChecker.png`, don't count. A
name that matches no row is `other`.

| Last words | Semantic |
| --- | --- |
| `base color`, `basecolor`, `albedo`, `diffuse` | albedo |
| `normal` | normal |
| `metallic` | metallic |
| `roughness` | roughness |
| `gloss` | gloss |
| `specular` | specular |
| `emissive` | emissive |
| `height`, `bump` | height |
| `displacement` | displacement |
| `opacity` | opacity |
| `ao` | ambient occlusion |
| `cavity` | cavity |
| `translucency` | translucency |
| `fuzz`, `sheen` | sheen |

### Semantic defaults

| Semantic | Holds | Color space | Compressed by default |
| --- | --- | --- | --- |
| albedo | Surface color | sRGB | BC7 |
| emissive | Emitted color | sRGB | BC7 |
| specular | Specular reflectance color | sRGB | BC7 |
| translucency | Color of light passing through the surface | sRGB | BC7 |
| sheen | Color of the fuzz layer on cloth and foliage | sRGB | BC7 |
| normal | Tangent-space normal | Linear | BC5 |
| metallic | Metalness | Linear | BC7 |
| roughness | Roughness | Linear | BC7 |
| gloss | Glossiness: one minus roughness | Linear | BC7 |
| ambient occlusion | Light that reaches the surface | Linear | BC7 |
| cavity | Small-scale occlusion in creases | Linear | BC7 |
| opacity | Coverage | Linear | BC7 |
| height | Height of the surface | Linear | No |
| displacement | Offset of the surface | Linear | No |
| metallic-roughness | glTF metalness in blue and roughness in green | Linear | No, packed into two channels |
| other | Unknown, such as UI art | sRGB | No |

Height and displacement maps stay uncompressed because they move geometry or
shading, where block-compression error shows as visible steps. An `other` image
keeps its exact colors. A gloss map holds the inverse of a roughness map; a
material that samples it computes roughness as one minus the sampled value.

### Settings

Every image gets a full mip chain by default, and the semantics above choose
whether it's block-compressed: normal maps to BC5, other compressed images to
BC7. An image's BEAD file can change either step with an object of these keys:

| Key | Default | Meaning |
| --- | --- | --- |
| `mips` | `true` | `false` stores only the authored size, with no smaller levels. |
| `compression` | From the image's semantic | Whether the image is block-compressed. |
| `coverage` | `0.5` for opacity maps, `false` for other images | The alpha cutoff, from 0 to 1, whose coverage every smaller level keeps, as [coverage](#coverage) defines; `false` averages the levels without scaling them. |
| `cpu_readable` | `false` | `true` keeps the stored texels readable by the application. A resource store that encodes images for GPU-only reading, such as one with Metal I/O compression, stores this image without that encoding. |

Every key is optional, and a key left out keeps its default. Packed
metallic-roughness maps and half-float images, such as EXR, are never
block-compressed, so `compression` has no effect on them. A standalone PNG,
JPEG, or EXR reads the object from its `image` key, in a sidecar named after the
whole file name, such as `rock_albedo.jpg.bead`. A glTF, GLB, or FBX model reads it
from its `images` key and applies it to every image the model contains.

Turn `mips` off for images drawn at their authored size, such as UI art, and
`compression` off for images whose exact colors matter more than their memory. Turn `cpu_readable` on for images the application reads
itself, such as UI art it crops or tints.

### Coverage

An alpha-tested material keeps a texel where its opacity is at or above the
material's `alpha_cutoff`. A level's coverage is the share of its texels whose
opacity channel, as stored, is at or above the image's `coverage` cutoff. An
opacity map holds opacity in its first channel; any other image holds it in its
alpha channel.

With a cutoff, each level below the authored size multiplies its opacity
channel by one factor, chosen so the level's coverage comes as close as its
texels allow to the authored size's coverage. A texel that reaches the cutoff
before the factor applies reaches it after, and one that doesn't, doesn't.
Results above 1 store 1. The other channels, and the authored size, keep their
values.

| Case | Result |
| --- | --- |
| Cutoff of 0 | Every texel passes; the levels keep their values. |
| Authored size with no passing texel | No level has a passing texel. |
| Texel of opacity 0 | It never passes, whatever the factor. |
| Half-float image, such as EXR | The levels keep their values. |
| `mips` set to `false` | No smaller levels exist, so the cutoff has no effect. |

The cutoff matches a material's only when it equals that material's
`alpha_cutoff`.

## Environment maps

A standalone `.environment.bead` file generates image-based lighting from a
high-precision source image. It's a JSON5 object with these fields:

| Field | Value |
| --- | --- |
| `$schema` | Optional. `byte_engine/schemas/environment.bead.schema.json`, for editor completion. |
| `source` | The ID of the source image, relative to the application's `assets/` directory. The image doesn't need to be a supported standalone image asset. |

Use a full-sphere, 2:1 latitude-longitude image with at least 16-bit integer or
floating-point precision. The environment decoder accepts EXR, Radiance HDR,
16-bit PNG, high-precision TIFF and PNM, and farbfeld sources. It rejects 8-bit
images so quantization doesn't become baked lighting or reflections. The
decoder converts supported nonlinear source metadata to linear light before it
generates the lighting maps. Author TIFF and PNM sources in linear light because
their decoders don't expose reliable transfer metadata. Untagged PNG and
farbfeld sources are interpreted as sRGB.

Baking the environment asset retains the source image and adds a diffuse
irradiance cubemap and eight roughness-prefiltered specular levels. The
visibility renderer loads the complete set when the asset is selected as the
world environment.

## Lightmaps

A standalone `.lightmap.bead` file bakes the indirect diffuse light of a
[level](/docs/reference/levels) into one image, by path tracing its meshes and
lights on the GPU. It's a JSON5 object with these fields:

| Field | Default | Value |
| --- | --- | --- |
| `$schema` | None | `byte_engine/schemas/lightmap.bead.schema.json`, for editor completion. |
| `level` | Required | The ID of the `.level` asset whose meshes and lights the lightmap holds. |
| `environment` | None | The ID of an [environment map](#environment-maps) whose sky lights the paths that leave the scene. Without it, they bring back no light. |
| `illuminance` | None | Lux, finite and zero or more. Scales the environment to deliver it to an upward-facing surface, as the world environment's illuminance does. Without it, the map's own values are used. |
| `texel_density` | `8` | Texels per meter of surface, finite and positive. |
| `samples` | `256` | Paths traced from each texel, from 1 through 65,536. |
| `bounces` | `3` | The most surfaces a path hits, from 1 through 16. |
| `max_extent` | `2048` | The image's largest side in texels: a power of two from 256 through 8,192. |

Baking the lightmap bakes the level, then every mesh, material, image, and
environment the level and the lightmap name, and reads those resources, so it
holds the meshes the renderer draws. A change to any of them bakes the lightmap
again. It produces a `Lightmap` resource and its image, `<id>#image`. Baking
needs a GPU that traces rays, and fails without one.

| Rule | Value |
| --- | --- |
| Holder | The level names the lightmap's ID in the `lightmap` kind of exactly one entity, or the bake fails. |
| Primitives | Every primitive of every `mesh` entity that has a `Vertex.LightmapUV` stream gets a rectangle of the image, and the rest get none. Generated meshes have the stream. Each rectangle maps the square of the primitive's [lightmap UVs](#lightmap-uvs). |
| Rectangle size | A square of side `ceil(sqrt(A / U) × texel_density)` texels, at least 16, where A is the primitive's surface area in meters after its entity's transform and U is the area its triangles cover in the lightmap UV square. |
| Placement | Rectangles lie in rows, largest first, two texels apart and one texel from the image's edges. The image is the smallest square of power-of-two side that holds them. When they don't fit in `max_extent` texels, every side shrinks by the same factor until they do, and the bake warns. |
| Texels | A texel holds light when a triangle covers its center: at that point. A texel that a triangle crosses and none covers at its center holds light at the triangle's point nearest its center. |
| Paths | Each path leaves the texel's point from a quarter of a texel's width above the triangle, along its face's normal, and ends after `bounces` hits, when it misses, or when it hits a back face. Its first direction follows the texel's guide, and every later one is cosine weighted around the hit's normal. From its second hit, a path continues with a probability of its albedo's largest channel, and a path that continues divides its light by that probability. |
| Guide groups | Texels share a guide when they lie in the same cube of world space four texels wide at the image's density, their normals' largest components lie along the same axis with the same sign, and their normals lie within about 25 degrees of the group's first texel's. A group holds at most 32 texels. |
| Guides | A texel's first `floor(samples / 8)` paths leave in cosine-weighted directions. Their light, as luminance, sums into the guide of the texel's group over 8 × 8 equal cells of the square that cosine-weighted directions map from. Each cell then takes the mean of its sum and those of the cells around it among its 8 neighbors. The guide's density is a quarter spread evenly over the square, plus three quarters spread in proportion to those means, or evenly when they're all zero. The texel's later paths leave in the directions the density picks. |
| Guided light | A path whose first direction follows a guide divides its light by the guide's density at that direction, relative to the even density, so every path's light estimates the same irradiance. |
| Hit surfaces | As for [surfel GI](/docs/reference/rendering#surfel-gi): a path hits each mesh's opaque primitives at full detail, and the hit's material reports its albedo and emission through its closest-hit shader. A material without one reports black. |
| Path light | A miss brings back the environment's light from its direction, times the environment's scale. A front-face hit brings back its emission, plus its albedo times the light of each sun that it faces and that no geometry hides, and of each point and cone light it faces, within the light's reach, that no geometry hides, lit as material evaluation lights a surface but without the light's IES profile. Each hit multiplies the light of the hits after it by its albedo. |
| Stored light | Each texel stores the mean of its paths' light: irradiance over π, in nits, in RGB, and in alpha the cosine-weighted share of its directions whose first ray reaches the environment, estimated from its paths as their light is, all as half floats. The texel's own direct light from the scene's lights isn't in it; the renderer draws that. |
| Back faces | A texel where more than a tenth of its directions, estimated as for the stored alpha, first hit a back face holds no light. |
| Dilation | Eight passes in turn give each texel that holds no light the mean of the texels around it that do, among its 8 neighbors, alpha included. A texel still without light after them is black, with alpha zero. |

## Motion databases

A standalone `.motion.bead` file builds a
[motion database](/docs/reference/animation#motion-databases), which
[matched states](/docs/reference/animation#matched-states) search. It's a JSON5
object with these fields:

| Field | Default | Value |
| --- | --- | --- |
| `$schema` | None | `byte_engine/schemas/motion.bead.schema.json`, for editor completion. |
| `clips` | Required | An array of clip asset IDs and patterns, with at least one entry. |
| `loops` | `[]` | An array of clip asset IDs and patterns naming the clips of `clips` that loop. |
| `root` | Required | The [ground root settings](#ground-root-settings). |
| `sample_rate` | `30` | The frames per second the database samples its clips at. Finite and positive. |
| `nodes` | `{}` | The [node feature weights](#node-feature-weights), by node name. |
| `trajectory` | Every key's default | The [trajectory settings](#trajectory-settings). |
| `search` | Every key's default | The [search settings](#search-settings). |
| `halflife` | Every key's default | The [halflife settings](#halflife-settings). |

The `clips` entries name the database's clips:

| Entry | Names |
| --- | --- |
| ID | An entry without `*` or `?` names one clip by asset ID, fragment included, as in `character.fbx#animations/Walk`. |
| Pattern | An entry with `*` or `?` matches the IDs of source files, with the syntax of [excluded assets](#excluded-assets). Each match names the file's default resource, which must be an animation clip. Matches follow one another in ascending ID order. |
| Order | Clips follow the order of their entries. A clip that several entries name keeps the place of the first. |
| Later sources | A pattern matches the sources there are when the database bakes. A matching source added later joins the database the next time the database bakes. |

A `loops` entry names the database's clips whose asset IDs it equals, as an ID,
or matches, as a pattern of the same syntax. A clip that a `loops` entry names
[loops](/docs/reference/animation#frames) in the database.

### Ground root settings

| Key | Default | Meaning |
| --- | --- | --- |
| `node` | Required | The name of the node the ground root projects, usually the hips. |
| `facing` | The `node` | The name of the node whose yaw the ground root faces. Name a node that faces where the body faces, like the head, when the root node twists toward the travel, as the hips do in many strafes. |
| `position_smoothing` | `0.1` | The standard deviation, in seconds, of the Gaussian that smooths the ground root's position. Zero leaves it as sampled. |
| `facing_smoothing` | `0.25` | The standard deviation, in seconds, of the Gaussian that smooths the ground root's yaw. Zero leaves it as sampled. |

### Node feature weights

Each key of `nodes` is a node name, and its value is an object of these keys:

| Key | Default | Meaning |
| --- | --- | --- |
| `position` | `0` | The weight of the node's position feature. |
| `velocity` | `0` | The weight of the node's velocity feature. |

### Trajectory settings

| Key | Default | Meaning |
| --- | --- | --- |
| `times` | `[0.333, 0.667, 1.0]` | The times ahead of a frame, in seconds, that the trajectory features sample. Finite, positive, and strictly ascending, with at least one. |
| `position` | `1` | The weight of the trajectory position feature. |
| `direction` | `1.5` | The weight of the trajectory direction feature. |

### Search settings

| Key | Default | Meaning |
| --- | --- | --- |
| `interval` | `0.1` | Seconds between searches while a matched state plays. Finite and positive. |
| `exclusion` | `0.333` | Seconds from the playing time within which frames of the playing clip aren't candidates. Finite and zero or more. |
| `blend` | `0.2` | Seconds a switch to a found frame inertializes over. Finite and zero or more. |

### Halflife settings

| Key | Default | Meaning |
| --- | --- | --- |
| `velocity` | `0.27` | The halflife, in seconds, of the spring that moves the predicted velocity toward the requested one and predicts the trajectory's position from it. Finite and positive. |
| `facing` | `0.27` | The halflife, in seconds, of the spring that predicts the trajectory's direction. Finite and positive. |

Every weight is finite and zero or more. Every key is optional unless the
tables say it's required, and any other key fails the bake. The bake also fails
when:

- `clips` is empty, an entry matches nothing, or an entry names a resource that
  isn't an animation clip.
- A `loops` entry names none of the database's clips.
- The root node, the facing node, or a node of `nodes` is missing from a clip's
  skeleton, or appears in it more than once.
- A node of `nodes` has no positive weight.
- The features have no dimensions, or more than 64.
- No frame is pickable.

Baking a motion database bakes every clip it names and produces a
`MotionDatabase` resource that names them in order.

## Sidecars

A sidecar is a JSON5 file named after the asset with `.bead` appended, next
to it. A missing sidecar means defaults; one that can't be read fails the
bake.

A file named `.bead` in a directory holds directory defaults: sidecar keys for
every asset in that directory and the directories below it. An asset's settings
are the `.bead` files from the asset root down to its own directory, then its
sidecar, each merged over the ones before it. Objects merge key by key, and any
other value replaces the one before it. A directory default that can't be read
fails the bake of every asset that reads sidecars below it. Directory defaults
don't make an asset discoverable the way an adjacent `.besl.bead` does.

Only these handlers read sidecars:

| Asset | Key | Value |
| --- | --- | --- |
| glTF, GLB, FBX | `default_resource` | `mesh` or `animation`, which the bare ID bakes as. Skeletons always need the `#skeleton` fragment. |
| glTF, GLB, FBX | `lods` | The detail level settings listed under [Detail levels](#detail-levels). Unknown keys fail the bake. |
| glTF, GLB, FBX | `images` | The [image settings](#image-settings) for every image the model contains. Unknown keys fail the bake. |
| PNG, JPEG, EXR | `image` | The [image settings](#image-settings) for the image. Unknown keys fail the bake. |
| glTF, GLB, FBX | `asset.<material name>` | The variant to use for that material: an authored `.bema` variant or one written in the sidecar, as listed under [Material bindings](#material-bindings). |
| FBX | `skeleton` | The ID of the skeleton to bake against, instead of the file's own. |
| BESL | `stage`, `tile`, `workgroup`, `maximum_mesh_threadgroups`, `maximum_vertices`, `maximum_primitives` | The stage metadata specified in the [BESL interface](/docs/reference/besl/interface#standalone-stage-metadata). The sidecar is required. |

### Material bindings

`asset` in a glTF, GLB, or FBX model's settings binds the model's materials to
variants. It's read after the directory defaults and the sidecar merge, so a
directory `.bead` can bind every model below it. A sidecar's entry merges field
by field over its directory's entry of the same key. A `null` key, field, or
variable counts as left out, which lets a deeper file drop one it inherits,
such as `select`.

| Key | Binds |
| --- | --- |
| The material's name | That material. Unnamed FBX materials use the name `default`. |
| `"*"` | Every material of the model without a key of its own, unnamed glTF and FBX materials included. A named key is used on its own, never merged with `"*"`. |

A material without a key, and without `"*"`, is generated from the model. A
binding is either `{ asset }`, the ID of an authored `.bema` variant that bakes
as a dependency, or an inline variant with these fields. With `asset` present,
every other field is ignored.

| Field | Value |
| --- | --- |
| `parent` | The parent material's asset ID, a [template](#binding-templates). Required without `select`, and ignored with it. |
| `select` | A non-empty array of rules `{ requires, parent, alpha_mode, alpha_cutoff, double_sided }`. `requires` is an optional array of variable names, and `parent` is a template. |
| `variables` | Optional. An object keyed by the parent's parameter names, whose values are templates, arrays of templates, numbers, or arrays of numbers. |
| `alpha_mode`, `alpha_cutoff`, `double_sided` | Optional, with the values a [`.bema` variant](/docs/reference/bema#variant-files) accepts. A field left out keeps the parent's value. |

#### Binding templates

`parent`, `select[].parent`, and every string in `variables` are level 1
templates of the URI Template standard, Request for Comments (RFC) 6570: each
`{name}` is replaced by the variable's value, unchanged and without URI
escaping. Only these variables exist:

| Variable | Value |
| --- | --- |
| `{dir}` | The name of the directory that holds the model, such as `xb5ebhf`; empty for a model at the asset root. |
| `{stem}` | The model's file name without its last extension, such as `xb5ebhf_LOD0`. |
| `{material}` | The material's name; `default` for an unnamed FBX material, and `material_<index>` or `material_default` for an unnamed glTF material. |

After expansion, a value that starts with `./` is relative to the model's
directory. Any other value is an asset ID from the asset root.

#### Resolution

1. Each variable resolves. A number or an array of numbers resolves to itself.
   A template, or an array of templates, resolves to the first whose source
   asset exists. When none exists, the variable is unresolved, which isn't an
   error.
2. Without `select`, the parent is `parent`. With it, the parent comes from the
   first rule whose `requires` variables all resolved; a rule without
   `requires` always matches. The rule's coverage fields replace the block's,
   field by field.
3. Each of the parent's parameters takes its variable's value. A parameter
   whose variable is unresolved or absent keeps the parent's value, static or
   dynamic. Variables the parent doesn't declare are ignored.
4. Values resolve with the parent parameter's `data_type`, as in a variant
   file. A string is always an asset ID, never a named color: it bakes as an
   image for a `Texture2D` parameter, so write colors as arrays of numbers.

The bake fails when:

- A binding or a rule isn't an object, or has a field not listed here.
- A template has an unknown variable, an operator such as `{+dir}`, or an
  unmatched `{` or `}`.
- A `variables` value mixes strings and numbers.
- No `select` rule matches.
- A resolved asset ID is given to a parameter that isn't `Texture2D`.

An inline variant is stored as the model's resource
`<model ID>#materials/<material>.variant`, with `<material>` named as under
[Container fragments](#container-fragments). It refers to its parent `Material`,
which every model that names that parent shares. The model's bake depends on
every candidate it checked: on each file it chose, and on the absence of each
earlier candidate, so creating one rebakes the model.

Every hand-written format has a JSON schema under the engine's
`assets/schemas` directory: `bema.schema.json`, `bemx.schema.json`, `besl.bead.schema.json`,
`environment.bead.schema.json`, `fusion.schema.json`, `image.bead.schema.json` for the image
sidecar, `model.bead.schema.json` for the model sidecar, `motion.bead.schema.json`, and
`particles.schema.json`.

## Pipelines

A `.pipeline` file is strict JSON describing one GPU pipeline. Its `name` is
free text and its `type` selects the fields:

| `type` | Fields | Defaults |
| --- | --- | --- |
| `compute` | `shader`, the shader's asset ID; `push_constants`, a list of ranges with `offset` and `size`. | No push constants. |
| `raster` | `shaders`, a list of shader IDs; `push_constants`; `vertex_elements`, each with `name`, `format`, and `binding`; `attachments`, each with `format`, an optional `layer`, and `blend`; `face_winding`; `cull_mode`; `fill_mode`; `depth_write`. | `clockwise`, `back`, `solid`, and depth writes on. |
| `tile` | `shader`, the ID of a `Tile` stage shader; `push_constants`. | No push constants. |

| Field | Values |
| --- | --- |
| Vertex and attachment `format` | `float`, `float2`, `float3`, `float4`, `u16`, `u32`, `rgba8_unorm`, `rgba16_unorm`, `rgba16_float`, `rg11b10_float`, `depth16`, `depth32` |
| `blend` | `none`, `alpha`, `premultiplied` |
| `face_winding` | `clockwise`, `counter_clockwise` |
| `cull_mode` | `none`, `front`, `back` |
| `fill_mode` | `solid`, `wireframe` |

Baking a pipeline bakes each named shader. A `.pipeline` file can't have the
`fused` type, which only a [fusion](#fusions) bakes.

## Fusions

A `.fusion` file is strict JSON that names pixel step pipelines to run as one
pass. The renderer finds fusions in the resource store and uses each one for
the runs of steps it matches; see
[pixel steps and fusion](/docs/reference/rendering#pixel-steps-and-fusion).

```json
{
	"name": "Correction and ACES 2.0 Grading",
	"steps": [
		"byte_engine/rendering/color-correction/correct.pipeline",
		"byte_engine/rendering/color-grading/aces2.pipeline"
	]
}
```

| Field | Value |
| --- | --- |
| `name` | Free text. |
| `steps` | Two to eight `.pipeline` asset IDs, in the order the steps run. |
| `$schema` | Optional, ignored by baking. |

A fusion fails to bake when:

- `steps` has fewer than two or more than eight entries.
- A step isn't a `tile` pipeline, or its shader isn't a
  [pixel shader](/docs/reference/besl/interface#pixel-shaders).
- The steps' shaders don't share one `tile` size and `workgroup`.
- Two steps' layers declare a descriptor of the same name, as two steps that
  take the same layer do.
- Two steps' shaders declare the same name, other than their `pixel`
  functions and the modules from the asset root they share.
- The fused shader binds more than four descriptor sets: one for each step
  that takes a layer, one for the incoming color, and, where tile shaders run
  as compute shaders, one for the output.

Baking a fusion bakes each step pipeline, then stores the fused shader as
`<fusion ID>#shader` and a `Pipeline` resource of kind `fused` at the fusion's
ID. The fused pipeline has one 4-byte push constant, whose bit *i* is set when
step *i* runs this frame.

## Color lookup tables

A `.lut` or `.cube` file is a text table with `TITLE`, `LUT_1D_SIZE` or
`LUT_3D_SIZE`, optional `DOMAIN_MIN` and `DOMAIN_MAX`, and comments starting
with `#`. It bakes to a one- or three-dimensional LUT whose entry count is the
size or the size cubed.

## Fonts

A `.ttf` or `.otf` file bakes into one `Font` resource whose payload is the
file's bytes, unchanged. A file that doesn't parse as a TrueType or OpenType
font fails the bake. A font collection, such as a `.ttc` file, isn't accepted.

## Container fragments

A glTF, GLB, or FBX file is a container: one source file that bakes into several resources. The fragment after `#`
in a resource ID names which one. The same fragments work in debug baking and in BELD.

| Fragment | glTF and GLB | FBX | Resource |
| --- | --- | --- | --- |
| None | `character.glb` | `character.fbx` | The container's default resource, described under [Skeletal models](#skeletal-models). |
| `skeleton` | Yes | Yes | The transform hierarchy. |
| `animation` | Yes | Yes | The first animation clip. |
| `animations/<index>` | Yes | Yes | The clip at that zero-based index. |
| `animations/<name>` | Yes | Yes | The clip with that exact name. |
| `images/<index>` | Yes | No | The image at that zero-based index. |
| `images/<texture id>` | No | Yes | The texture with that ID. |
| `materials/<material>.variant` | Yes | Yes | One generated material's variant, its material, its shaders, and the images it samples, without the mesh. |
| `materials/<material>.material` | Yes | Yes | The same bake, requested by its material. |

`<material>` is the name the container's mesh gives its generated material:

| Container | `<material>` |
| --- | --- |
| glTF and GLB | The material's sanitized name, with each character other than a letter, digit, `_`, or `-` replaced by `_`; `material_<index>` for an unnamed material; `material_default` for primitives without one. |
| FBX | `<index>_<sanitized name>`, where `<index>` is the material's index in the file; `<index>_material` for an unnamed material; `default_material` for polygons without one. |

A material that a sidecar binds to an inline variant keeps its `materials/<material>.variant` ID, which then bakes the inline variant. A material bound to an authored `.bema` variant with `{ asset }` has no `materials/` resource; bake the variant's own ID.
A `materials/` fragment that matches no generated material fails to bake.

## Skeletal models

glTF, GLB, and FBX use one import-neutral skeletal representation.
A `Skeleton` stores transform nodes in parent-before-child order and preserves each node's rest-local translation, rotation, and scale.
An `Animation` stores sparse translation, rotation, and scale curves against those dense node indices and references the skeleton it was authored for.
Missing curves deliberately fall back to the skeleton's rest pose, which gives
CPU animation sampling and blending a stable pose.

A mesh with skins or node animation references the same skeleton, and each primitive retains its dense transform-node index.
This lets an animation graph apply rigid node motion without reconstructing
source-file node ownership.
Skinned meshes additionally store one skin binding per imported mesh instance.
Each binding maps the palette-local indices in the `Vertex.Joints` stream to skeleton nodes and pairs them with adjusted inverse-bind matrices.
The adjusted matrices account for the bind-pose transform already flattened into imported vertices, so a CPU-generated global pose can write a GPU palette as `global_joint * adjusted_inverse_bind` without reopening the source file.
Rigid primitives have no skin binding, and mixed rigid/skinned source files retain primitive-local joint and weight stream offsets.
FBX vertices without authored cluster weights use a mesh-node fallback palette entry, so they continue following animated mesh ancestors instead of freezing in bind space.

Each clip and the skeleton is its own resource, named by a [container fragment](#container-fragments).

Without a fragment, FBX and glTF containers use a content-only default that's identical in debug baking and BELD:

- A container with any mesh bakes as `Mesh`.
- A container without meshes and with exactly one animation bakes as `Animation` and stores its dependency as `#skeleton`.
- Containers with neither an uncontested mesh nor a single animation require an explicit fragment.

A sibling BEAD manifest can override the first two choices with `"default_resource": "mesh"` or
`"default_resource": "animation"`. An animation override still requires exactly one clip. Skeleton resources never
become the unfragmented default and must always be requested through `#skeleton`.

The importers normalize weights to a fixed four-influence vertex format.
FBX matrix-linear and rigid skins are supported. Files that require multiple layered skin deformers or dual-quaternion skinning are rejected instead of being approximated silently.
glTF morph-weight channels aren't part of the skeletal clip representation and a selected clip containing them is rejected explicitly.
Animated rigid or skinned mesh nodes must have an invertible bind transform because their vertices are stored in flattened bind space.
The importers reject zero-scale bind transforms rather than irreversibly discarding geometry that a later animation would make visible.

The visibility renderer accepts complete global poses and uploads their derived
skin palettes. Sampling, blending, and the animation graph that produce those
poses are specified in the [animation reference](/docs/reference/animation).

## FBX

An FBX asset ID that defaults to a mesh bakes every polygon-mesh instance into one `Mesh` resource.
The importer normalizes axes and authored units, triangulates polygon faces, preserves material parts, transforms instance geometry, and emits position, normal, tangent-frame, color, UV, joint, and weight streams when the source provides them.
Meshes without authored UVs receive a zero-filled UV stream because the visibility renderer requires that stream even for untextured materials.
Polygon corners of one mesh whose position, normal, tangent, bitangent, UV, and color are exactly equal, and in a skinned mesh share a control point, become one vertex. Corners that differ in any of them, as along a UV or normal seam, stay separate vertices.

An FBX model's sidecar binds its materials to variants as [Material bindings](#material-bindings) specifies.
Without a binding, the importer generates a material variant whose [surface](/docs/reference/bemx) inputs come from the FBX material:

| Surface input | FBX value | FBX texture |
| --- | --- | --- |
| `base_color` | Base color, or diffuse color for Lambert and Phong, times the base or diffuse factor | Base color or diffuse map, red, green, and blue, multiplied with the value |
| `opacity` | Base color alpha times the opacity; without an opacity, one minus the transparency or transmission factor | Base color or diffuse map alpha, and the opacity map's red channel, both multiplied with the value |
| `metalness` | Metalness, 0 by default | Metalness map's red channel, multiplied with the value, read only for PBR shading models |
| `roughness` | Roughness, which Phong derives from shininess, 1 by default | Roughness map's red channel, multiplied with the value, read only for PBR shading models |
| `normal` | None | Normal map, tangent space, scale 1. Bump and height maps aren't read. |
| `occlusion` | None | Ambient occlusion map's red channel |
| `emission` | Emission color times the emission factor | Emission map, multiplied with the value |

Lambert and Phong materials keep no metalness or roughness maps, so their metalness and roughness are always the value.
Legacy transparent-color maps aren't read, because exporters disagree on whether white means opaque or transparent.

The material's alpha mode follows from its opacity:

| Condition | Alpha mode |
| --- | --- |
| The material has an opacity map | Masked, with a cutoff of 0.5 |
| Otherwise, opacity before textures is below 0.999 | Blended |
| Otherwise | Opaque |

A material is double-sided when its shading model marks it so.

Each texture bakes as an image named by its `#images/<index>` fragment, with the semantic of the surface input that samples it, never a semantic guessed from its file name.
Base color maps bake as albedo and emission maps as emissive, both sRGB; opacity, normal, metalness, roughness, and occlusion maps bake as their own linear semantics.
A texture that several inputs sample bakes once, with the first semantic in this order: albedo, emissive, opacity, normal, occlusion, metalness, roughness.
A texture no generated material samples bakes as albedo.

FBX animation stacks are baked through the format's pivot, layer, and rotation-order rules before becoming engine curves:

- `character.fbx#animation` selects the first animation stack.
- `character.fbx#animations/0` selects a stack by zero-based index.
- `character.fbx#animations/Walk` selects a stack by exact name.
