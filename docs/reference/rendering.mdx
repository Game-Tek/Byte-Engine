The renderer draws each window and each render image from a scene pipeline
followed by post-scene passes. This page specifies the objects an application creates, the camera,
how pipelines and passes compose, every pass the engine ships with, and the
contract of the visibility pipeline. The design notes behind it are under
[Rendering](/docs/develop/rendering) in Contribute, and the lights are in the
[lighting reference](/docs/reference/lighting).

## Objects

| Object | Role |
| --- | --- |
| Window | A named render surface with an extent, optional decorations, and optional [cursor capture](/docs/reference/input#cursor-capture), with one camera attached. Each window becomes one sink, numbered in creation order. |
| Render image | An image the renderer draws a camera into instead of a window, with an extent in pixels, showing one scene. Each render image becomes one sink, numbered with the windows in creation order. |
| Scene | What one message scope creates: the world, or a scene the application creates, such as a preview stage. Each scene has its own scene pipelines, sun, and fog. Every window shows the world. |
| Camera | View settings created on the world with a transform, which the renderer follows. |
| Sink | The per-frame destination the renderer builds from a window's or render image's extent and camera: the view, the extent, the exposure scale, the frame interval, and the player's motion preference. |
| View | Projection and view matrices with near, far, vertical field of view, and aspect ratio, perspective or orthographic. |
| Renderable mesh | An entity's geometry: a baked mesh by ID, a generated mesh, a sphere, or a box. A generated mesh may name its material; otherwise it takes the pipeline's default. |
| Environment | A baked environment map, optionally scaled to deliver a given illuminance. The newest one lights the scene. Without one, the visibility pipeline lights with the [sky environment](#sky-environment) when the atmosphere sky is installed, and with an opaque black fallback otherwise. |
| Fog, lights, particle emitters | Specified with their own pages: [Light a scene](/docs/use/lighting), [lighting](/docs/reference/lighting), [particles](/docs/reference/particles). The newest fog wins. |
| Debug mesh | A retained wireframe sphere, box, capsule, segment, or circle with a color, tested against scene depth or drawn over it. |

Scene color is linear HDR in the packed `RGBu11u11u10` format. Tone-mapping
passes write 16-bit float display color. A sink's final target, the window's
swapchain or the render image, is `BGRAu8` and stores display-encoded color as
the last pass wrote it, without encoding it again.

### Windows

| Rule | Behavior |
| --- | --- |
| Extent | The extent a window asks for is in points on macOS and in surface units on Wayland, so a 1920 × 1080 window covers 3840 × 2160 pixels at scale 2. The sink's extent is in pixels. |
| Size changes | The sink follows the window's size in pixels when the user resizes it or the display's scale changes. |
| Keyboard focus | Every window can take keyboard focus, with or without decorations. Keys go to the focused window. |
| Decorations on Wayland | A window with decorations asks the compositor to draw them. When the compositor draws none, as GNOME's doesn't, libdecor draws them, in the dark theme variant when the desktop prefers dark. Without libdecor, the window opens undecorated and one warning is logged. |
| Text on Wayland | A key press that types a printable character reports it as `Keyboard.Character`. Holding a key doesn't repeat it. |
| Render graph | A window with a camera records the passes registered for all sinks and those registered for windows, in the order they were registered, over its scene. A window without one records only the passes registered for it, in the order they were registered, over black; with none registered, it presents nothing. A window's passes must be registered before the frame after the window is created, and registering one later stops the application. |
| Closing | The main window is the first one opened. Closing it, with its close button or a `CloseWindow` message naming it, quits the application. Closing any other window closes it alone: the renderer waits for the frames in flight, destroys its swapchain, and stops rendering it, and the other windows keep rendering. A `CloseWindow` message applies before the next frame; one naming no open window does nothing. |
| Camera changes | A `SetWindowCamera` message on the application's message scope, naming the handle the window was created with and a camera, makes the window show that camera from the next frame on. It applies only to a window created with a camera; a message naming any other window, or no open window, is logged and left out. A camera that doesn't exist yet leaves the window without a scene until it does. |
| Feature changes | A `SetWindowFeatures` message on the application's message scope, naming the handle the window was created with, applies before the next frame. Only cursor capture changes on an open window; a change to another feature is logged and left out, and so is a message naming no open window. |
| Pointer changes | A `SetWindowPointer` message on the application's message scope, naming the handle the window was created with and a [pointer shape](#pointer-shapes), applies before the next frame. A message naming no open window is logged and left out. |

#### Pointer shapes

A window shows the pointer in one shape while the pointer is over its content.
Every window starts with `Default`. A window that captures the cursor hides it
whatever its shape. Each shape is one the operating system draws.

| Shape | Meaning | macOS | Windows | Linux (Wayland) |
| --- | --- | --- | --- | --- |
| `Default` | The arrow | Arrow | Arrow | `default` |
| `Hand` | A press activates what's here, such as a link | Pointing hand | Hand | `pointer` |
| `Text` | Text to select or edit | I-beam | I-beam | `text` |
| `Grab` | Something to drag | Open hand | Hand | `grab` |
| `Grabbing` | A drag in progress | Closed hand | Four-headed arrow | `grabbing` |
| `Crosshair` | Precise picking | Crosshair | Cross | `crosshair` |
| `NotAllowed` | A press here does nothing | Not-allowed sign | Slashed circle | `not-allowed` |
| `ResizeColumn` | An edge or splitter that resizes horizontally | Column resize | Left-right arrow | `col-resize` |
| `ResizeRow` | An edge or splitter that resizes vertically | Row resize | Up-down arrow | `row-resize` |

On Linux, a compositor without the cursor shape protocol keeps its own pointer
image whatever the shape.

## Camera

| Field | Default | Rule |
| --- | --- | --- |
| Field of view | 45° | Vertical, in degrees, above 0 and below 180. |
| Exposure | 0 stops | The exposure scale is 2 to the power of the stops, within ±64. |
| Near and far planes | 0.1 and 100 | In meters along the view direction, the near plane above 0 and below the far plane, the far plane finite. |
| Projection | Perspective | Sinks always use a perspective view. The aspect ratio comes from the sink's extent. |
| F-number | ∞ | Above 0. ∞ is a pinhole, which keeps every depth in focus. |
| Focus distance | 10 m | Above 0. The depth that's in focus. |
| Sensor height | 24 mm | Above 0. |
| Detail level | None | A level number, 0 or more, or none. See [detail level rules](#the-visibility-pipeline). |

A camera created again under its own handle replaces every field of that
camera from the next frame on. The inspector's
[`CameraUpdate`](/docs/reference/inspector#entities-and-messages) message
does this.

The camera's position and orientation come from its shown transform. Up is
+Y, unless the view direction is within 1 percent of vertical, when +Z is used.

### Lens

The camera is a thin lens. Depth is the distance from the camera along its
view direction.

| Quantity | Definition |
| --- | --- |
| Focal length F | h / (2 tan(θ / 2)), for sensor height h and vertical field of view θ. |
| Aperture diameter A | F / N, for f-number N. |
| Focus distance S | The camera's focus distance, held to at least F + 1 mm. |
| Circle of confusion c | The signed diameter, in pixels, of the disc that a point at depth z spreads over: c = A · F / (S − F) · (1 − S / z) · H / h, for a sink H pixels tall. It's 0 at the focus distance, positive behind it, and negative in front of it. |
| Depth of the background | Where depth is 0, z is the far plane. |

### Lens sampling

While an enabled pass asks for lens samples, such as the depth-of-field
reference, the sink's view moves each frame to a point of the camera's
aperture. Scene pipelines and every post-scene pass of that sink see the moved
view.

| Rule | Value |
| --- | --- |
| Aperture | A disc perpendicular to the view direction, centered on the camera, with a diameter of A · S / (S − F). |
| Sample on frame k | The point at √u of the disc's radius and at angle 2πv, for u = frac(0.5 + 0.7548776662 k) and v = frac(0.5 + 0.5698402910 k), where k counts the renderer's frames. |
| Projection | Sheared so that every point at the focus distance shows where the camera's own view shows it. Depth is unchanged. |
| Result | A point at depth z moves by c(z) pixels between opposite edges of the aperture. |

### Jitter

While an enabled pass asks for jitter, such as
[temporal antialiasing](#temporal-antialiasing), the sink's view moves each
frame by a fraction of a pixel. Scene pipelines and every post-scene pass of
that sink see the moved view. Velocity and every reprojection between frames
use the views without jitter.

| Rule | Value |
| --- | --- |
| Phases | N = ⌈8 / s²⌉, for the sink's [render scale](#render-scale) s. 8 at full scale. |
| Offset on frame k | (h₂(i) − 0.5, h₃(i) − 0.5) render pixels, for i = (k mod N) + 1, where h_b is the radical inverse of i in base b and k counts the renderer's frames. x grows right and y grows down. |
| Projection | Translated so that every point shows the offset away from where the view without jitter shows it. Depth is unchanged. |
| With lens sampling | Both apply: the jitter moves the lens-sampled view. |
| Texture detail | Material texture reads select their level with a bias of log₂ s − 1. |

### Render scale

A sink renders its scene below its own pixel size when an enabled pass
upscales, such as [temporal antialiasing](#temporal-antialiasing). The
`render.taa.scale` parameter sets the scale.

| Term | Definition |
| --- | --- |
| Output extent | The sink's pixel size: its window's or render image's. |
| Render scale s | `render.taa.scale`, held to the range the upscaling technique supports. 1 while no enabled pass upscales. |
| Render extent | The output extent times s on each axis, rounded to the nearest pixel and at least 1. |
| Before the upscaling pass | Scene pipelines, and the post-scene passes registered before it, render at the render extent. Their targets have that extent, divided by the target's own divisor. |
| From the upscaling pass on | The upscaling pass writes `main` at the output extent. It and every later pass render at the output extent. |
| Change | A change to s, or to the output extent, sizes the targets again on the next frame and resets every history. |

At most one enabled pass of a sink upscales.

## Shown transforms

Every frame shows each entity's transform at the frame's
[display time](/docs/reference/time#loops). Scene pipelines, lights, cameras,
and particle emitters all follow the shown transform. Poses aren't blended;
animation steps once per frame.

| Term | Rule |
| --- | --- |
| Sample | A transformation update read during a simulation step. Its stamp is the end time of that step. |
| Placement | A transformation update read outside a simulation step. It's shown at once and ends any motion in progress. |
| First update | A handle's first update is shown at once, sample or placement. |
| Span | The time from the handle's previous stamp to the sample's stamp, at most 250 ms. A sample after a placement spans one step. |
| Segment | Starts at the sample's stamp less one step, from the transform shown at that time, and reaches the sample one span later. Between the two, position and scale move linearly and orientation turns along the shorter arc. |
| Same step | A later sample in the same step replaces the earlier one's target and keeps its segment. |
| At rest | Past the end of its segment, a handle stays at its latest sample until its next update. |

| Source | Result |
| --- | --- |
| Publishes every step | Shown between its two latest samples by the blend factor, one step behind. |
| Publishes every _n_ steps | Moves without stopping between samples and is shown _n_ steps behind, as long as _n_ steps last at most 250 ms. |
| Starts moving after a rest | Its first segment lasts up to 250 ms; the next sample's segment starts from wherever that one reached. |

### Render images

| Rule | Behavior |
| --- | --- |
| Creation | A `RenderImage` created on the application's message scope, with a scene, an extent in pixels, and a camera, opens before the next frame. The renderer then sends a `RenderImageReady` message on the application's message scope, naming the handle the render image was created with and the image. |
| Image | `BGRAu8`, as large as the render image's extent. Passes can sample it, read and write it as a storage image, and copy from it. |
| Render graph | A render image records its scene's pipelines and the passes registered for all sinks, but not those registered for windows, such as an interface drawn over the game. Its last pass writes the image. Creating the first render image closes the render graph, as creating the first window does. |
| Frames | Every frame the renderer renders draws every render image, whether or not anything reads it, before it draws any window. A window's pass that reads a render image reads the picture of the same frame. |
| Size changes | A `SetRenderImageExtent` message on the application's message scope, naming the handle the render image was created with and an extent in pixels, resizes the image from the next frame on. The image keeps its handle. A message naming no open render image is logged and left out. |
| Removal | A `DeleteMessage` on the application's message scope naming the handle the render image was created with stops rendering it before the next frame and drops its passes. Its image and its render targets stay allocated until the renderer drops. |
| Screenshots | A screenshot of a render image's sink with no pass named captures the image after the last pass. |

### Scenes

| Rule | Behavior |
| --- | --- |
| World | The world is the scene the application starts with. Every window shows it. |
| Creation | Creating a scene gives a new message scope. Objects created on it, such as meshes, lights, fog, environments, cameras, and particle emitters, belong to that scene alone, and its scene pipelines never see the other scenes' objects. |
| Scene pipelines | Each scene records the scene pipelines installed for it, in the order they were installed. A pipeline is installed for one scene, and installing it for another scene creates another instance with its own state. |
| Sun and fog | The newest directional light and the newest fog created on a scene's scope light that scene's sinks. |
| Cameras | A sink shows its scene from its camera's transform, whichever scope created the camera. |
| Debug meshes | Debug meshes are the world's: a sink of another scene shows none. |
| Shared state | Post-scene passes and the scene background are shared by every scene. Each scene generates its own sky environment, from its own sun, following its first sink. |

## Pipelines and passes

| Concept | Role |
| --- | --- |
| Scene pipeline | Owns one scene's state and per-sink resources and records one command per sink of its scene per frame. Several can be registered; the default setup registers the visibility pipeline and particles for the world. |
| Render feature | One registration of a post-scene effect: what every sink's pass shares, such as settings. Registered for every sink, for every window with a camera, such as a UI, or for one window without a camera. |
| Render pass | One sink's post-processing, built by its feature, that reads `main` and replaces it or draws over it. |
| Pixel step | A render pass that computes each pixel of its replacement for `main` from the same pixel of the incoming `main`. The renderer records it, alone or [fused](#pixel-steps-and-fusion) with the steps next to it. |
| Scene background | A feature whose pass the scene pipeline records after opaque and before transparent surfaces, such as the sky, and which may generate each scene's environment. A later registration replaces an earlier one. |
| Pass state | Enabled or bypassed, held by each registration for every pass it built, set in code or by the `render.pass.<name>` parameter, which sets every registration with that name. A bypassed pass draws nothing, and later passes read the `main` it would have read. |
| Idle pass | A pass that records nothing in a frame, because it's bypassed, has nothing to apply, or still waits for its pipeline. It leaves `main` unchanged. That costs nothing when its replacement for `main` has the format, extent, and uses of the `main` it reads, and one copy otherwise. |
| Stand-in | A second image a pass declares for its replacement for `main`, built with more uses, such as storage. In a frame the pass writes through it, the replacement is that image. In every other frame the replacement is its own image, without those uses. A pass has one only where the device can place one image under two names, and the terminal pass has none. |
| Overlay | A pass that draws over `main` instead of replacing it, such as a UI pass or the debug overlay. |

| Rule | Value |
| --- | --- |
| Registration | Post-scene passes and the scene background are registered before the first window or render image. Passes for one window are registered before the frame after that window is created. |
| Removal | Removing a window or render image drops every pass built for it. |
| Order per sink | Every scene pipeline of the sink's scene in registration order, then every post-scene pass in registration order, then a copy to the sink's final target only when no post-scene pass replaces `main`. Overlays registered after the last pass that replaces `main` record after that pass or copy. |
| Terminal pass | The last post-scene pass that replaces `main` writes the sink's final target: the window's swapchain or the render image. Overlays registered after it draw over the final target, inside the bounds of what they show. On a sink with no `main` before its overlays, the last overlay writes the final target instead. |
| Targets | A pass declares named, sink-scoped targets: full-size, scaled by a divisor, persistent, or history targets whose previous frame can be read. Reading a target that nothing creates fails at setup. |
| Clears | A node that records nothing has its first-use targets cleared; one that records has them discarded. A replacement for `main` is the exception: when its pass records nothing, it holds the `main` before it. |
| Frame-wide work | Detail levels, shadow views, and exposure follow each scene's first sink. |
| Swapchain | FIFO presentation with 2 frames in flight. On Vulkan, a swapchain has 3 images unless `render.swapchain.images` sets a count, and when the driver and surface support waiting for presents, a frame starts only after the display shows the frame presented 2 frames before it, or after 67 ms. |

| Temporal antialiasing | `taa` | `TAA Output`, `TAA History`, and, where the device has a vendor upscaler, `TAA Upscaled` | After the scene, particles, and height fog, before depth of field, motion blur, lens flare, bloom, and tone mapping. | Debug overlay | `debug-overlay` | `main` in place, and `debug-overlay layer` | After the passes it should cover. |

| Pass | Stages |
| --- | --- |

| Bloom | `bloom-extract`, `bloom-downsample` and `bloom-upsample` when the levels need them, `bloom-composite` |

### Sky environment

The atmosphere sky also generates each scene's environment, which the visibility pipeline lights
with while the scene has no `Environment`. It holds the sky that scene's first sink's camera sees,
under that scene's sun, in the layout of a baked environment:

| Property | Value |
| --- | --- |
| Radiance | The sky's radiance in each direction: the sky-view light for each lux of sunlight, times the sun's illuminance, unexposed, in nits. Below the horizon, what the sky shows there: the sky at the horizon in the same heading for a full sky, or black when the sky skips below the horizon. Without the sun's disk, which the directional light carries. |
| Specular cube | Six faces of 128 × 128 texels, RGBA16F, 8 levels. Level `l` holds the radiance prefiltered with the Trowbridge-Reitz (GGX) lobe of roughness `l / 7`, viewed along the texel's direction; level 0 holds the radiance. Each texel takes 64 samples. |
| Irradiance cube | Six faces of 8 × 8 texels, RGBA16F, 1 level: the cosine-weighted mean radiance around the texel's direction, which is irradiance over π. Each texel takes 256 samples. |
| Faces | +X, −X, +Y, −Y, +Z, −Z, oriented as a baked environment's. |
| Intensity | 1. The sky is already in physical units, so no illuminance rescales it. |
| Viewpoint | The first sink's camera height, rounded to the nearest meter. |
| Regenerated | In full, before any of the frame's work that reads the environment, in each frame where the sun's direction or illuminance, the rounded height, or the haze changes. Other frames record nothing. |
| Without a directional light | Black. |

### Pixel steps and fusion

Height fog, color correction, the color grading passes, the tone mappers, and
sRGB display are pixel steps. Each step's pipeline is a `tile` pipeline whose
shader is a [pixel shader](/docs/reference/besl/interface#pixel-shaders).

| Term | Definition |
| --- | --- |
| Run | One or more pixel steps registered one after another, with no other post-scene pass between them, that record as one pass. |
| Fusion | A pipeline of kind `fused`, baked from a [`.fusion` asset](/docs/reference/assets#fusions), that runs a list of step pipelines in one pass. |
| Catalog | Every `Pipeline` resource of kind `fused` in the resource store. |
| Active | A step is active in a frame when it's enabled and has something to apply. Height fog without a fog is inactive. |

| Rule | Value |
| --- | --- |
| Catalog read | When the first window opens, the renderer reads the catalog once. Development builds first bake every `.fusion` source that's missing or stale. Sinks initialize after the catalog is read, and draw nothing before. |
| Matching | Going through the steps in registration order, a run starts at each step that isn't in a run yet. It takes the longest fusion whose steps are the pipelines of that step and the steps after it, in order. With no such fusion, the step is a run of its own on its own pipeline. |
| Fusion off | With `render.fusion` set to `false`, every step is a run of its own. |
| Output | A run writes one replacement for `main`, named like its last step's output and in its last step's output format. The run that ends the post-scene passes writes the sink's final target. The other steps' outputs don't exist. |
| Precision | Inside a fused run, color passes from step to step as 32-bit floats. |
| State | Each step keeps its own pass state and `render.pass.<name>` parameter. A run of one step that's bypassed or inactive is an idle pass. A fused run skips its bypassed and inactive steps, and when all of them are skipped, it's an idle pass. |
| Pending | While a run's pipeline compiles, and after it fails, the run is an idle pass. |
| Metric | A run of one step reports `pass.<step name>`. A fused run reports `pass.` followed by its steps' names joined by `+`, such as `pass.color-correction+aces2-color-grading`. |

The engine ships these fusions:

| Fusion | Steps |
| --- | --- |
| `byte_engine/rendering/fusions/correction-agx.fusion` | `color-correction`, `agx` |
| `byte_engine/rendering/fusions/correction-aces.fusion` | `color-correction`, `aces` |
| `byte_engine/rendering/fusions/correction-lut-agx.fusion` | `color-correction`, `lut`, `agx` |
| `byte_engine/rendering/fusions/correction-lut-aces.fusion` | `color-correction`, `lut`, `aces` |
| `byte_engine/rendering/fusions/correction-aces2-grading.fusion` | `color-correction`, `aces2-color-grading` |
| `byte_engine/rendering/fusions/correction-baked-grading.fusion` | `color-correction`, `baked-color-grading` |
| `byte_engine/rendering/fusions/lut-agx.fusion` | `lut`, `agx` |

### Pass settings

| Pass | Settings and defaults |
| --- | --- |
| Bloom | Scatter 0.06, tail exponent 2, halation 0 in every channel, halation radius 0.005 of the sink's height in every channel, maximum brightness 4,096, radius 1, 6 levels of 1 to 6. |
| Depth-of-field reference | No settings. While enabled, it samples the lens. `main` becomes a running mean of the scene, restarted when the camera's own view, its lens, or the sink's extent changes: frame n since the restart weighs 1 / n for its first 1,024 frames, and 1 / 1,024 after that. The mean is held at 32-bit float per channel, after each color channel is held to 65,504; alpha is the current frame's. Moving objects don't restart it. |
| Depth of field | The minimum and maximum blur diameters, in pixels, each unset by default; the lens is the camera's. See [Depth of field](#depth-of-field). The `circle-of-confusion` view shows −b / 32 in red and b / 32 in blue, each held to 0 to 1, and green 1 where \|b\| is under 1 pixel. |
| Motion blur | Shutter 8,333 µs, maximum blur radius 32 pixels within 0 to 32, 8 taps of 1 to 32. See [Motion blur](#motion-blur). |

| Height fog | A layer's height falloff 0.2 and base height 0; a fog's albedo white, maximum opacity 1, anisotropy 0.7 within 0 to 1, ambient illuminance 0 lux, 16 light samples within 1 to 64. See [height fog lighting](/docs/reference/lighting#height-fog-lighting). |

### Depth of field

The `depth-of-field` pass blurs each pixel p of `main` by the camera's lens.
The terms use the circle of confusion c of the [lens](#lens), r for the
distance in pixels from p to a point s of the image, and b<sub>p</sub> and
b<sub>s</sub> for the blur diameters at p and s.

| Term | Definition |
| --- | --- |
| Maximum blur diameter M | 64 pixels, or the pass's maximum when it has one, held to 1 to 64 pixels. |
| Minimum blur diameter m | 0, or the pass's minimum when it has one, held to 0 to M. |
| Blur diameter b | The sign of c times max(d, m), where d is \|c\| when \|c\| is at most M / 2, and otherwise M / 2 + M / 2 × tanh((\|c\| − M / 2) / (M / 2)), which stays below M. A c of 0 counts as positive. |
| Reach of s | e = \|b<sub>s</sub>\| / 2. When b<sub>s</sub> > b<sub>p</sub>, s lies behind p, and e is at most \|b<sub>p</sub>\| / 2. |
| Coverage | clamp(e − r + 0.5, 0, 1). |
| Density | 1 / max(π b<sub>s</sub><sup>2</sup> / 4, 1). |
| Gathered | The mean of the colors around p, each weighted by coverage × density, in scene-linear light with each channel held to 65,504. |
| Ring share | The part of the gathered weight that points beyond 3.5 pixels of p carry. |
| Result | The gathered color moved toward the mean of the 3 × 3 pixels around p, by p's ring share. In that mean each pixel weighs 1, 2, or 1 along each axis, times its own ring share. |
| Sampling | Every pixel within 3.5 pixels of p is a point. Beyond, 16 points per ring stand for the ring's area, at rings whose bounds grow by 1.39 times from 3.5 pixels. Each pixel turns every ring by its own angle, up to a sixteenth of a turn, and places each ring's points at its own distance between the ring's bounds, spread evenly over the ring's area; both come from slice 0 of the [blue noise](#blue-noise), the same in every frame. Each ring is read from the image or an average of it whose texels are 2, 4, or 8 pixels wide, the widest no wider than the points' spacing. Each average takes 2 × 2 texels of the one before, weighing each by min(\|b\| / w, 1) for texels w pixels wide, or evenly where every weight is 0, and averages b the same way. Rings that no blur near p can reach are skipped. |
| Pinhole | A lens whose c is 0 everywhere, such as one with an f-number of ∞, leaves `main` unchanged when m is 0, and blurs every pixel by m otherwise. |

### Motion blur

The `motion-blur` pass blurs each pixel p of `main` along the motion of the
surfaces around it, as a shutter open for part of the frame would. It reads
`main` and `Velocity`, so camera turns, camera moves, moving meshes, and skinned
meshes all blur. The terms use d for the distance in pixels from p to a tap s,
and z for a pixel's current linear view depth in `Velocity`.

| Term | Definition |
| --- | --- |
| Shutter fraction f | The shutter time over the sink's frame interval, held to 0 to 1; 0 when the frame interval is unknown. |
| Maximum blur radius R | The pass's maximum, held to 0 to 32 pixels. |
| Blur v | The pixel's `Velocity` motion times f / 2, shortened to length R when longer. It reaches from the pixel to either end of its blur. |
| Blur length l | \|v\|, at least 0.5. |
| Tile | Each 32 × 32 pixel square, counted from the top-left corner; the last row and column of tiles may be partial. |
| Tile maximum | The longest v among the tile's pixels; the first of them when two are as long. |
| Neighborhood blur N | The longest tile maximum among the 3 × 3 tiles around p's tile. Tiles past the image's edge count as the edge tiles. |
| Pass-through | When \|N\| is less than 0.5, p keeps its color. |
| Taps | For n taps, tap i, from 0 to n − 1, lies at p + N × t<sub>i</sub>, with t<sub>i</sub> = −1 + 2 (i + j + 1) / (n + 1). j is in −0.5 to 0.5, from interleaved gradient noise of p's coordinate, shifted each frame and repeating every 64 frames. A tap reads the pixel it falls in, and a tap past the image's edge reads the nearest edge pixel. |
| In front | front(a, b) = clamp(1 − (z<sub>b</sub> − z<sub>a</sub>) / 0.1 m, 0, 1): how much b lies in front of a. |
| Cone | cone(d, l) = clamp(1 − d / l, 0, 1). |
| Cylinder | cylinder(d, l) = 1 − smoothstep(0.95 l, 1.05 l, d). |
| Tap weight | front(p, s) × cone(d, l<sub>s</sub>) + front(s, p) × cone(d, l<sub>p</sub>) + 2 × cylinder(d, l<sub>s</sub>) × cylinder(d, l<sub>p</sub>). |
| Result | (c<sub>p</sub> / l<sub>p</sub> + Σ w<sub>s</sub> c<sub>s</sub>) / (1 / l<sub>p</sub> + Σ w<sub>s</sub>), over the taps s with weights w<sub>s</sub>, in scene-linear light with each channel held to 65,504. Alpha is p's own. |
| Closed shutter | An f of 0 leaves `main` unchanged. |
| Reduced motion | While `accessibility.motion` is `reduced`, the shutter time is 0, so f is 0. See [Reduced motion](/docs/reference/gui#reduced-motion). |

The pass offers three debug views: `velocity`, v divided by R in red and
green, mapped from −1 to 1 onto 0 to 1; `blur-length`, \|v\| divided by R in
every channel; and `neighbor-max`, N mapped as `velocity` maps v.

### Color correction

Color correction adjusts the scene-linear picture before tone mapping. It
reads only each pixel's own color. Its steps run in the order of the table.

| Step | Definition |
| --- | --- |
| Input | Scene-linear sRGB with a D65 white. Alpha passes through. |
| Exposure | Every channel times 2<sup>exposure</sup>. |
| White balance | A von Kries adaptation in CAT16 cone space from the white W(temperature, tint) to D65, with both whites at luminance 1, then scaled so a neutral grey keeps its luminance. |
| White `W(T, t)` | The Planckian white of temperature T in CIE 1960 *uv*, from Krystek's 1985 approximation, moved by the *uv* offset that takes the 6,504 K Planckian white to D65, then 0.05 × t along the locus's unit normal toward the green side, which is higher *v*. W(6,504 K, 0) is D65. |
| Working space | ACEScg, through the D65-to-D60 adapted matrix of the ACES passes. Channels below 0 are held to 0, then encoded as ACEScct. |
| Lightness `L` | (max + min) / 2 of the three ACEScct channels. Each channel's offset is its value minus L. |
| Tone position | u = (L − black) / (white − black), where black = 0.0729055 (ACEScct of 0) and white = 1.4679963 (ACEScct of 65,504); p = 0.2442012, u at ACEScct 0.4135884 of mid grey 0.18; t = 0.5908968, u at ACEScct 0.8972603 of 64. |
| Shadows | For 0 < u < p, u becomes u + k u (1 − u / p)<sup>2</sup>, where k = 2 × shadows for shadows ≥ 0 and k = shadows below 0. |
| Highlights | For p < u < t, with y = (u − p) / (t − p), u becomes u + 3 × highlights × (t − p) × y<sup>2</sup> (1 − y)<sup>2</sup>. |
| Contrast | With u after shadows and highlights, for u ≤ p, f(u) = p (u / p)<sup>contrast</sup>; for p < u < 1, f(u) = 1 − (1 − p) ((1 − u) / (1 − p))<sup>contrast</sup>; at u ≥ 1, f(u) = u. L becomes black + (white − black) × f(u). Each channel keeps its offset from L. |
| Split tone | Each channel c becomes c + n × (m<sub>h</sub> × H − m<sub>s</sub> × S) × D. The masks are m<sub>s</sub> = 16 y<sup>2</sup> (1 − y)<sup>2</sup> with y = (L − 0.0729055) / (0.4135884 − 0.0729055) between black and mid grey, and m<sub>h</sub> = 16 y<sup>2</sup> (1 − y)<sup>2</sup> with y = (L − 0.4135884) / (0.7831050 − 0.4135884) between mid grey and 16 (ACEScct 0.7831050); each is 0 outside its range. H = amount × min(1, 1 + balance) and S = amount × min(1, 1 − balance). The protection n = 1 / (1 + (C / 0.1)<sup>2</sup>), where C is the largest minus the smallest ACEScct channel. |
| Split direction `D` | The ACEScct offsets log2(c<sub>i</sub> / 0.18) / 17.52 of the ACEScg color c that has mid grey's Oklab lightness, Oklab chroma 0.05, and Oklab hue h, less their mean weighted by ACEScg luminance (0.2722287, 0.6740818, 0.0536895). |
| Saturation | L and the offsets are taken again from the split-toned channels. Each channel c becomes q + saturation × (c − q), around the pivot q = L + density × the largest offset. |
| Output | ACEScct decoded to ACEScg, converted to linear sRGB with the inverse of the input matrix, and held to 0 and above. |

| Term | Definition |
| --- | --- |
| Exposure | Stops, any value. +1 doubles the light, −1 halves it. It adds to the camera's exposure. |
| Temperature | The color temperature, in kelvins, of the light that shows as neutral. A lower value turns the picture bluer, a higher one warmer. |
| Tint | The white's distance from the Planckian locus, from −1 to 1. Positive values neutralize a greener light and turn the picture magenta; negative values turn it green. |
| Shadows | From −1 to 1. Positive values brighten the shadows, steepening the curve just above black up to 3 times: at 1, a tone 4.5 stops below mid grey rises 1.7 stops. Negative values deepen them, until at −1 the curve is flat at black and the same tone falls 1.2 stops. Black, mid grey, and everything brighter stay in place. |
| Highlights | From −1 to 1. Positive values brighten the tones from mid grey to 64, most at 4.25 stops above mid grey, which 1 raises by 1.6 stops; negative values pull them down by as much. The change fades out smoothly at both ends, so mid grey and everything past 64 stay in place. |
| Split hue | The Oklab hue h, in degrees, that the highlights move toward. The shadows move toward the opposite hue. About 55 gives orange highlights and teal shadows. |
| Split amount | From 0 to 1. At 1, a grey at the peak of either mask moves by about 0.05 in Oklab chroma, at the peaks 3 stops below and 3.25 stops above mid grey. Black, mid grey, and tones past 16 keep their color. The offsets sum to 0 under ACEScg luminance, so a tinted grey keeps its brightness to first order. |
| Split balance | From −1 to 1. Negative values keep the shadow tint and weaken the highlight tint, down to none at −1; positive values do the opposite. |
| Split protection | Built in. A grey takes the whole tint; a color whose ACEScct channels spread by 0.1 (about 1.75 stops) takes half, so skin and saturated colors keep their own hue. |
| Contrast | The curve's slope at mid grey. Above 1 it darkens the shadows and brightens the highlights, rolling off toward black and toward 65,504 so nothing clips; below 1 it flattens them. Mid grey never moves. |
| Saturation | 0 removes all color, 1 keeps it, and higher values strengthen it. A pixel whose channels are equal never changes. |
| Density | Where saturation takes its light from. At 0 channels move around L, so stronger color is brighter in its main channel. At 1 they move around the largest channel, so stronger color only lowers the others, as more dye does in film, and weaker color raises them toward it. Values between blend the two pivots. |

### Film grain

Film grain imitates the grain of scanned film stock on the display-encoded
picture. Each frame draws new grain. Grain changes the picture's density, so
every channel of a pixel scales by the same factor, and dark and bright areas
take the same relative grain.

| Term | Definition |
| --- | --- |
| Result | Each color channel times e<sup>a × z(L) × g</sup>, held to 0 and above. Alpha passes through. At a level of 0 or below, or while bypassed, the picture passes through unchanged. |
| Luma `L` | 0.2126 R + 0.7152 G + 0.0722 B of the display-encoded color, held between 0 and 1. |
| Cells | The image divided into 4 × 4 pixel blocks from its top-left corner. |
| Draw | The sum of four uniform draws minus 2, so mean 0 and variance 1/3. Each pixel has one per frame, and each cell has one per frame. |
| Noise | White noise per pixel and frame, with mean 0 and variance 1/3, uncorrelated between pixels: the pixel's draw, minus the mean of the 16 pixel draws of its cell, plus a quarter of the cell's draw. The mean of a cell's noise is therefore a quarter of the cell's draw. The noise continues past the image's edges, so edge pixels take grain like any other. |
| Narrow blur `N` | The noise blurred by a Gaussian of standard deviation σ = max(size × H / 2160, 0.05) pixels, where H is the sink's height, cut off at a radius of min(⌈2.5 σ⌉, 8) pixels, with weights that sum to 1. |
| Cell value | The mean of the cell's noise. |
| Wide blur `W` | The cell values blurred by a Gaussian of standard deviation √(max((8.4 σ)² − 3.92, 0)) / 4 cells, cut off at a radius of min(⌈2.5 × that⌉, 16) cells, then filtered bilinearly between cell centers at each pixel. Below 0.3 cells the blur is left out, and the cells are only filtered. |
| Grain `g` | (N − 0.95 W) scaled to unit variance on a field of uniform color. |
| Amplitude `a` | level × 0.08505 × r. The factor r is 1 for a sink 2,160 pixels tall or taller. For a shorter sink, it's the share of the grain's standard deviation that's left when a 2,160-pixel picture is downscaled to H pixels with a Hermite filter widened by 2,160 / H, a widening held to at most 11. Fine grain loses more than coarse grain. |
| Zone weight `z` | Each zone's weight is max(0, 1 + gain), at luma 0 (Black), 0.13 (Shadow), 0.30 (Mid), 0.60 (High), and 1 (White). Between two zones the weight blends with a smooth step, 3t² − 2t³. Every weight is divided by the weight at luma 0.5, at least 0.05, so z is 1 at mid grey whatever the gains. |
| Level | 1 makes grain on a 50 % grey card as strong as on scans of real 35 mm, 16 mm, and 8 mm stock. |
| Size | The narrow blur's standard deviation in pixels of a 2,160-pixel-tall picture. About 0.4 matches 35 mm, 1.2 matches 16 mm, and 2.7 matches 8 mm. |
| Gain | Any value. −1 or below removes the zone's grain, 0 keeps it as strong as at mid grey, and 3 makes it four times as strong. |

### Bloom

Bloom moves a share of every pixel's light into a faint, wide tail around it,
and halation moves a share of each channel into a halo of a set radius. Neither
adds light: a field of one brightness leaves bloom unchanged, and a highlight
keeps the light it doesn't spread. There's no threshold, so every pixel spreads
light, and the tail and halo show only where they're brighter than the pixels
they fall on. Each channel's tail and halo come from that channel's light alone.

| Term | Definition |
| --- | --- |
| Result | For each channel c, (1 − S<sub>c</sub>) × scene + the sum over levels k of w<sub>k,c</sub> × level k, in scene-linear light after exposure, held to 65,504. S<sub>c</sub> = s + h<sub>c</sub> is the sum of the channel's weights. Where every S<sub>c</sub> is 0, the scene passes through unchanged. |
| Scatter `s` | The share of each pixel's light that moves into the tail, from 0 to 1, the same for every channel. |
| Halation `h` | The share of each channel's light that moves into its halo, per red, green, and blue channel, from 0 to 1 − s. |
| Levels | Level 0 is half the sink's resolution, and each later level is half the one before. Level k is the source blurred by a kernel of total weight 1 that reaches twice as far as level k − 1's, and one of its texels spans 2<sup>k + 1</sup> pixels. |
| Level weight w<sub>k,c</sub> | s × r<sup>k</sup> / the sum of r<sup>j</sup> over every level j, plus h<sub>c</sub> × g<sub>k,c</sub> / the sum of g<sub>j,c</sub> over every level j. The tail's and the halo's weights each sum to 1 before their share scales them. |
| Tail exponent `p` | Sets r = 2<sup>2 − p</sup>, so the tail falls off as about 1 / distance<sup>p</sup>. At 2, every level carries the same share; at 3, each level carries half the share of the one before. |
| Halation radius | The halo's radius, per channel, as a share of the sink's height. It sets g<sub>k,c</sub> = e<sup>−2 (k − m)²</sup>, where m = log<sub>2</sub>(radius in pixels / 2), held between 0 and the last level: the halo centers on the level whose texels span its radius and reaches about half a level to either side. |
| Source | Level 0 averages 2 × 2 blocks of the scene in groups of four, and within a group each block weighs 1 / (1 + M) by its average, where M is the largest channel. With pixel weights, every channel of every pixel is first held between 0 and the maximum brightness, and within a block each pixel weighs 1 / (1 + M) against the others. Without them, a block is the plain average of its pixels, held between 0 and the maximum brightness. Either way a single bright pixel can't flicker the tail, and where every pixel is alike the weights cancel; pixel weights also hold back a cluster of bright pixels inside one block. |
| Pixel weights | Off by default. Set by `BloomPassSettings::pixel_weights` and the `render.bloom.pixel-weights` parameter. |

Rendering on demand, set by the `render-on-demand` parameter, renders a frame
only when a window, camera, or pass state changed, a pass asked for one, or a
screenshot is pending. Scene changes don't count, so an application that moves
cameras or objects requests a redraw itself.

### SMAA

SMAA finds the edges between each pixel and its west and north neighbors in
`main`, then blends the pixels along each edge it finds.

| Term | Definition |
| --- | --- |
| Perceptual color | Each channel c of `main` mapped to √(max(c, 0) / (1 + max(c, 0))). |
| Contrast | Between a pair of pixels: the largest of the three channels' differences in perceptual color. |
| Depth edge | A pair of pixels whose `depth` values a and b differ by more than 1 % of the larger: \|a − b\| > 0.01 max(a, b). A pair that shows no surface never makes one. |
| Threshold | 0.03 between pixels on a depth edge, and 0.05 otherwise. Without `depth`, 0.05 everywhere. |
| Edge | A pixel has an edge with its west or north neighbor when their contrast is at least the threshold and at least half the largest contrast among the pixel's four neighbors and the west neighbor's west and the north neighbor's north. |

The depth edge test is the engine's own: the reference SMAA predicates on an
absolute depth difference and raises the threshold away from depth edges, and
the engine instead lowers it on them, so it finds every edge it found without
`depth`.

### Temporal antialiasing

Temporal antialiasing replaces `main` with a running blend of the jittered
frames, each reprojected to the current frame. The `render.taa.technique`
parameter picks how it blends, and can change while running.

| Technique | Blend | Render scale | Debug views |
| --- | --- | --- | --- |
| `engine` | The engine's own resolve, defined below. | `render.taa.scale`, held to 0.5 through 1. | The four below. |
| `metalfx` | The MetalFX temporal scaler, on Metal devices that support it. | `render.taa.scale`, held to the device's supported range. | None. |

When the device doesn't support the chosen technique, the pass logs a warning
and resolves with `engine`, at the scale `engine` holds `render.taa.scale` to.

#### MetalFX

The `metalfx` technique reads `main`, `Depth`, `Velocity`, and `Reactive` at
the render extent and writes `main` at the output extent. The scaler keeps its
own history. It writes `TAA Upscaled`, a storage image and `TAA Output`'s
[stand-in](#pipelines-and-passes): in a `metalfx` frame `TAA Output` is that
image, and in an `engine` frame `TAA Output` is its own image, without storage
use.

| Input | Value |
| --- | --- |
| Color | `main`, pre-exposed scene color. Its pre-exposure is the sink's exposure scale divided by the exposure scale on the frame the scaler last reset. |
| Depth | `Depth`, reversed: 1 at the near plane and 0 at the far plane. |
| Motion | The red and green of `Velocity`, times −1 on each axis, so each vector points from the pixel to where it was in the previous frame, in render pixels. |
| Reactive mask | `Reactive`. |
| Jitter | The sink's [jitter](#jitter) offset, in render pixels, x right and y down. |
| Reset | On the frames the `engine` technique resets, defined below, and on the first frame after the technique changes. |

#### Engine resolve

The `engine` technique reads `main`, the current and previous `Velocity`, and
`Reactive` at the render extent, and its own history at the output extent, and
writes `main` at the output extent. At [render scale](#render-scale) 1 the two
extents are one, and each pixel is its own nearest sample. In this table, a
pixel is an output pixel, a render pixel is a pixel of the render extent, s is
the render scale, a color is pre-exposed scene color, and every color
operation happens on weighted color, c / (1 + Y), in YCoCg, where Y is luma.

| Term | Definition |
| --- | --- |
| Render position | The pixel's center times s on each axis: where the pixel lies in the render extent. |
| Nearest sample | The render pixel whose sample lies nearest the render position. A render pixel's sample lies at its center less the frame's [jitter](#jitter), so the nearest sample is the render pixel that holds the render position plus the jitter, held inside the render extent. |
| Current color | At render scale 1, the nearest sample's color. Below it, the colors of the nearest sample and the 8 render pixels around it, held inside the render extent, each in the blend's weighted YCoCg and weighed by exp(−2.29 d²) for the distance d, in pixels, from the pixel's center to that sample; the sum is divided by the sum of the weights. |
| Sample weight β | 1 at render scale 1. Below it, exp(−2.29 d²), for the distance d, in pixels, from the pixel's center to the nearest sample. |
| Dilated velocity | The `Velocity` of the render pixel, among the 3 × 3 around the nearest sample, whose current linear depth in `Velocity` is least, divided by s, so it's in pixels. |
| Previous position | The pixel's center less its dilated velocity. |
| History sample | The history at the previous position, read with a 5-tap Catmull-Rom filter (B = 0, C = 0.5), times the ratio of this frame's exposure scale to the previous frame's. |
| Off screen | The previous position lies outside the sink. |
| Disoccluded | The farthest of the current linear depths in the previous frame's `Velocity`, at the 4 render pixels around the previous position times s, is less than 0.99 times the previous linear depth in `Velocity`. Something stood in front of the surface in the previous frame. |
| Neighborhood box | Over the 3 × 3 render pixels around the nearest sample: the mean μ and standard deviation σ of each channel. The box spans max(minimum, μ − γσ) to min(maximum, μ + γσ) per channel, for variance gamma γ. |
| Clipped history | The history sample moved along the line toward the box's center until it lies within the box. A sample already inside is unchanged. |
| Luma weight | w = (1 − \|Y<sub>c</sub> − Y<sub>h</sub>\| / max(Y<sub>c</sub>, Y<sub>h</sub>, 0.2))², for the current luma Y<sub>c</sub> and the clipped history's luma Y<sub>h</sub>. |
| Feedback | lerp(maximum, lerp(minimum, maximum, w), clamp(\|v\| / 2, 0, 1)) for the dilated velocity's length \|v\| in pixels, so a still pixel takes the maximum whatever its luma weight; then lerp toward the minimum by clamp((\|v\| − 2) / 13, 0, 1), then at most n / (n + 1) for the history's frame count n, then times 1 − the nearest sample's `Reactive`. 0 when off screen, disoccluded, or reset. |
| Result | lerp(clipped history, current, (1 − feedback) × β), unweighted back to scene color, and the current color when off screen, disoccluded, or reset. It's `main` from here on and the next frame's history. |
| Frame count | 0 when the feedback is 0 for being off screen, disoccluded, or reset; otherwise the history's count plus 1, at most 255. The history keeps it. |
| Reset | The first frame, the first frame after the sink's render or output extent changes, and the first frame after the pass was bypassed. |

The pass offers four debug views: `velocity`, the dilated velocity divided by
16 pixels in red and green, held to −1 to 1 and mapped to 0 to 1; `disocclusion`,
red where off screen and green where disoccluded; `reactive`, `Reactive` in
every channel; and `taa-frames`, the frame count divided by 32 in every channel.

### Blue noise

Passes that need a random value per pixel read the engine's spatiotemporal blue
noise. Each slice is blue noise across the image, and each pixel's values
through the slices are blue noise in time.

| Property | Value |
| --- | --- |
| Size | 32 slices of 64 × 64 texels, two independent channels, 8 bits each. |
| Read | At the pixel modulo 64, as (value + 0.5) / 256. |
| Slice on frame k | k mod 32 while the sink is [jittered](#jitter); 0 otherwise. Depth of field always reads slice 0. Screen-space GI always reads slice k mod 32. The [masked cutoff](#materials) follows the scene's first sink. |

## The visibility pipeline

Each instance of the visibility pipeline draws one scene. On this page, its
first sink is the first sink of that scene.

| Limit | Value |
| --- | --- |
| Geometry capacity | Set by the `render.geometry.*` parameters; a mesh that doesn't fit is rejected at upload. |
| Meshlet | 64 vertices and 124 triangles |
| Meshlets per primitive instance | 4,096 |
| Instances drawn per frame | Set by the `render.instances.*` parameters, at most 33,554,432; the rest are left out with one warning |
| Materials, bindless textures | 1,024 each |
| Resident IES profiles | 64 distinct profiles; lights that share a profile share its slot |
| Resident lightmaps | 16 |
| Texture slots per material | 16 |
| Lights | 1,024; the rest are left out with one warning |
| Shadowed lights | 4 directional with 4 cascades each, or 1 with 16 virtual shadow map levels; 16 cone, 16 point |
| Light clusters | 16 by 8 by 24 |

A renderable is drawn only once its mesh's coarsest detail level, every
material, and every texture are resident.

A material texture is resident once its coarse mips are: the mips from the
first one whose larger side is at most 128 texels. Until its full mip chain
loads, it samples as though its finer mips were missing, so a surface that
needs them looks blurred. A texture with no mips larger than 128 texels, or no
mip that small, loads whole. Lightmaps and IES profiles always load whole.

A skinned primitive instance that receives a pose takes its own vertices out of
the geometry vertex capacity, as many as its primitive has, for as long as it
keeps receiving poses. It gives them back when it's removed. When the capacity
can't hold them, the instance draws in its bind pose and the pipeline logs one
error for it.

| Detail level rule | Value |
| --- | --- |
| Allowed error | One pixel times `render.lod.bias`, converted to world units from the first sink's projection. |
| Small instances | An instance is small while its bounding sphere's radius covers fewer than `render.lod.small-radius` pixels, measured at the sphere's nearest point to the camera. A small instance is allowed `render.lod.small-bias` times the error. |
| Instance error | The level's error per distance times the straight-line distance from the camera to the nearest point of the bounding sphere, plus its constant error, divided by the largest model axis. Turning the camera never switches levels. |
| Wanted level | The coarsest level whose error is within the allowed error; the finest otherwise. An instance around the camera, with zero scale, or without a finite error wants full detail. |
| Drawn level | The wanted level when it's resident; otherwise the mesh's finest resident level. |
| Replaced primitives | A primitive that [others of its mesh take over from](/docs/reference/assets#authored-detail-levels), as a billboard does from a plant, isn't drawn once the error they take over at is within the allowed error. Those others aren't drawn until then. Both sides measure distance with one bounding sphere, so exactly one of them is drawn. |
| Forced level | The detail level of the first sink's camera when it has one, otherwise `render.lod.force` when it's set. Every instance wants that level, or its primitive's coarsest when it has fewer. A primitive that takes over from others isn't drawn, and the primitives it would replace are. |
| Shadows | Each shadow view, such as a cascade, a virtual shadow map level, a cone map, or a point map's face, draws an instance at the coarsest resident level of its primitive whose error is within one of the view's texels times `render.lod.bias`, and never at a level finer than the camera draws. The error is measured as the camera's is: by the straight-line distance from the light to the nearest point of the bounding sphere in a perspective view, at any distance in an orthographic one, divided by the largest model axis. The small-instance allowance doesn't apply. A skinned instance that receives a pose, a [cluster mesh](/docs/reference/levels#merged-placements), and every instance while a level is forced draw the camera's level in every view. |
| Ray tracing | Rays hit each primitive's coarsest level. Rays never hit a primitive that takes over from others; they hit the primitives it replaces instead, at any distance. |

| Detail level residency rule | Value |
| --- | --- |
| Base level | Each primitive's coarsest level loads with its mesh and stays resident while the mesh does. |
| Finer levels | Each primitive holds at most one finest resident level R, and every level from R down to its coarsest, with no gaps. Primitives of one mesh hold their levels independently. |
| Wanted level | A primitive's wanted level is the finest level any of its instances wants this frame. |
| Loading | While a primitive's wanted level is finer than R, its levels from R − 1 down load and replace the finer levels it held before, one level at a time. A mesh loads the primitives that want more together, at most one such load at a time. |
| Release | When a primitive's finer levels don't fit the geometry capacity, the primitive whose finer levels no instance has wanted for the longest releases them all and goes back to its base level, and the load tries again once that room frees. Levels an instance wanted in the last frame, and base levels, are never released. |
| No room | When nothing can be released, the load waits and tries again on a later frame. Instances keep drawing their finest resident level. Other primitives of the same load that fit become resident. |

| Meshlet drawing rule | Value |
| --- | --- |
| Culling | Each view culls every meshlet of an instance it may show: by the view's frustum, by the meshlet's normal cone unless the material is double-sided, and, for the camera, by occlusion. The meshlets of a skinned instance that receives poses are never culled. |
| Culling groups | Meshlets are culled 32 at a time. An instance that draws more than 8 meshlets has groups of its own, one for each 32 of its meshlets. The meshlets of smaller instances fill groups together, in instance order. |
| Shared draws | The meshlets a group keeps are drawn together while they fit: consecutive kept meshlets share one draw of up to 128 vertices and 252 triangles, two full meshlets. They may belong to different instances, and to different views of one shadow batch. A meshlet that doesn't fit starts the next draw. |
| Capacity | Each culling group of a large instance, and each meshlet of a small one, takes one of the `render.instances.meshlet-group-capacity` groups. |
| Meshlet vertices | With `render.geometry.meshlet-vertices` on, the camera and shadow passes draw each meshlet from its own copy of its vertices' positions and UVs. A position there is rounded to 16 bits on each axis within its detail level's bounding sphere, so it lies within the sphere's radius over 65,535 of the vertex. Shading, rays, and lightmaps read the exact vertices. An instance that receives poses is drawn from its own posed vertices. |

`render.directional-shadows.technique` selects how directional lights cast
shadows: `cascades`, the default, follows the rules below, and `virtual`
follows [virtual shadow maps](#virtual-shadow-maps).

| Directional shadow rule | Value |
| --- | --- |
| Cascades | Four, splitting the range from the camera to `render.directional-shadows.distance` by the split blend between logarithmic and even. |
| Fitting | With receivers fitting, each cascade shrinks to the surfaces the camera sees, after two small depth passes. With frustum fitting, it covers the whole slice without them. |
| Stability | Each cascade is the smallest light-space square around its slice, padded by 17 texels, rounded in 8 steps per doubling, and snapped to a world-fixed texel grid. Casters start 100 m toward the light. |
| Casters | A cascade draws an instance only when its bounding sphere is at least 32 of the cascade's texels across. An instance is measured by its primitive's caster radius: the radius of its bounding sphere, or for a [cluster mesh](/docs/reference/levels#merged-placements) the radius of its largest copy, not the sphere around all of them. Skinned instances always draw. Cone and point maps draw instances of every size. |
| Holding a receiver | A cascade holds a receiver that lies inside its square, at least 10 texels from its edge, and inside its depth range, from where its casters start to its far side, give or take one depth step of 1/65535. With receivers fitting, a cascade's far side is the surface farthest from the light that the camera sees in that cascade's slice, so a cascade often doesn't hold a receiver of another slice. |
| Beyond the last cascade | No sun shadow. |
| Receiver | The surface point, moved off its triangle along the triangle's normal on the sun's side by sin θ texels of the cascade it's tested in, where θ is the angle between that normal and the direction toward the sun. |
| Receiver plane | Each filter tap compares the stored depth with the depth of the receiver's triangle plane at the tap's texel center, moved toward the sun by 1.5 depth steps of 1/65535 per cascade, from cascade 0 at 1.5 to cascade 3 at 6. Where the sun is within about 3° of the plane, the plane's depth changes across the map as it would at that angle, a slope of 20. |
| Proven receivers | A receiver's occluders are searched in the 4 × 4 cells of 8 × 8 texels around it. The receiver is lit, with no texel of the map read, when no cell's nearest depth rises above the receiver's plane at the cell's center by more than the plane's depth change over 4 texels along each map axis, added. It's shadowed when every cell's farthest depth lies above the plane's highest point within those 4 texels. An occluder that rises less than that above the plane in every cell, one whose shadow would be about 4 texels long or shorter, such as a curb, therefore casts no shadow-map shadow on the receiver; [contact shadows](#contact-shadows) cover the first `render.contact-shadows.distance` of it. |
| Penumbra width | On each side of an occluder's edge, the occluder's distance above the receiver along the light times the tangent of the light's angular radius. |
| Penumbra cascade | Among the cascades from the receiver's own up to the one after the cascade its occluders are searched in that hold the receiver, the one where the penumbra's width w, in its texels, makes the larger of 2 / w and w / 6 least; the lower-numbered one where two tie. A penumbra of no width counts as 0.1 millimeters. |
| Penumbra filter | A tent over every texel whose center lies within the radius of the receiver on both axes. The radius is the penumbra's width in the penumbra cascade's texels, at least 2 and at most 8. Each texel weighs the radius less its center's distance from the receiver, on each axis, and the weights are normalized to sum to 1. |
| Cascade fade | The candidates split at a width of √12 texels, where 2 / w and w / 6 are equal: those narrower and those at least that wide. Where the best candidate of the other side than the penumbra cascade's has less than 1.5 times the penumbra cascade's larger of 2 / w and w / 6, the result mixes the two cascades' results. The penumbra cascade's share is that ratio less 0.5: half where the two are equal, all of it at 1.5. Candidates on the penumbra cascade's own side never mix with it. |
| Blended receivers | A blended surface is a receiver like an opaque one: the same search, proofs, penumbra filter, and cascade fade, at the surface the transparent phase draws. It gets no [contact shadow](#contact-shadows). |

### Terrains

A renderable terrain names a [`Terrain` resource](/docs/reference/terrain) and
draws some of its nodes, each as a renderable of the node's mesh at the
terrain entity's transform. Which nodes it draws follows the first sink's
camera, as detail levels do.

| Terrain rule | Value |
| --- | --- |
| Camera | The first sink's camera position, carried into terrain space by the inverse of the terrain's transform. |
| Distance | The straight-line distance in terrain space from the camera to the nearest point of a node's bounds; zero inside them. |
| Allowed error | The detail levels' allowed error at that distance, in terrain units: the error per distance times the distance times the transform's smallest axis scale, plus the constant error, divided by its largest axis scale. |
| Refined | The root is wanted. A wanted node with children is refined when its error is larger than its allowed error, and then its children are wanted instead of it. |
| Wanted balance | While a wanted, unrefined node borders, on the other side of an edge, a refined node of its own level whose child along that edge is refined, the wanted node is refined too. |
| Requests | Every wanted node's mesh is requested, refined or not. |
| Covered | A node is covered when its mesh is resident, or when it has children and every child is covered. Nothing draws until the root is covered. |
| Drawn | From the root, a covered node draws its children by this rule when it's refined and every child is covered, or when its mesh isn't resident; otherwise it draws itself. So a node keeps drawing until its children can replace it, and finer nodes keep drawing until a coarser node that replaces them is resident. |
| Drawn balance | While a drawn node borders, on the other side of an edge, a node of its own level whose child along that edge draws its own children, and that child's mesh is resident, the child draws itself instead. Seams whose closing meshes aren't resident yet can show gaps until they load. |
| Release | A node's mesh is released after 120 frames in which no terrain of that resource wanted or drew it, unless it's the root, or a renderable still draws it. A released mesh loads again when it's wanted. While the pipeline traces rays, no terrain node mesh is released. |
| Node renderables | Each drawn node is a renderable of its own, with the detail levels, culling, shadows, and ray tracing of any renderable. Material parameters set on the terrain entity don't reach them, and they have no lightmap. |
| Transform | A change to the terrain entity's transform moves every node it draws. Deleting the entity removes them. |

### Shadow maps

Every shadow-casting light draws from one memory budget,
`render.shadow-maps.budget-mb`, 128 MiB by default. With virtual shadow maps,
directional lights take nothing from it: their pages come from their own
[page pool](#virtual-shadow-maps).

| Light | Shadow map | Cost |
| --- | --- | --- |
| The first directional light, with cascades | Four cascades of 2,048 texels per side by default, 16-bit depth | 32 MiB at the default resolution |
| A cone light | One map of its size class, 16-bit depth | 32 KiB to 8 MiB |
| A point light | A cube map of six faces of its size class, 16-bit depth | 192 KiB to 48 MiB |

A cone map or point cube face takes one of five sizes, its size class:

| Size class | Texels per side | Cone map | Point cube map |
| --- | --- | --- | --- |
| 0 | 128 | 32 KiB | 192 KiB |
| 1 | 256 | 128 KiB | 768 KiB |
| 2 | 512 | 512 KiB | 3 MiB |
| 3 | 1,024 | 2 MiB | 12 MiB |
| 4 | 2,048 | 8 MiB | 48 MiB |

A light's span is its shadow range's projected diameter, in pixels, in the sink
where it looks largest. A light whose range contains a sink's camera spans that
sink's larger side. A cone light needs the span in texels per side, and a point
light half the span. The light takes the smallest class with at least that many texels, up to class 4. A light
moves to a larger class as soon as it needs one, and to a smaller class only once
it needs fewer than three quarters of that class's texels.

The first directional light is placed first, then cone and point lights in
order of the screen area they cover, each at the cost of its size class, then
any other directional lights. A light that doesn't fit stays lit without
shadows, with one warning in the log. At most `render.lights.directional.max` directional lights, 1 by default and 4 at most, 16 cone lights, and 16 point lights hold shadow maps at once. With virtual shadow maps, one directional light does.

### Shadow map updates

A shadow map isn't drawn again every frame. Each frame draws a set of updates
chosen within an update budget, `render.shadow-maps.update-texels`, 10,485,760
texels by default: two and a half cascades at 2,048 texels per side. One update
draws one of these:

| Update | Texels |
| --- | --- |
| One cascade of a directional light | The cascade resolution squared, 4,194,304 at 2,048 texels per side |
| One cone map | Its size class's texels per side squared |
| One face of a point light's cube map | Its size class's texels per side squared |

With virtual shadow maps, directional lights have no cascades to update:
their pages stay cached instead, and every update is a cone map or a point cube
face.

Every frame draws cascades 0 and 1 of every shadowed directional light. Their
texels count against the budget first, even when they exceed it. Every other
update is a candidate: cascades 2 and 3, cone maps, and point cube faces. The
candidates share what's left of the budget, plus the budget that earlier frames
carried over.

Candidates are ordered in three tiers:

1. Maps that haven't been drawn yet.
2. Maps whose view changed since they were drawn: the light moved, turned, or
   changed its shadow range, or, for a cascade, the camera or the sun moved it.
3. Every other map.

Within a tier, candidates are ordered by age times importance, highest first.
Age is the number of frames since the map was drawn. Importance is the largest
number of sink pixels the light's shadow range covers in any sink, and for a
cascade, the pixel count of the largest sink. Candidates draw in that order
while their texels fit in what's left of the budget. A candidate that doesn't
fit is skipped, and later candidates can still draw.

The texels the candidates leave unspent carry over to the next frame, up to the
texels of the largest candidate. A candidate that doesn't fit this frame draws
once enough has carried over. With the default budget and one shadowed
directional light, half a cascade is left each frame, so one of cascades 2 and 3
draws every other frame, and each one every fourth frame.

When no candidate fits, the first one draws anyway, past the budget, if it
hasn't been drawn yet, or if cascades 0 and 1 take the whole budget, so that
nothing carries over. A frame that draws past the budget carries nothing over.

Until a map has been drawn, its light is lit without that shadow. A map that
isn't drawn this frame keeps the view it was drawn with, and receivers sample
it with that view. A receiver that a cascade's drawn view doesn't hold uses the
next coarser cascade that holds it, and gets no shadow from that light when none
does. A new map, a map in a new size class, and every map of an image that
changed size count as not yet drawn.

A light keeps its map, at the same place in its class's image, for as long as it
stays selected in the same size class. A light that changes class gets a new
map. The image of each class grows when the class needs more maps than it holds,
and shrinks only when the budget needs its memory. An image that changes size
loses every map it holds.

### Virtual shadow maps

With `render.directional-shadows.technique` set to `virtual`, the first
directional light casts shadows through a virtual shadow map, and other
directional lights cast none. Its shadow is a clipmap of 16 levels around the
first sink's camera. Each level is a map of 4,096 × 4,096 texels, split into
32 × 32 pages of 128 × 128 texels. Only the pages that receivers need hold
depth, in memory taken from one page pool, and a page keeps its depth across
frames until something changes it.

| Virtual shadow map rule | Value |
| --- | --- |
| Levels | 16. Level l spans `render.directional-shadows.first-level-size` × 2<sup>l</sup> meters per side, 4 m by default, and its texels measure that span over 4,096. |
| Placement | Each level looks along the direction the light travels. It's centered on the first sink's camera across the light, snapped to whole pages, and its depth range reaches 1,000 m toward the light and 1,000 m away from it, from the camera's position along the light. |
| Depth | 32-bit, larger toward the light: depth in 0 through 1 times 4,294,967,040, truncated. |
| Reach | A receiver farther than `render.directional-shadows.distance` from the camera gets no sun shadow and needs no pages. |
| Receiver level | ceil(log<sub>2</sub>(d × b / (0.4375 × s))), held between 0 and 15, where d is the receiver's distance from the camera, s the first level's size, and b `render.directional-shadows.level-bias`. |
| Needed pages | Each opaque receiver of the first sink needs, in its level and in the next two coarser levels up to level 15, every page holding a texel within 16 texels of the receiver on both axes. |
| Page pool | `render.directional-shadows.pool-pages` pages, 4,096 by default, at 64 KiB each. A needed page without depth takes a free page, then a page no receiver needed this frame. When none is left, it stays without depth this frame and is needed again the next. |
| Cached pages | A page keeps its depth until its level moves so that the page leaves the level's square; the light's direction changes, which empties every page; an instance whose bounding sphere, before or after, reaches into the page appears, disappears, moves, changes the detail level it draws, or becomes drawable; or another page takes its memory. A skinned instance's pose doesn't empty a page. A page without depth is drawn again in the frame a receiver needs it. |
| Depth across moves | A page's depth holds while the camera moves along the light: receivers compare against it from where its level stood along the light when the page was drawn. |
| Casters | Opaque and masked instances, at least 32 of the level's texels across. Masked instances cast as if opaque. |
| Holding a receiver | A level holds a receiver that lies at least 26 texels inside its square, so everything the sampler reads lies inside it, within its depth range, and whose needed pages in that level all hold depth. |
| Receiver's level | The first level, from the one the receiver level rule gives up to two coarser, that holds the receiver. When none does, the receiver gets no sun shadow. |
| Search level | The first level, from the receiver's, where the penumbra of an occluder 2 m above the receiver spans at most 12 of its texels and that holds the receiver; otherwise the receiver's level. |
| Receiver, penumbra width, penumbra filter | As for cascades, with the level in the cascade's place. |
| Receiver plane | As for cascades, but moved toward the sun by 5 mm plus half a texel of the level. |
| Penumbra level | Among the receiver's level and the next two coarser levels that hold the receiver, the one where the penumbra's width w, in its texels, makes the larger of 2 / w and w / 6 least; the lower-numbered one where two tie. A penumbra of no width counts as 0.1 millimeters. |
| Level fade | As the cascade fade, between the penumbra level and the best candidate on the other side of √12 texels. |
| Blocker search and probes | Read cells of 8 × 8 texels within 12 texels of the receiver, each holding its texels' depth nearest and farthest from the light. The receiver is fully shadowed when every cell's farthest depth lies above its plane's highest point over the cells, and fully lit when no cell's nearest depth reaches its plane's lowest point. Otherwise the occluders' height is the mean of the nearest depths of the cells that rise above the plane at their centers. |
| Transparent receivers, fog | No sun shadow. |

### Contact shadows

Contact shadows darken where visible geometry blocks a short ray toward a
shadowed sun, which the shadow map is too coarse to resolve, such as under a
foot on a floor. `render.contact-shadows.enabled` turns them on, and
`render.contact-shadows.distance` sets the ray's reach.

| Rule | Value |
| --- | --- |
| Rays | One per pixel of every opaque surface and each shadowed sun the surface faces, from the pixel's depth toward the sun, at most the reach in world units and 64 pixels on screen. |
| Facing | A surface faces a sun when the sun lies on the camera's side of the plane through the pixel's depth and its neighbors' depths. A surface that faces away casts no ray and gets no contact shadow from that sun. |
| Samples | One per pixel the ray crosses on screen, at least 1 and at most 16, evenly spaced along the ray and moved by the march offset. |
| Blocking | A ray is blocked where it passes less than 5 cm plus 2 % of its depth behind the depth of another surface. Blocks past half the reach count less, down to none at its end. |
| March offset on frame k | Interleaved gradient noise at the pixel p + 5.588238 × j on both axes, where j is the [blue noise](#blue-noise) slice for frame k. |
| Filter | The mean of the 3 × 3 pixels around the pixel, each weighed by 1 − e / 0.02, held to 0 through 1, where e is the distance of its depth from the pixel's surface plane relative to the pixel's depth. Without a weight above 0, the shadow map alone shadows the pixel. |
| Result | The sun's shadow-map visibility times the filtered contact visibility. |

### Materials

The pipeline accepts a material whose render model is `Visibility` with the
`MaterialEvaluation` pass, which is what every `.bema` file and imported model
bakes to. Its surface code is generated from the material's
[BEMX graph](/docs/reference/bemx): into the material's own evaluation shader
in `pipelines` mode, and into the shader of its phase and kind in `uber` mode.

| Rule | Value |
| --- | --- |
| Alpha mode | Opaque, masked with a cutoff, or blended; see [alpha modes](/docs/reference/bema#alpha-modes). Blended materials draw in the transparent phase. |
| Masked coverage | The masked visibility and shadow passes evaluate each masked material's `opacity` in one coverage shader per pass kind, which holds one arm per distinct program and set of static values, in both evaluation modes. A masked material is drawn once both coverage shaders hold its arm, with the same development and release rules as uber `Coverage`. |
| Masked cutoff | The masked visibility pass covers a pixel when s ≥ n, for s = (o − t) / max(fwidth(o), 0.0001) + 0.5, the material's `opacity` o and `alpha_cutoff` t. The noise n is the first channel of the [blue noise](#blue-noise) while the scene's first sink is [jittered](#jitter), and 0.5 otherwise, which covers exactly the pixels where o ≥ t. Under jitter, a pixel within about one pixel's change of opacity of the cutoff is covered on a share of frames that grows with s, so the temporal blend shows partial coverage. The masked shadow passes always cover where o ≥ t. |
| Double-sided | Draws without back-face culling, in the visibility and shadow passes. |
| Mirrored | An instance whose [transform mirrors it](/docs/reference/world#transforms) culls the same faces as when it isn't mirrored, in the visibility and shadow passes. |
| Variables | Programs that differ only in textures or dynamic values share one pipeline and one dispatch; each distinct set of static scalar and vector values takes its own. Texture variables take slots in declaration order, up to 16. Dynamic values number at most 16384 in all, counting every loaded material's and every entity's own. |
| Layers | Every material evaluation shader takes the scene, visibility buffer, material evaluation, and directional shadows layers, and every closest-hit shader the scene and ray-traced scene layers. |

`render.material-evaluation` chooses how material evaluation runs. Both modes
shade every pixel with the same surface and lighting:

| Mode | Shaders | Work per phase |
| --- | --- | --- |
| `pipelines` | One evaluation shader per material program, specialized per set of static values | The material prepasses list each pipeline's pixels, then each pipeline shades its list. |
| `uber` | One shader per phase and kind that holds every material variant of that phase and kind in the bake as one arm | One pass over the sink in 8 × 8-pixel tiles for each shader the frame uses, without material prepasses. |

| Uber rule | Value |
| --- | --- |
| Kinds | Each phase has two shaders: one for [translucent materials](#translucent-materials) and one for the rest. A material has an arm in exactly one of the four. |
| Arms | One per distinct program, set of static values, phase, and kind. Variants that differ only in textures or dynamic values share an arm. |
| Coverage | A material is drawn once the published shader of its phase and kind holds its arm. A development build bakes the shader again when a material baked after it arrives, because the stored materials are an input of the shader; a release build logs one error for each material missing from the bake and doesn't draw it. |
| Background | The opaque pass of the materials that aren't translucent writes zero to `Lit`, and to `Diffuse Radiance` when the project builds SSGI in, at every pixel no opaque surface covers. It runs every frame. |
| Unused shaders | A shader other than the one that writes the background runs only in a frame that draws an instance whose material has an arm in it. |
| Baked shaders | Material resources keep their graph instead of an evaluation shader. Every bake assembles the four shaders last, from every material variant in the store, and skips a shader whose materials didn't change; they have no asset of their own. Changing the mode makes every material stale, so the next bake processes them. |

The evaluation shader writes the graph's surface into these properties. A surface
input the graph leaves out takes its [BEMX default](/docs/reference/bemx#surface),
and a graph without a normal keeps the geometric one:

| Property | Type | Default |
| --- | --- | --- |
| `albedo` | Four half floats: the base colour, then the opacity, which is alpha in the transparent phase | 0.8, 0.8, 0.8, 1 |
| `normal` | Three half floats in tangent space | 0, 0, 1, meaning no normal map |
| `metalness` | Half float | 0 |
| `roughness` | Half float | 0.5 |
| `occlusion` | Half float, multiplying indirect diffuse light | 1 |
| `emission` | Three half floats, added to the diffuse light | 0, 0, 0 |
| `translucency` | Three half floats, in translucent materials only | 0, 0, 0 |
| `subsurface_radius` | Three half floats, meters, in subsurface materials only | 0, 0, 0 |

Lights reflect off a surface as if its roughness were at least 0.045, so the
highlight of a smoother surface, such as calm water, stays finite. Reflected
environment and screen-space light use the roughness as written.

The surface's world-space normal is converted to the tangent frame. A BEMX
`image` node samples its texture at its coordinates with the level of detail
their change across the pixel selects: the derivatives the pipeline computed
for the vertex UV, or the [measured change](/docs/reference/bemx#values-and-geometry)
of coordinates the graph computes. A closest-hit shader sizes both from the
ray's footprint. Writing a normal or reading the tangent or bitangent makes the
pipeline build the tangent frame for that material, and sampling a texture at
the vertex UV or reading texture coordinates makes it reconstruct the UV.

A BEMX `time` node reads the frame clock's elapsed time in seconds, the clock
every pipeline manager receives for the frame. Every pass of a frame reads the
same time.

### Translucent materials

A material whose graph sets the BEMX
[`translucency`](/docs/reference/bemx#surface) input is translucent, whatever
value the input computes. Its evaluation shader lights the surface from both
sides. No other material's shader holds that code: in `pipelines` mode each
material has its own shader, and in `uber` mode translucent materials have a
shader of their own in each phase.

The far side of a surface is the side its shading normal points away from. A
double-sided surface's normal points to the viewer's side.

| Light | On a translucent surface |
| --- | --- |
| A light on the near side | Lights the surface as it does any other. |
| A light on the far side | Adds diffuse light and no specular light. The diffuse light is the near side's, with `translucency` in place of the base color and the angle the light makes with the far side in place of the angle with the near side. |
| Shadows | A light on the far side is shadowed by what lies between it and the surface, as a light on the near side is. The surface doesn't shadow itself. |
| Environment | The surface adds the environment's irradiance on its far side, weighted as indirect diffuse light is, with `translucency` in place of the base color, whichever source lights the near side. |
| Other indirect diffuse light | Screen-space and ray-traced indirect light and lightmaps light the near side only. |
| Ray tracing | Rays that hit the surface read no `translucency`. |

A graph that sets BEMX `thickness` is translucent with a `translucency`, in each
channel, of `base_color` times the share of light that crosses the thickness
`t` under that channel's [scattering profile](#subsurface-scattering):
`¼·e^(−t/d) + ¾·e^(−t/(3d))`.

### Subsurface scattering

A material whose graph sets BEMX
[`subsurface_radius`](/docs/reference/bemx#surface) is a subsurface material
when `render.subsurface.enabled` was `true` at startup. Otherwise, and in the
transparent phase, it shades as if it didn't scatter.

Light spreads under the surface along Christensen and Burley's normalized
diffusion profile. For a channel with albedo `A`, the `base_color` channel, and
mean free path `ℓ`, the `subsurface_radius` channel, the light that leaves the
surface a distance `r` from where it entered is:

| Term | Value |
| --- | --- |
| Shape | `s = 1.85 − A + 7·|A − 0.8|³` |
| Scale | `d = ℓ / s` |
| Profile | `R(r) = (e^(−r/d) + e^(−r/(3d))) / (8π·d·r)`, which integrates to one over the plane |

| Rule | Value |
| --- | --- |
| Scattered light | The diffuse light the surface receives: indirect, environment, and direct light, and the light crossing a translucent surface. Emission, specular light, reflections, and transmission don't scatter. |
| Color | The scattered light is weighted by the square root of `base_color` where it enters and again where it leaves, so each pixel's diffuse light is `√A` times the profile-weighted average of `√A` times the light received around it. |
| Neighbors | Light spreads between pixels of subsurface materials only. Pixels of other materials, and the background, neither give nor take scattered light. |
| Distance | `r` is the distance in view space between the two surface points, depth included, so light crosses a step in depth only as far as the profile allows. |
| Samples | The pass reads 32 points around each pixel. While the sink is [jittered](#jitter), each pixel turns the pattern by 2π times the first channel of the [blue noise](#blue-noise); otherwise the pattern is the same every frame. The pattern spreads them where the profile of the channel with the largest `d` is largest, out to the radius that holds 99.7 % of its light. |
| Radius of zero | A pixel whose largest `d` covers less than one pixel keeps its own diffuse light. |
| Normalization | Each pixel's result is divided by the sum of its samples' weights, so a surface lit evenly keeps its brightness. |
| Ray tracing | Rays that hit the surface read no `subsurface_radius`; GI shades the surface as if it didn't scatter. |

### Ambient occlusion

GTAO, Jimenez and others' ground-truth ambient occlusion, estimates two values
for each opaque pixel from the depth around it: its visibility, the
cosine-weighted fraction of the hemisphere around its normal that nearby
geometry leaves open, and its bent normal, the mean direction of that open
part.

| Rule | Value |
| --- | --- |
| Resolution | GTAO evaluates and filters at half the sink's size. Material evaluation reads the visibility at full size, and the bent normal filtered from the half-size image. |
| Slices | `render.gtao.radial-rays` directions split into half as many slices. Each slice is the plane through the view direction and one screen direction. Each pixel turns its slices by its own angle, up to the spacing between them, and offsets its samples along each side by its own fraction of a step; both come from the [blue noise](#blue-noise) at the half-size image's pixel. |
| Horizons | Each slice finds the highest horizon on either side of the pixel among `render.gtao.samples-per-ray` depth samples per side, within `render.gtao.radius` world units. A sample's horizon fades to the lowest one, the surface's own tangent, over the outer 61.5 % of the radius. A horizon never drops below the tangent. |
| Visibility | The slices' horizon arcs, integrated against the cosine around the normal and averaged, weighted by the length of the normal's projection onto each slice. |
| Bent normal | The slices' arcs integrated against their direction, summed with the same weights and normalized. It lies within a quarter turn of the view vector, since every slice's visible arc holds the view vector. At a pixel where GTAO finds no surface normal in the depth, the bent normal is the view vector. |
| Small radius | As the radius shrinks below 4 half-size pixels, the occlusion and the bent normal's tilt away from the normal fade to none. |
| Sky | Pixels with no geometry have a visibility of 1. |

### Reflections

An opaque pixel reflects the environment and, below a roughness of 0.4, the
screen around it. Light a screen-space reflection finds carries its own
occlusion. Two terms, multiplied together, dim the environment's reflection:

| Term | Value |
| --- | --- |
| Specular occlusion | The fraction of the reflection's lobe that falls inside the visibility cone, Jimenez and others' cone-cone approximation. The visibility cone is centered on the pixel's bent normal and has a cosine of `√(1 − v)`, where `v` is the pixel's environment visibility, as [indirect diffuse light](#indirect-diffuse-light) defines it. The reflection's lobe is a cone around the mirror direction with a cosine of `2^(−3.32193·α²)`, where `α` is the roughness squared, at least 0.01. The fraction is the cones' intersection, by the smoothstep fit of their solid angles, divided by the lobe's solid angle. Without GTAO, the bent normal is the shading normal. |
| Horizon occlusion | `clamp(1 + 1.3 · dot(R, Ng), 0, 1)²`, Russell's fit, where `R` is the mirror direction of the shading normal and `Ng` the geometric normal. A shading normal that tilts the mirror direction toward or below the surface, as a normal map does near creases and silhouettes, fades the reflection to nothing at 0.77 below the surface's plane. |

A mirror direction that points below the geometric surface finds no
screen-space reflection, only the faded environment.

### Indirect diffuse light

One source lights the indirect diffuse light of a frame's opaque surfaces:

| Source | Lights the frame when |
| --- | --- |
| Surfel GI | `render.gi.enabled` is `true`, `render.gi.technique` is `surfels`, the device traces rays, and the surfel GI pipelines have compiled, the one that shades its rays included. |
| Probe GI | `render.gi.enabled` is `true`, `render.gi.technique` is `probes`, the device traces rays, and the probe GI pipelines have compiled, the one that shades its rays included. |
| Lightmaps | `render.gi.enabled` is `true`, `render.gi.technique` is `baked`, and `render.baked-gi.enabled` was `true` at startup. Each opaque pixel of an instance that a resident lightmap lights reads it; every other pixel is lit as under None. |
| SSGI | `render.gi.enabled` is `true`, `render.ssgi.enabled` was `true` at startup, and either `render.gi.technique` is `ssgi`, or it's `surfels` or `probes` and that technique doesn't light the frame. |
| None | None of them does. The environment alone lights indirect diffuse light, darkened by GTAO when it runs. |

| Rule | Value |
| --- | --- |
| Images | The source writes `Indirect Diffuse History` and `Indirect Diffuse Normals`, which material evaluation reads. Material evaluation writes `Diffuse Radiance`, which SSGI rays read in the next frame, only in a frame that SSGI lights. |
| SSGI history | SSGI reads its history only after a frame it lit at the same sink size. Its first frame after a frame it didn't light starts without history. |
| Environment light | Material evaluation adds the environment's irradiance around each opaque pixel's normal, times the environment's intensity and the pixel's environment visibility: the smaller of one minus the source's hit fraction and GTAO's visibility, each when it ran. Under surfel GI or probe GI, and at a pixel a lightmap lights, it adds none: their light holds the environment's light their rays reached. The environment visibility also dims the environment's reflections. |
| Small-scale occlusion | Under surfel GI or probe GI, and at a pixel a lightmap lights, the source's light already holds the occlusion its rays found: the share of them that reached the environment, one minus the hit fraction, or a lightmap's alpha. When GTAO runs, material evaluation multiplies the source's light at each opaque pixel by GTAO's visibility divided by that share, at most one. GTAO darkens the light only where it finds more occlusion than the source did, and never where no ray reached the environment. |
| Surfels | At most `render.surfel-gi.surfel-capacity` surfels live at once, and they trace at most `render.surfel-gi.ray-budget` rays a frame. |
| Probes | Probes trace at most `render.probe-gi.ray-budget` rays a frame, 128 for each probe they update. |
| Baked shaders | Material shaders keep the indirect diffuse read while any source is built in, the diffuse radiance write while SSGI is, and the lightmap read while lightmaps are. Materials have closest-hit shaders while surfel GI, probe GI, or lightmaps are built in. |

### Surfel GI

Surfel GI keeps surfels: small world-space discs on the surfaces the camera
sees. A grid around the first sink's camera lists the surfels that overlap each
of its cells, and every sink that surfel GI lights reads the surfels listed
around each of its pixels.

| Term | Definition |
| --- | --- |
| Surfel | A disc with a world-space position, a normal, and a radius, held in one slot of a pool of `render.surfel-gi.surfel-capacity` slots. |
| Radius | 0.24 meters, times the surfel's distance from the first sink's camera divided by 3.2 meters when that ratio is above one. |
| Grid | 8 cascades of 32 × 32 × 32 cells, centered on the first sink's camera and snapped to whole cells of cascade 0. A cell of cascade `c` measures 0.2 × 2<sup>c</sup> meters, and a position falls in the finest cascade that covers it. |
| Disc distance | A point's distance from a surfel's center, times one plus twice the point's distance from the surfel's plane in meters. |
| Cell list | The surfels whose disc distance to some point of the cell can be below 1.25 times their radius. A surfel near a cascade boundary is listed in both cascades. A surfel is listed in at most 32 cells: the cells it reaches fall into 8 shells by how near their nearest point lies, as a share of 1.25 times its radius, and it's listed in the nearest shells whose cells number at most 32 together. A list starts with the surfels whose disc distance to the cell's center is below 0.625 times their radius, then lists the rest; the order within each part can change from frame to frame. |
| Coverage | The sum, over the surfels listed in a pixel's cell, of a weight that falls smoothly from one at the surfel's center to zero at a disc distance of 1.25 times its radius, times the cosine between the surfel's and the pixel's normals. |
| Bounce | Zero for a surfel a pixel spawned, and one for a surfel a ray's hit spawned. |

| Rule | Value |
| --- | --- |
| Spawn | Each 16 × 16-pixel tile of each sink spawns at most one surfel in each frame its pixels gather, at its least covered pixel. A pixel is a candidate when its coverage is below 0.1, its second-largest weight below 0.4, its cell lists fewer than 48 surfels, and a random draw passes with a probability that grows with its view depth. The new surfel takes the pixel's position and normal. When surfels whose trust is one and that face within 26 degrees of the pixel's normal light the pixel, the new surfel starts with the light of the one with the largest weight, worth 32 rays. |
| Hit spawns | A front-face hit on a surface whose albedo isn't black asks for a surfel when the sum of the weights times the visibilities of the surfels it reads is below 0.1, its cell lists fewer than 48 surfels, and the surfel whose ray found it has a bounce of zero: the first such hit in each cell a frame, and at most 64 hits a frame. Each request spawns a surfel with a bounce of one at the hit's position and normal, without light, while the surfels with a bounce of one make up less than a quarter of the live surfels, as the frame's grid counted them, and the slots in use less than three quarters of the pool. |
| Votes | In each frame it gathers, a pixel votes 5 for every surfel of its own cell that faces it within 37 degrees while the cell lists at most 48 surfels, and 2 for the surfel with the largest weight in its blend when that weight is above 0.05; when that weight is more than half of the blend's, the pixel votes 50 plus 50 times that share instead. A ray's hit votes for the surfel around it whose light reaches it most: 50 times that light's pre-exposed luminance, at most 50, when the luminance is above 0.01. A surfel keeps the strongest vote it got since the last frame. |
| Despawn | Each tile kills at most one surfel in each frame its pixels gather: the heaviest at its most covered pixel, when that pixel's coverage passes 3.5 and its second-largest weight passes 0.9. Both thresholds fall to 3.0 and 0.8 as the cell fills from 36 toward 48 surfels. |
| Aging | Each frame, a surfel ages by one frame plus its cell's rent, less its vote, and never gets younger. The rent is one frame for every 10 surfels the cell lists beyond 48, plus the square of those extra surfels over 32 once the cell lists more than 96. |
| Recycle | A surfel 500 frames old goes back to the pool. |
| Validation | Every 8 frames, each surfel traces a ray along its normal that crosses its plane, from 0.25 times its radius above the point its rays leave from to as far below its center. A hit marks the surfel supported, and a supported surfel whose ray finds no surface dies. |
| Burial | A surfel that received 32 rays and whose rays hit back faces more than half the time lately dies. Its share moves toward each update's share of back-face hits by the update's rays over the update's rays plus 16. |
| Rays | Each frame, a surfel with a bounce of zero asks for 32 rays until it has received 512, then 16 while its estimate's inconsistency is above 0.3, and 4 otherwise; a surfel with a bounce of one asks for 4. Requests for 32 or 16 rays form the priority class, the rest the regular class. Each class traces a window of its asked rays that starts where its last window ended, so the surfels in it take turns: the priority class up to three quarters of `render.surfel-gi.ray-budget`, or more while the regular class asks for less than the rest, and the regular class the rest of the budget. |
| Ray paths | A ray leaves from 0.01 times the surfel's radius above its center, but at least 0.5 millimeters and at most 1 centimeter, and reaches 10 kilometers. Its direction comes from the surfel's guide for a share of the rays that grows from 0 to 0.5 over the surfel's first 192 rays once the guide holds light, and from the cosine-weighted distribution otherwise. A guided direction is random. Cosine-weighted directions follow the R2 low-discrepancy sequence, rotated per surfel, at the point the surfel's received rays have reached. |
| Guide | Each surfel splits its hemisphere into 8 × 8 cells of equal solid angle, through the concentric map of the unit square onto the disk and the disk's equal-area lift onto the hemisphere. Each ray moves the four cells around its direction, by their bilinear shares, 2% of the way toward the pre-exposed luminance of the light it brought back times the cosine of its direction. A guided ray picks a cell in proportion to the cell's share of the guide, then a uniformly random direction inside the cell. |
| Radial depth | Each surfel splits its hemisphere into 4 × 4 cells of its octahedral projection, turned 45 degrees to fill the unit square, each holding the first four moments of the distance its rays went there. A ray counts its distance up to twice the surfel's radius, and a miss counts as twice the radius. It moves its cell 5% of the way toward its own moments when it ends nearer than the cell's mean, and 1% otherwise; a cell no ray reached yet takes the first ray's moments. |
| Hit surfaces | A ray hits the [ray-traced scene](#ray-traced-scene). The hit's material reports its diffuse albedo, the base color times one minus the metalness, and its emission, with texture levels that cover a cone widening by 0.31 radians along the ray. A material reports black until its closest-hit shader has compiled, and when its bake has none. The back of a single-sided surface reports black. |
| Ray light | A miss brings back the environment's light from its direction: the environment's specular level prefiltered for roughness 2/7, times the environment's intensity. A back-face hit brings back its emission. A front-face hit brings back its emission, plus its albedo times what reaches it: each sun that it faces and that no geometry hides; each point and cone light it faces, within the light's reach, that no geometry hides, lit as material evaluation lights a surface but without the light's IES profile; and the light of the first 16 surfels its cell lists, as they were the frame before, each weighted by its weight, its visibility from the hit, and its trust, over the sum of their weights times their visibilities, but at least 0.1. A hit that no surfel around it sees gets the scene's lights alone. |
| Estimate | Each surfel estimates the average light its rays bring back, as irradiance over π, and the fraction of its cosine-weighted rays that hit, with the multiscale mean estimator. Toward the light, each ray counts with the cosine-weighted density of its direction over the density it was drawn from. Toward the hit fraction, each ray drawn from the cosine-weighted distribution counts once, and a ray drawn from the guide doesn't count; a frame whose rays all came from the guide leaves the hit fraction as it was. The estimate holds rays: each update adds its rays, and what it held fades by e<sup>−f/240</sup> over the f frames since its last update. Until the surfel has received 128 rays, an update's rays weigh evenly with the rays the estimate holds. Afterward, an update's average counts at most 0.1 plus eight deviations above the recent mean, in pre-exposed units, and the estimate moves toward it at the estimator's rate, but at least by the update's rays over the rays the estimate then holds. |
| Trust | A surfel's weight in lookups is the rays it received, plus the 32 of a parent whose light it started with, over 128, up to one. |
| Visibility | A point's visibility from a surfel, for a pixel or a ray's hit, bounds the share of the surfel's rays toward the point that end before it: the Hamburger four-moment bound of moment shadow mapping on the radial depth around the direction toward the point, read bilinearly between cells, with its shadow strengthened 1.2 times. Visibilities up to a bleed then count as zero, and the rest stretch over zero to one. The bleed is 0.2, plus 0.15 times the deviation of the cell's distances over their root mean square, plus 0.25 times that ratio times one minus the cosine between the direction and the surfel's normal. A point is fully visible when Cantelli's inequality puts at most 0.1% of the blended distances before it. It's also fully visible when every cell a ray reached would leave it fully visible alone, by that rule or because the four-moment bound finds no shadow at its distance. A point below a surfel's plane takes the direction on its horizon. |
| Gathering | The half-resolution pixels of each 16 × 16-pixel tile gather an estimate in every other frame: the frames whose index has the parity of the tile's column plus its row, counted in tiles. A pixel also gathers in any frame where its history, or the history of a pixel in the same GPU subgroup, holds a confidence below 4. |
| Pixel estimate | In each frame it gathers, each half-resolution pixel reads the first 64 surfels its cell lists. Its estimate blends their light and hit fractions, each weighted by its weight, its visibility, and its trust, over the sum of those products. Its confidence is that sum over the sum of the weights times the visibilities, or over one when that sum is less. A pixel hidden from every surfel that would light it takes no light and a hit fraction of one, with the confidence of the surfels that hide it, counted the same way. A pixel no surfel lights has neither estimate nor confidence. |
| Pixel history | Each pixel keeps a history of its light, its confidence, and the variance of its luminance. The previous frame's history comes from where the previous camera saw the pixel's surface: the four texels around that point, each where the previous frame's depth lies within 5% of the point's, weighted by its bilinear share times its normal's agreement, as for SSGI's history. An estimate more than 3 deviations from the history's luminance cuts the history's confidence, down to one at 8 deviations, as far as the estimate's confidence goes; the deviation counts the history's own, plus 0.05 times its luminance, plus 0.001. The history's confidence is then at most 16, and the pixel blends its estimate into it by their confidences. A pixel that doesn't gather keeps its history. |
| Pixel light | Material evaluation reads each pixel's history averaged with neighbors on a golden-angle spiral, after toning each light down by one over one plus its largest channel and back up after. A pixel reads 2<sup>4(1 − c)²</sup> taps, its own included, but from 2 to 8, within sqrt(16² + (2² − 16²) c) texels, where c is its confidence up to one. Each neighbor weighs by its confidence, a falloff along the spiral, its normal's agreement, and its distance from the pixel's tangent plane. Where the summed weights fall short of one, the light of the neighbors at a similar depth on any surface fills the rest. Where no tap of the spiral has any, the nearest of six rings around the pixel, of 32, 64, 128, 256, 512, and 1,024 texels with 8 taps each, that holds a tap with confidence fills it, each tap weighted by its confidence times its depth similarity plus 0.001. Where no ring holds any, the pixel takes no light and a hit fraction of one. |
| Limits | The grid lists each surfel in at most 32 cells, a pixel reads at most 64 surfels of its cell, and a ray's hit at most 16. A full pool spawns nothing until a slot is recycled. A sink spawns in at most 129,600 tiles, the tiles of a 7,680 × 4,320 sink; in a larger sink, the tiles past them spawn nothing. Rays' hits ask for at most 64 surfels a frame. |

The first sink records the frame-wide surfel stages, `surfel-grid`,
`surfel-trace`, `surfel-validate`, and `surfel-integrate`, after its light
clusters and before it draws the scene; every sink that surfel GI lights
resolves, spawns, and reconstructs its surfels' light inside its `screen-space`
stage.

### Probe GI

Probe GI keeps a volume of irradiance probes around the first sink's camera,
in the manner of dynamic diffuse global illumination. Each probe records
the light that reaches it from every direction and how far its rays went, and
every sink that probe GI lights reads the probes around each of its pixels.

| Term | Definition |
| --- | --- |
| Cascade | One of 4 windows of 24 × 12 × 24 probes along x, y, and z. Cascade `c` places its probes `render.probe-gi.spacing` × 2<sup>c</sup> meters apart, on the grid points from the first sink's camera's grid point less 11, 5, and 11 probes. |
| Probe | A grid point of a cascade, plus an offset of at most 0.45 times the cascade's spacing on each axis, held in one of 27,648 slots. Each cascade's grid point keeps the same slot while the window moves, wrapping around the window. |
| Irradiance map | 6 × 6 texels of the probe's octahedral projection, inside a one-texel border that repeats the texels across the octahedron's edges. Each holds irradiance over π, in nits, in RGB and the hit fraction in alpha, in half floats. |
| Distance map | 14 × 14 texels in the same projection and border, each holding the mean and mean square of the distance rays went near its direction, in half floats. |
| State | Unset, until the probe's first update since its window reached it; buried, when more than 25% of its rays hit back faces; active, when a front face one of its rays hit lies within one spacing of its grid point on every axis, or a pixel read it in the last 8 frames; idle otherwise. |

| Rule | Value |
| --- | --- |
| Schedule | Each frame updates the `render.probe-gi.ray-budget` / 128 probes of highest priority. Unset probes come first, those a pixel read in the last 8 frames ahead of the rest, then finer cascades first. Every other probe ranks by the frames since its last update times its importance, in steps of a quarter of a doubling: the importance is 8 when it's active and a pixel read it in the last 8 frames, 1 when it's active otherwise, and 0.125 when it's idle or buried. Probes of the same rank take turns in an order that changes every frame. |
| Rays | Each update traces 128 rays from the probe, up to 10 kilometers, along a spherical Fibonacci pattern that a random rotation turns every frame. |
| Hit surfaces | As for [surfel GI](#surfel-gi): a ray hits the [ray-traced scene](#ray-traced-scene), and the hit's material reports its albedo and emission. |
| Ray light | A miss brings back the environment's light from its direction: the environment's specular level prefiltered for roughness 2/7, times the environment's intensity. A back-face hit brings back no light. A front-face hit brings back its emission, plus its albedo times what reaches it: each sun that it faces and that no geometry hides; each point and cone light it faces, within the light's reach, that no geometry hides, lit as material evaluation lights a surface but without the light's IES profile; and 0.95 times the probes' light at the hit as the last update left it. That light comes from the finest cascade whose window holds the hit, and the hit gets the scene's lights alone when no probe of it lights there. A ray's light is at most 30,000 nits in each channel. |
| Blend | Each irradiance texel averages the rays' light, weighed by the cosine to its direction, and the share of them that hit. Each distance texel averages the rays' distances and their squares, weighed by that cosine to the power 50; a back-face hit counts a fifth of its distance, and every distance at most twice the spacing. A texel keeps 0.97 of what it held, and n / (n + 1) while its probe has n of its first 32 updates. A probe whose rays' mean luminance and whose irradiance map's mean luminance differ by ten times or more, each counted as at least 0.01 nits, starts over: the update replaces both maps and counts as its first. |
| Relocation | A probe whose rays hit back faces more than 25% of the time moves through the nearest back face, past it by a tenth of the spacing. Otherwise, a probe nearer than a fifth of the spacing to a front face moves away from it to that distance. A move that would take the offset past 0.45 of the spacing on any axis doesn't happen, and a move longer than a tenth of the spacing starts the probe's averages over. |
| Pixel light | Each half-resolution pixel rebuilds its surface from the linear depth pyramid. Its point moves off the surface by 0.225 times the spacing along 0.2 times its normal plus 0.8 times the direction toward the camera. Each active probe of the eight around it weighs the product of its trilinear share; ((c + 1) / 2)² + 0.2, where c is the cosine between the normal and the direction toward the probe; and the cube of Chebyshev's bound on the probe's distances toward the point, but at least 0.05. A weight under 0.2 is crushed to its cube over 0.04. The finest cascade whose window holds the point with one probe to spare lights it; within two probes of that margin, and for the trilinear share of unset probes, the next cascade lights the rest. A pixel no cascade lights takes the environment's irradiance around its normal, times the environment's intensity, and a hit fraction of zero. |
| Marks | Every other pixel of every other row marks the eight probes around it in the cascade that lights it, and in the next one too where the two blend. |

The first sink records the frame-wide probe stages, `probe-schedule`,
`probe-trace`, and `probe-update`, after the surfel stages and before it draws
the scene; every sink that probe GI lights reads the probes and marks them
inside its `screen-space` stage.

### Lightmaps

A lightmap holds the indirect diffuse light of a level's static meshes, which
BELD bakes from the level; [lightmaps](/docs/reference/assets#lightmaps) define
what its texels hold. A spawned level's `lightmap` kind makes it resident.

| Term | Definition |
| --- | --- |
| Lit instance | An instance of a primitive that the resident lightmap gives a rectangle, on an entity of the spawn whose `lightmap` kind names it, once both the lightmap and its image are loaded. |
| Lightmap UV | The pixel's [lightmap UVs](/docs/reference/assets#lightmap-uvs), interpolated as its texture coordinates are, times the rectangle's scale, plus its offset. |

| Rule | Value |
| --- | --- |
| Pixel light | Each opaque pixel of a lit instance reads the lightmap's full-size level at its lightmap UV, with bilinear filtering and clamped edges, at full resolution. Its light isn't pre-exposed. |
| Hit fraction | One minus the lightmap's alpha at the pixel's lightmap UV. The lightmap's light replaces the environment's diffuse light, and the hit fraction occludes the environment's reflections as it does for the other sources. |
| Movement | A lit instance keeps reading its rectangle when its entity moves. Bake the lightmap again after moving what it lights. |
| Skinned primitives | Are never lit instances. |
| Residency | One lightmap is resident at a time: a newer `lightmap` component replaces it, and deleting its entity removes it. |

Lightmaps record no stages: material evaluation reads them inside its
`material-evaluation` stage.

### Ray-traced scene

The rays surfel GI and probe GI trace hit the scene as the first sink's frame
places it, with these exceptions:

| Rule | Value |
| --- | --- |
| Geometry | Each mesh's opaque, unskinned primitives at full detail. Masked and blended primitives are left out, so rays pass through foliage and glass, and so are skinned primitives, so rays pass through the shapes skinning deforms. A mesh without such primitives has no geometry. |
| Instances | Every renderable the frame draws whose mesh has geometry, once that geometry is built. |
| Builds | A mesh's geometry is built once, from the first frame that draws one of its renderables, in the order meshes arrive: at most 262,144 triangles of builds a frame, and at least one mesh a frame. A frame that doesn't record the frame-wide work builds nothing, and its meshes wait for the next frame. A mesh's geometry lasts as long as the mesh stays resident. |
| Placement | Every frame that surfel GI or probe GI lights places the instances at their transforms in that frame. |

The first sink records the builds and the placement in the
`acceleration-structures` stage, before `surfel-grid`. The stage's time covers
the builds. The placement runs alongside the stages after it, so its time shows
in the first stage that traces rays.

### Screen scene queries

A screen scene query asks which entity a camera shows at one pixel. The
application creates a `ScreenSceneQuery` in the world, and the visibility
pipeline answers it by creating a `ScreenSceneHit` in the world.

| Field | Definition |
| --- | --- |
| `ScreenSceneQuery::camera` | The handle of the camera whose window the point is in. |
| `ScreenSceneQuery::point` | The pixel, as `[x, y]` in the window's render extent: x grows to the right and y grows down from the top-left pixel, `[0, 0]`. |
| `ScreenSceneHit::query` | The handle the query was created with. |
| `ScreenSceneHit::entity` | The handle of the renderable mesh whose surface covers the pixel, or none. |

| Rule | Value |
| --- | --- |
| Hit surface | The nearest surface the frame draws at the pixel: a blended surface in front of the opaque scene, otherwise the opaque or masked surface. |
| No entity | The pixel shows no surface, such as the sky; the point is outside the extent; or no window of the frame that takes the query shows its camera. |
| Taking | Each frame takes the queries created before it, oldest first, at most 16 per window. Queries beyond 16 wait for later frames. |
| Answer | Every query gets exactly one hit. The hit is created once the frame that read the pixel completes on the GPU, two frames after it took the query. The entity is the one at the pixel in that frame, even if it was deleted since. |
| Pipelines | Only the visibility pipeline answers queries. |

The reads record no stage metric.

### Stages and targets

Each sink records these stages in order, and each reports a `stage.<name>`
metric when it runs: `skinning`, `shadow-maps`, `shadow-depth-pyramid`,
`light-clusters`, `acceleration-structures`, `surfel-grid`, `surfel-trace`,
`surfel-validate`, `surfel-integrate`, `probe-schedule`, `probe-trace`, `probe-update`,
`visibility-early`, `max-depth-pyramid`, `visibility-late`,
`material-prepasses`, `min-depth-pyramid`, `velocity`, `cascade-fit`, `virtual-shadow-maps`, `screen-space`,
`fog-light`, `material-evaluation`, `subsurface`, `background`, `backdrop`, and `transparent`. Only the first sink
records the ray tracing, surfel, and probe stages: the surfel stages in a frame
that surfel GI lights, the probe stages in a frame that probe GI lights, and
`acceleration-structures` in either. `material-prepasses` runs only when `render.material-evaluation` is
`pipelines`. `subsurface` runs only when `render.subsurface.enabled` was `true`
at startup. `backdrop` runs only in a frame that draws transparent surfaces
while a loaded blended material reads `scenecolor` or `sceneposition`.
`velocity` runs only in a frame where an enabled pass of the sink reads `Velocity`, such as [temporal antialiasing](#temporal-antialiasing) or [motion blur](#motion-blur).

`shadow-depth-pyramid` and `cascade-fit` run only with cascades, and
`virtual-shadow-maps` only with virtual shadow maps, in a frame with a shadowed
directional light. Only the first sink records `virtual-shadow-maps`, after its
depth pyramid, and it covers every page pass and the page draw.

Inside `screen-space`, each dispatch also reports its own metric, when the
technique it belongs to runs: `sun-visibility-trace`, `gtao-evaluate`,
`ssgi-trace`, `surfel-resolve`, `probe-resolve`, `sun-visibility-resolve`,
`gtao-blur`, `ssgi-temporal`, `surfel-allocate`, `surfel-spatial`, and
`gtao-upscale`. The dispatches overlap on the GPU, so a dispatch's time isn't
its cost alone: it can include time other dispatches ran alongside it.

| Target | Content |
| --- | --- |
| `Lit`, aliased `main` | Scene color, full size. Reflections read the previous frame's copy. |
| `Depth`, aliased `depth` | Reversed depth, full size. Reflections read the previous frame's copy. |
| `Velocity` | Full size, 16-bit float, written only in a frame where an enabled pass of the sink reads it. Red and green: the pixel's position less the position the same surface point had in the previous frame, in pixels, with x growing right and y growing down, both under the views without [jitter](#jitter). Each mesh moves by its previous and current shown transforms, and each skinned mesh by its previous and current poses; a mesh's first frame uses its current transform and pose for both, and in the first frame after one that didn't write `Velocity`, every mesh uses its current transform for both. Blue and alpha: the point's linear view depth in the previous frame and in this one. The transparent phase leaves them the opaque surface's. Where depth is 0, the direction's motion under the previous and current camera orientation, and blue and alpha the far plane's distance. The previous frame's copy can be read. |
| `Reactive` | Full size, 8-bit, written in the frames that write `Velocity`. How little a temporal pass trusts its history at each pixel, from 0 to 1: 0 where only opaque surfaces show, otherwise min(α, 0.9) for the coverage α of the nearest blended surface drawn there. |
| `Backdrop Color`, `Backdrop Depth` | The opaque scene's light and positive linear view depth, full size, as they stood before the transparent phase, which `scenecolor` and `sceneposition` read. |
| `Primitive Index`, `Instance Index` | 32-bit IDs per pixel. |
| `Sun Visibility`, `Contact Shadow Trace` | Sun visibility per shadow slot, and its [contact shadow](#contact-shadows) trace, both full size. |
| `SSGI Raw`, `Indirect Diffuse Normals`, `Indirect Diffuse History` | Half-size indirect lighting and its history. |
| `Diffuse Radiance` | Full-size diffuse light that opaque surfaces leave for the next frame's SSGI rays. It exists only when `render.ssgi.enabled` is `true`. |
| `Ambient Occlusion`, `GTAO Raw`, `GTAO Blur` | Ambient occlusion, full size, and its half-size evaluation and denoised intermediate; no usable data on frames GTAO doesn't run. |
| `GTAO Bent Normal`, `GTAO Bent Normal Blur` | The half-size bent normal, as GTAO evaluates it and as material evaluation reads it after the denoise; no usable data on frames GTAO doesn't run. Red and green hold its components along `t = normalize(up × V)` and `b = V × t`, mapped from −1 through 1 to 0 through 1, where `V` is the view vector and `up` the view's up axis; its component along `V` is `√(1 − x² − y²)`. |
| `Subsurface Diffuse`, `Subsurface Shape`, `Subsurface Albedo` | Full size, only when `render.subsurface.enabled` is `true`. At each pixel of a subsurface material: the diffuse light before scattering, times `√A` and the exposure; `d` per channel, in meters; and `√A`. `Subsurface Albedo`'s alpha is 1 at those pixels and 0 at every other pixel opaque material evaluation writes. |
| `Surfel History`, `Surfel History Weights` | Half-size history of surfel GI's light, and its confidence and luminance variance; only when surfel GI is built in. |

These names, with a pass's outputs, select a screenshot through the inspector;
history targets can also be read from the previous frame.
