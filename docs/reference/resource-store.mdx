A resources directory is the store that BELD writes and an application reads.
This page specifies its files, how payloads are encoded, what every resource
records, how queries work, and the model each resource class stores. The
lifecycle is in the [resource management](/docs/reference/resource-management)
reference; the source formats are in the [asset formats](/docs/reference/assets)
reference.

## Files

| File | Content |
| --- | --- |
| `resources.db` | The database of every resource's metadata, the class and property indexes, the packed payload offsets, the store configuration, and, in debug builds, the [development records](#development-records). |
| One file per resource, named `<uid>-<hash>-<encoding>` | The payload in files mode: the resource's UID as 32 hexadecimal characters, the payload hash as 16, and the encoding name. No extension. |
| `resources.pack` | Every payload, in packed mode. |
| `.resource-management-version` | The signature of the engine that wrote the store. |
| `.resource-write-*.tmp`, `.resource-write-*.compressed` | Staging files while a payload is written; renamed into place on commit. |

Replacing a resource in files mode keeps the old payload file, so a reader that
saw the old metadata can still open it. Deleting a resource removes the file.

## Storage modes

| Mode | Payloads |
| --- | --- |
| Files, the default | One file per resource. |
| Packed | Ranges inside `resources.pack`, each recorded in the database. |

The mode is written when the store is created, and opening the store with a
different mode fails. Clearing the store removes its resources and payloads
but keeps the mode. Packed mode can't hold GPU-loaded encodings.

The fragmentation rule holds when the pack is 64 MiB or more, has at least 32
free ranges, is a quarter or more free, and has no single free range holding
half of the free space. A packed store that meets it logs a warning once.

## Payload encodings

| Encoding | Name | Content |
| --- | --- | --- |
| Raw | `raw` | The bytes as authored. |
| CPU LZ4 | `cpu-lz4` | A block table followed by one block per segment of the decoded payload, as defined in [CPU LZ4 layout](#cpu-lz4-layout). |
| Metal I/O LZ4 | `metal-io-lz4` | A Metal I/O container that only the GPU loads, for textures on macOS in files mode. |

A resource stored in one piece is split into segments, and each segment is
compressed when every rule holds:

| Rule | Value |
| --- | --- |
| Policy | Compression isn't disabled for the resource. |
| Size | The segment is 1 KiB or more. |
| Probe | Segments of 128 KiB or more are probed first: four 16 KiB windows spread across the segment must save more than 6.25 percent, or the segment stays raw without compressing the rest of it. |
| Result | The compressed segment is kept only when it saves more than 12.5 percent. |

A segment that fails a rule is stored raw inside the `cpu-lz4` payload. When no
segment is compressed, the whole resource is stored as `raw` instead.

### CPU LZ4 layout

| Term | Definition |
| --- | --- |
| Boundary | Offset 0, the decoded size, and every stream's start and end offset. |
| Segment | The decoded bytes between two consecutive distinct boundaries. A payload without streams is one segment. A stream that overlaps no other stream is exactly one segment, and bytes outside every stream form segments of their own. |
| Block | The stored form of one segment. |

A `cpu-lz4` payload holds these parts in order, with no padding:

| Part | Size | Content |
| --- | --- | --- |
| Block count | 4 bytes | The number of blocks, N, as a little-endian unsigned integer. |
| Block table | 16 × N bytes | One entry per block, in decoded order: the decoded size, then the stored size, each a little-endian 64-bit unsigned integer. |
| Blocks | Sum of the stored sizes | Each block's stored bytes, in table order. |

| Rule | Value |
| --- | --- |
| Raw block | A block whose stored size equals its decoded size holds the segment's bytes as authored. |
| LZ4 block | Any other block is one LZ4 block, without a frame, that expands to exactly its decoded size. |
| Decoded size | The blocks' decoded sizes add up to the resource's `size`. |
| Stored size | The block count, the table, and the blocks add up to the resource's `stored_size`. |

| Read target | Result |
| --- | --- |
| Complete payload | Every block is decoded. |
| Named streams | Only the blocks that each requested stream covers are decoded. |
| Partial range | Rejected. |

A resource written through a transaction, in partial writes, stays raw. When
the store's image compression is on, a plain image resource, one without
image-based lighting data, skips CPU compression and is stored as Metal I/O
LZ4 instead. Reading such a resource through a CPU target fails. In files
mode, a payload file whose length differs from the recorded stored size is
treated as corrupt and isn't read.

## Identity

| Value | Rule |
| --- | --- |
| ID | The public resource ID, a path relative to the assets directory with an optional fragment. |
| UID | The MD5 of the ID, as 32 lowercase hexadecimal characters. Listing a store yields IDs in UID order. |
| Hash | A rapidhash of the decoded bytes, so re-encoding a payload doesn't change the resource's identity. |

## Metadata

Every resource records:

| Field | Content |
| --- | --- |
| `id`, `class` | The public ID and the class name. |
| `hash`, `size`, `stored_size`, `encoding` | The payload's identity, decoded size, stored size, and encoding. |
| `asset_dependencies` | The source files the resource was baked from, each with its ID without a fragment and its version: the file's size and modification time for local files, or a content hash for content-backed sources, or a record that an optional file was absent. |
| `resource` | The class's typed model. |
| `streams` | Optional named byte ranges inside the decoded payload. |
| `queryable_properties` | String properties the query index covers. |
| `baked_at` | Nanoseconds since the Unix epoch. |

## Queries

| Rule | Value |
| --- | --- |
| Properties | Every resource exposes `name`, equal to its ID. A variant also exposes `render-model`, its parent material's render model name, and `render-pass`. |
| Query | A class, zero or more property-equals-value predicates, a limit, and an optional cursor. |
| Matching | The class and every predicate must match exactly, case-sensitively. |
| Index | The first predicate drives an index scan; later predicates filter the results. Without a predicate the class index is scanned. |
| Paging | A page holds up to the limit. When more remain, the page carries a cursor for the next one; a limit of zero returns an empty page. An invalid cursor is an error. |

## Development records

Debug builds write and read two records per resource ID besides its metadata.
Release builds neither write nor read them, so a store baked by a release build
has none.

| Record | Content |
| --- | --- |
| Trace | The messages of the latest bake of the ID, each with a level of info, warning, or error, and the ID itself. A bake that stores no resource still records its trace. An empty trace isn't recorded. |
| References | The IDs of the resources the stored resource's model names, listed in the next table, each once, in the order the model first names it. Written with the resource and removed with it. |

| Class | References |
| --- | --- |
| `Mesh` | Its skeleton and its material variants. |
| `Variant` | Its material and every image a variable's value names. |
| `Material` | Its shaders and every image a parameter's value names. |
| `Animation` | Its skeleton. |
| `Flipbook` | Its images. |
| `MotionDatabase` | Its clips. |
| `Lightmap` | Its image. |
| `Pipeline` | Its shaders. |
| `ParticleSystem` | Its simulate and draw pipelines. |
| Every other class | None. |

## Version marker

The marker holds a signature derived from the engine's resource-management
source. A writable open with a different or missing marker beside an existing
database deletes the whole directory, recreates it, and writes the marker.
Debug builds open the store writable, so a stale store resets itself; release
builds open read-only and fail on a mismatch. BELD's read-only commands report
the mismatch without touching the directory.

## Resource classes

| Class | Model | Payload | Streams | Dependencies |
| --- | --- | --- | --- | --- |
| `Audio` | Bit depth of 8, 16, 24, or 32; channel count; sample rate; frame count. | Interleaved little-endian PCM. | None | None |
| `Image` | Format, gamma, extent, mip count, optional image-based lighting maps, optional photometry. | Texels. | `mip[N]` per level; `ibl.diffuse_irradiance.mip[0]` and `ibl.prefiltered_specular.mip[0..8)` for environment maps. | None |
| `Lut` | One- or three-dimensional, size, domain minimum and maximum. | Little-endian float RGB triplets, `size` or `size³` of them. | None | None |
| `Pipeline` | Name and kind. | None | None | Its shaders, by ID. |
| `ParticleSystem` | Capacity, longest life, rate, burst, simulate and draw pipeline IDs. | None | None | Its pipelines and shaders. |
| `Shader` | ID, stage, interface, and artifact kind. | The compiled artifact. | None | None |
| `Flipbook` | Frames per second and images. | None | None | Its images. |
| `Material` | Double-sidedness, alpha mode, coverage, shaders, render model, parameters. | None | None | Its shaders and parameter images. |
| `Variant` | Parent material, variable values, alpha mode. | None | None | Its material. |
| `Mesh` | Optional skeleton, skin bindings, vertex components, streams, material variants by reference, primitives. | Packed vertex, index, and meshlet data, grouped by detail level. | `level[N].` streams per detail level, listed after this table. | Its skeleton; materials are listed but not loaded with the mesh. |
| `Skeleton` | Nodes with optional names, parents, and rest transforms. | None | None | None |
| `Animation` | Optional name, skeleton, duration, optional frame rate, per-node curves. | None; curves live in the metadata. | None | Its skeleton. |
| `Lightmap` | The spawn index of the level entity that holds the `lightmap` kind, the image by reference, and, for each primitive with a rectangle, its entity's spawn index, its primitive index, and its rectangle as a scale and an offset that map lightmap UVs into the image. | None | None | Its image. |
| `MotionDatabase` | Clips with their frame and pickable frame counts, sample rate, ground root and feature node names, trajectory times, normalization, every frame's features and ground root, and search and spring settings. | None; frames live in the metadata. | None | None; its clips are listed but not loaded with it. |

Image formats: `BC5`, `BC5SNORM`, `RG8`, `RG16`, `R16F`, `RGB8`, `RGBA8`,
`BC7`, `RGB16`, `RGBA16`, `BC7SRGB`, `RGBA16F`, and `RGBA8SRGB`, with linear
or sRGB gamma. An environment map is an image with image-based lighting maps;
there is no separate class.

Shader stages: vertex, fragment, compute, task, mesh, ray generation, closest
hit, any hit, intersection, miss, and callable. Artifacts: SPIR-V, HLSL, MSL,
Metal library, and DXIL.

Mesh streams hold one detail level each, so a reader can load the levels it
needs and leave the rest on disk. Level 0 is full detail; each later level is
coarser. Every stream name starts with its level, `level[N].`, followed by one
of these names:

| Stream | Element | Holds |
| --- | --- | --- |
| `Vertex.Position`, `Vertex.Normal`, `Vertex.BiTangent` | Three floats | The vertices that level N adds, for every primitive. |
| `Vertex.UV` | Two floats | Same. |
| `Vertex.LightmapUV` | Two floats | Same, for unskinned primitives with [lightmap UVs](/docs/reference/assets#lightmap-uvs): coordinates from 0 through 1 at which no two triangles overlap. |
| `Vertex.Tangent`, `Vertex.Color`, `Vertex.Weights` | Four floats | Same. |
| `Vertex.Joints` | Four 16-bit integers | Same. |
| `VertexIndices` | 16-bit integer | Level N's meshlet vertices, as indexes into the primitive's vertices. |
| `MeshletIndices` | 8-bit integer | Level N's triangle corners, as indexes into their meshlet's vertices. |
| `Meshlets` | Meshlet record | Level N's meshlets. |
| `TriangleIndices` | 16-bit integer | Level 0 only: full detail as a plain triangle list, three indexes into the primitive's vertices per triangle. |

Each stream lists its primitives in order, and a primitive with nothing at a
level has nothing in that level's streams. A meshlet holds at most 64 vertices
and 124 triangles.

| Mesh rule | Value |
| --- | --- |
| Primitive | A material index, an optional transform node, an optional skin, its streams, a bounding box, a bounding sphere around its full-detail triangles, a vertex count, and 1 to 8 detail levels. |
| Detail level | An error, a meshlet count, and a vertex count. |
| Detail level errors | The first level's error is 0, and errors never decrease. |
| Meshlet counts | Each level's meshlet count is the count of that primitive's meshlets in the level's `Meshlets` stream. |
| Vertex order | Vertices are ordered by the coarsest level that uses them, coarsest first. A level's vertex count V is the number of vertices that level or any coarser level uses, and every index the level's meshlets name is below V. |
| Vertex streams | A primitive's first V vertices for level N are its vertices in the `level[L]` vertex streams for every level L from the coarsest down to N, in that order. Vertex counts never increase from one level to the next coarser one, and the first level's vertex count is the primitive's vertex count. |
| Skinned primitives | Have exactly one detail level. |
| Skins | Need a skeleton, hold at most 65,536 entries, and name nodes inside it. A skinned primitive carries joints and weights for every vertex. |

Container fragments name the resources a model file produces, such as `#skeleton`, `#images/<index>`, and
`#materials/<material>.variant`; [container fragments](/docs/reference/assets#container-fragments) lists them.
