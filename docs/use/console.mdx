Use the console when you run your application from a terminal and want to try a setting without restarting it, such
as forcing a mesh detail level or switching the global illumination technique. While your application runs, the
terminal shows its log with a command line under it.

## Change a setting

1. Run your application from a terminal:

   ```bash
   cargo run
   ```

   The terminal switches to the console: the log fills the screen, and the command line waits at the bottom.

2. Click the terminal, so your keys go to it instead of the application's window.

3. Type `set`, the setting's name, and the value, then press Enter. Press Tab to complete the name or the value: the
   console lists the settings your application has, one dotted part at a time, and the values each one takes.

   ```text
   set render.lod.force 2
   ```

4. Read the result in the log and in the status line under the command line. It shows the value in effect, or why
   the setting wasn't changed:

   ```text
   render.lod.force set to 2
   ```

Every setting the [runtime settings](/docs/reference/parameters#runtime-settings) table lists works, and so does every
debug view: `set render.debug.view.motion-blur.velocity true` shows motion blur's velocity over the window; see
[Show a debug view](/docs/use/debug-views). Type `help` to list the commands, press Up to run an earlier command again,
and press Page Up to read older log lines.

## See what's baking

A debug build bakes assets the first time it needs them. To watch those bakes, press Cmd+2: the pane switches from the log
to the bakes. It shows how many assets are baking, have baked, and have failed; each asset baking now with how long it
has run; and the latest assets to finish, marked ✓ or ✗ with how long each took. Each asset sits indented under the asset that needed it, named by what differs from that asset's ID, so you can see why it bakes. Press Cmd+1 to return to the log. Press Cmd+3 for the entities.

If your terminal keeps Cmd+number for its own tabs, press F2 instead: it shows the next view.

## Find and change an entity

1. Type `entities` and part of the entity's name. The pane switches to the entities and narrows the list as you type,
   best match first; each row shows the entity's handle, name, position, and types.

   ```text
   entities crate
   ```

   Add `type:` and part of a type name to keep only entities of that type, such as `entities type:camera`. Press Enter
   to keep the search.

2. Type `post`, the message to send, and the entity, then press Tab after the entity's name: the console replaces the
   name with the entity's handle. Press Tab again after the handle to see the payload the message takes.

   ```text
   post Delete crate
   ```

3. Add the payload as JSON, then press Enter. To move an entity, post its new transform:

   ```text
   post TransformationUpdate 12 {"position":[0,1,0]}
   ```

   A transform replaces the whole transform: a field you leave out, such as `orientation` or `scale`, resets to its
   identity value.

The status line says whether the message was posted, or why it wasn't. See the messages each application accepts in
[Entities and messages](/docs/reference/inspector#entities-and-messages).

## Close the application

Press Ctrl+C to close the application. The terminal returns to how it was, with the run's log in its history.

## Turn the console off

The console starts only when standard input and standard output are both terminals, so piped runs, test harnesses, CI,
and agents never have it. When your application reads standard input or writes to standard output itself, turn the
console off with the `console.enabled` parameter, in `config.json`, as `BE_CONSOLE__ENABLED=false`, or on the command
line:

```bash
cargo run -- --console.enabled=false
```

## Rust API

- [`inspector::console::spawn`](/docs/api/latest/byte_engine/inspector/console): starts the console; the
  application calls it for you.
- [`DefaultInspector::update_configuration`](/docs/api/latest/byte_engine/inspector/DefaultInspector): changes a
  runtime setting from your own code or tool.

See the [console reference](/docs/reference/console) for the screen, every key, and every command.
