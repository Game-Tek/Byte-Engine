title: Spawn reusable objects with prefabs
description: Write a group of entities and its behavior once as a .prefab file, then place it from levels or spawn it from code with its own values.

---

Use a prefab for anything you place more than once: a unit, a lamp post, a door
with its frame. A `.prefab` file holds the entities, the components they carry,
and parameters that each copy can set. Behavior comes from tasks you attach to
a component kind, so a prefab that places the kind places its logic too.

## Write a prefab

Add a `.prefab` file to your assets. Write its entities as a level's, with
transforms relative to where the prefab is placed. Declare each value a copy
can change under `parameters`, with its default, and refer to it with
`$parameter`:

```json5
{
	"$schema": "byte_engine/schemas/prefab.schema.json",
	parameters: { speed: 3, team: "red" },
	entities: [
		{
			id: "body",
			components: {
				transform: { position: [0, 0.9, 0] },
				mesh: { resource: "units/goblin.glb" },
				body: { type: "kinematic", shape: { capsule: { radius: 0.3, height: 1.8 } } },
				patrol: { speed: { "$parameter": "speed" }, team: { "$parameter": "team" } },
			},
		},
		{
			parent: "body",
			prefab: { resource: "units/spear.prefab" },
			components: { transform: { position: [0.3, 1.2, 0] } },
		},
	],
}
```

The second entity is an instance of another prefab: the spear spawns under it,
at its transform.

## Give the prefab its behavior

Register the kind that carries the behavior's settings with your spawner, and
attach a task to it on the runtime. Do both before you spawn:

```rust
#[derive(Clone, serde::Deserialize)]
#[serde(deny_unknown_fields)]
struct Patrol {
	speed: f32,
	team: String,
}

let mut spawner = Spawner::with_engine_kinds();
spawner.register::<Patrol>("patrol")?;
app.runtime().attach(|tasks: Tasks<Game>, unit: Handle, patrol: Patrol| async move {
	loop {
		walk_route(&tasks, unit, patrol.speed).await;
		tasks.sleep(MediaTime::from_seconds(1)).await;
	}
});
```

Every entity that gets a `Patrol` starts its own task, and deleting the entity
ends it. The task waits and reads state as any [gameplay task](/docs/use/gameplay-tasks) does.

## Place a prefab in a level

Give a level entity a `prefab` field. Its `transform` places the prefab, and
`parameters` replaces the defaults you name:

```json5
{
	components: { name: "north gate guard", transform: { position: [12, 0, -4] } },
	prefab: { resource: "units/goblin.prefab", parameters: { speed: 5 } },
}
```

`Loaded::load` loads the level and every prefab it places, so spawn the level
as before. Deleting the instance entity deletes the prefab's entities.

## Spawn a prefab from code

Load the prefab once, then spawn it wherever you need a copy. Pass a placement,
and set parameters from any value that serializes to an object:

```rust
let goblin = build_single_threaded_async_runtime()
	.block_on(Loaded::load(app.resource_manager(), "units/goblin.prefab"))?;

#[derive(serde::Serialize)]
struct Recruit {
	team: &'static str,
}

let unit = spawner.spawn(
	app.world(),
	&goblin,
	Placement::at(Transform::from_position(ground)).under(arena).with_parameters(&Recruit { team: "blue" })?,
)?;
```

The returned handle is the copy's root: every entity of the prefab belongs to
it, so deleting it removes the copy. `under` makes the copy part of a scene you
already have, so deleting that scene removes it too.
