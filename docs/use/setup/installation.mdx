Install Byte-Engine as a Cargo dependency in your application workspace.

## Prepare your workspace

Byte-Engine uses unstable Rust features. Pin the supported nightly toolchain in your application workspace's `rust-toolchain.toml`:

```toml
[toolchain]
channel = "nightly-2026-05-31"
```

Complete the [environment setup guide](/docs/use/setup/environment) for your
platform's graphics, audio, and native build dependencies before building your
application.

## Choose an installation method

The installation method determines where Cargo gets the Byte-Engine source:

- **Published release:** Choose this for most applications. Cargo selects a
  released version from crates.io using normal package version resolution.
- **Git dependency:** Choose this when you need unreleased engine changes but
  don't need to edit the engine locally. Cargo fetches the source from the
  Byte-Engine Git repository.
- **Local checkout:** Choose this when you want to inspect or modify the engine
  alongside your application. Cargo uses a path to a checkout that you update.

## Install the published release

Add the latest published Byte-Engine release to your application crate:

```sh
cargo add byte-engine
```

Cargo adds the published package version to your crate's `Cargo.toml`.

</Tab>
<Tab>

## Install a Git dependency

Add Byte-Engine directly from its Git repository:

```sh
cargo add byte-engine --git https://github.com/Game-Tek/Byte-Engine
```

Cargo records the Git repository in your application's `Cargo.toml` and fetches
the engine source when it resolves dependencies.

## Use a local engine checkout

Clone Byte-Engine and add it to your application as a local path dependency.

### Arrange the local workspaces

Use a shared parent directory for the engine repository and your application workspace. This layout matches the Byte-Engine sandbox workspace:

```text
development/
├── Byte-Engine/
│   └── crates/
│       └── byte-engine/
└── my-game/
    ├── Cargo.toml
    ├── rust-toolchain.toml
    └── game/
        ├── Cargo.toml
        └── src/
            └── main.rs
```

From the shared parent directory, clone Byte-Engine:

```sh
git clone https://github.com/Game-Tek/Byte-Engine.git
```

If your directories use different names or locations, adjust the dependency paths in the following steps.

### Configure the application workspace

List your application crate in `my-game/Cargo.toml`:

```toml
[workspace]
members = ["game"]
resolver = "2"
```

Add the same supported nightly toolchain shown above to `my-game/rust-toolchain.toml`.

### Add the engine crate

From `my-game/game/`, add the local checkout with Cargo:

```sh
cargo add byte-engine --path ../../Byte-Engine/crates/byte-engine
```

This command adds the following dependency to `my-game/game/Cargo.toml`:

```toml
[dependencies]
byte-engine = { path = "../../Byte-Engine/crates/byte-engine" }
```

Cargo resolves a path dependency from the `Cargo.toml` that declares it. In this layout, `../../Byte-Engine` moves from `my-game/game/` to the shared `development/` directory and then enters the engine checkout.

If your application also uses a lower-level engine crate directly, add its package name and local path. For example:

```toml
[dependencies]
byte-engine = { path = "../../Byte-Engine/crates/byte-engine" }
ghi = { package = "byte-engine-ghi", path = "../../Byte-Engine/crates/ghi" }
resource-management = { package = "byte-engine-resource-management", path = "../../Byte-Engine/crates/resource-management" }
utils = { package = "byte-engine-utils", path = "../../Byte-Engine/crates/utils" }
```

Most applications only need the `byte-engine` dependency.

### Verify the local setup

After completing the environment setup, run this command from `my-game/`:

```sh
cargo check -p game
```

Cargo builds the application against the local Byte-Engine checkout. Pull changes in `Byte-Engine/` whenever you want to update the engine, then run the check again.
